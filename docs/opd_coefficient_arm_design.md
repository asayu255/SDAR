## 0. これは何か

MOPD の損失は $L=\sum_i w_i L_i^{RL} + \beta\sum_j w_j L_j^{OPD}$ で、$\beta$（`opd.kl_loss_coef`、現行 0.01）は
3 タスク共通の 1 スカラーである。§4.14 の測定は**教師ごとの量**を出した —— タスク $j$ の教師が押す方向が
各タスクの報酬勾配と揃っているか。

このアームは**探索実験**である。検定するのは:

> **校正データ上で勾配ノルム予算を保ちながら、cosine から作った代理指標（§1.1）を改善するように
> 3 本の教師の係数を配り直すと、0→150 の学習で到達点が変わるか。**

一次近似の正しさ、実際の RL 損失、成功率のいずれも、この規則が保証するものではない（§1.1、§5）。
RL–RL の衝突は対象外（cosine 0.002〜0.016）。

## 1. 機構（確定）

### 1.1 係数の決め方

$$
\tilde C_{ij}=\frac1N\sum_{n=1}^{N}\frac{\langle r_i^{(n)},\,d_j^{(n)}\rangle}{\|r_i^{(n)}\|\,\|d_j^{(n)}\|},
\qquad
c_j=\sum_{i}\tilde C_{ij}
$$

予算重み $q$（損失側の行重み $w_i$ とは別物）:

$$
q_j=\frac{\overline{\|d_j\|}}{\sum_k\overline{\|d_k\|}},\qquad
\bar c_q=\sum_j q_j c_j,\qquad
\delta_j=c_j-\bar c_q
$$

$$
\kappa=\min\!\left(\frac{1-b_{\min}}{-\min_j\delta_j},\ \frac{b_{\max}-1}{\max_j\delta_j}\right),
\qquad
b_j=\mathrm{clip}\big(1+\kappa\,\delta_j,\ b_{\min},\ b_{\max}\big)
$$

$b_{\min}=0.5$、$b_{\max}=1.5$。実効係数は $\beta\,b_j$。$r_i,d_j$ は係数込み（`task_loss_weight` を含む）。

**成り立つ性質**（有効な入力で $\kappa$ が box を守るとき）:

* $\sum_j q_j b_j = 1$ —— 校正データ上の線形予算 $\sum_j b_j\overline{\|d_j\|}$ が control と一致する
* 代理指標 $F(b)=\sum_j q_j c_j b_j$ について $F(b)-F(\mathbf 1)=\kappa\sum_j q_j(c_j-\bar c_q)^2\ge 0$

したがってこの規則は「**校正データ上の勾配ノルム予算を保ち、平均 cosine から作った代理指標を改善する**」
と説明できる。**それ以上ではない** —— 実際の RL 損失や成功率を保証する式ではない。

**$b$ は順位だけでは決まらない。** $b$ は列スコアの相対差と予算重み $q$ に依る。同じ順位でも
対角を除くと (1.076, 1.191, 0.500) → (0.993, 1.234, 0.500) に変わる（§5）。
また、スコア全体を $10^{-4}$ 倍しても $b$ は同じになる（$\kappa$ が逆に伸びる）。
**webshop が常に 0.5 に張り付くのは半減が精密に推定されたからではなく、$\kappa$ を box 境界まで
進める設計だからである。** 半減は初回の介入強度として事前に選んだ実験条件であり、データが支持した強度ではない。

**付則（タスクを区別しない）**: あるバッチでタスク $i$ の RL 勾配が厳密に 0 なら、その行の平均から
そのバッチを除く。定義されたバッチが $N/2$ 未満の行があれば go しない。
step 300 の 24 セルはすべて非ゼロで、発動していない。**算出スクリプトにはこの付則がまだ入っていない**（§4.2）。

### 1.2 3 つの設計判断と、その理由

| 判断 | 採用 | 理由 |
|---|---|---|
| $C$ が決めるのは配分だけ、総量は決めない | $\sum_j q_j\delta_j=0$ | **設計判断**。$R+D=0$ の停留点では $R^\top PD=-R^\top PR\le0$ が成り立つが、これを「負の内積は正則化が効いている印」「総量を委ねると必ず縮む」と一般化はしない（標本勾配の内積には共分散が入り、期待勾配の停留条件とは別）。実測で $\langle\sum r,\sum d\rangle$ は 8 バッチ中 7 で負であり、総量を $C$ に委ねる形は元の QP で全停止を出した。総量は $\beta$ が担うと**決めた** |
| 硬い制約 QP ではなく比例則 | $b_j=1+\kappa\delta_j$ | 硬い制約は絶対水準（$C_ib\ge0$）に依り、bootstrap で全停止と部分減衰の間を 6:4 で行き来した。比例則は順位の再現率（96.4%）に依る —— ただし $b$ の値は順位以外にも依る（§1.1） |
| 行の重みは等しい票 | $\alpha_i=1$ | **簡潔な選択**。cosine が小さいことは真の直交・相殺・標本雑音のどれでも起きるので、「低信頼度の行は既に減衰しているから理論的に適切」とは言わない。代替案（精度重み・被覆率）は下記のとおり退けた |

**予算は係数の和ではなく $\|d_j\|$ 加重和で取る。** $\|d_j\|$ は 0.408〜0.886（2.17 倍）違うので、
$\sum_j b_j$ を固定しても蒸留量は保存されない（初版 $\sum b=3$ では線形和 +10.0%、合成ノルム +24.4%）。

**捨てた案とその理由**:

* **精度重み（逆分散）** —— search 行を最大（1.859）にして順位再現を 97.1% → 65.1% に落とした。
  cosine は大きさを正規化するので、小さくなった値のバッチ間分散は小さく「安定」に見える。
* **被覆率重み** —— (i) 「8 本の rollout がたまたま揃った標本の人工物」と「その状態で真に方策勾配が 0」を
  同じ割引で扱う、(ii) `rollout.n` と成功率の regime に依るので学習段階で $b$ が整列と無関係に動く、
  (iii) 人選 $S$ との一致を根拠にするのは循環。
* **偏差を $q$ で割る形** —— $\|d\|$ の小さい alfworld を 1.16 まで動かす。alfworld の列和はほぼ 0
  （$c=-0.019$）で、測定は alfworld を動かす根拠を持たない。
* **人が選ぶ $S=\{\text{alfworld},\text{webshop}\}$** —— 機構が入力の関数として閉じない。

### 1.3 何が正則化の量を決めるか

正則化の量は $\beta$（現行 0.01）と床 $b_{\min}=0.5$ が担い、$C$ からは決めない。これは設計判断である。
$\beta$ の時間変化を入れるなら $\beta(t)$ 減衰として $C$ とは独立に決める。

## 2. 現時点の値（step 300、$N=8$）

| | alfworld | search | webshop |
|---|---:|---:|---:|
| $c_j$ | −0.0188 | **+0.0258** | **−0.2432** |
| $\overline{\|d_j\|}$ | 0.4563 | 0.8859 | 0.4084 |
| $q_j$ | 0.2607 | 0.5061 | 0.2333 |
| **$b_j$** | **1.076431** | **1.191101** | **0.500000** |
| 実効 $\beta b_j$ | 0.0108 | 0.0119 | 0.0050 |

**予算（校正データ上）**:

| | $\sum_j b_j\overline{\|d_j\|}$ | $\|\sum_j b_jd_j\|$（batch 別の RMS） |
|---|---:|---:|
| control (1,1,1) | 1.7506 | 1.0700 |
| 再配分 | **1.7506（+0.00%）** | 1.1885（**+11.1%**） |
| 一様 1.111 | 1.945 | 1.1885 |

* 合成ノルムは **batch 別に計算した RMS** である。単純平均なら control 1.0501 / 再配分 1.1644 で、
  一様倍率は 1.1088 になる。**RMS 基準で 1.111（正確には 1.110833）を採用**し、算出スクリプトも揃える（§4.2）。
* 線形予算の一致は**校正データの平均上**でのみ成り立つ。batch 別の $\sum b_j\|d_j^{(n)}\|/\sum\|d_j^{(n)}\|$ は
  **0.973〜1.014**。KL 損失値・合成勾配ノルム・Adam 更新量・学習中の累積的な拘束は保存しない。

**$P=I$ の局所近似での向き**: $\overline C_{\rm dot}(b-\mathbf 1)=(+0.123,\ +0.066,\ +0.057)$（alfworld, search, webshop）。
平均では 3 タスクとも RL 損失が下がる向きだが、batch 別に正だったのは **7/8・5/8・5/8**。
実験を動機づける数字であって、成功率の保証ではない。

**bootstrap（8 バッチ再抽出 ×2000）**:

| | |
|---|---|
| その測定での順位（search > alfworld > webshop）の再現 | **96.4%** |
| $P(b_{\text{search}}>1)$ | 0.999 |
| $P(b_{\text{alfworld}}>1)$ | **0.92**（改訂 1 の 0.76 は採用していない $S=\{\text{alf},\text{web}\}$ の値） |
| $b_{\text{alfworld}}$ の 5–95% | [0.99, 1.15] |
| $b_{\text{webshop}}$ の 5–95% | [0.50, 0.50]（設計上、下端に張り付く） |

**go/no-go**: 順位の bootstrap 再現率が 90% を下回れば $\kappa=0$（= control）とし、走らせない。
「その測定で得た順位の再現率」と「step 300 の順位との一致率」は**別項目**として記録する（算出スクリプトは
現在 search > alfworld > webshop を固定判定している: §4.2）。

**測定が支持しているのは 1 つの情報**: webshop の教師が押す向きが他タスクの報酬勾配と食い違う
（§4.14.3 の OPD–OPD 8/8 負、§3.6 の出力空間、この $C$ の webshop 列）。実際に検定する自由度は
「webshop の係数を半分にし、予算を主に search に回す」の 1 つで、半減は事前に選んだ強度である。

## 3. 実験設計（3 アーム、A を pilot として固定）

0 → 300 step、**各条件 1 学習 run の pilot**。`test_freq=150` なので評価点は **150 と 300 の 2 つ**（trainer は最終 step で必ず val を回す）。当初 150 step で設計したが、`total_training_steps` は cosine スケジュールの分母であって期間ノブではない: step 150 の時点で 150 step 宣言の run は LR 0 まで減衰済み、300 step 宣言の run はピークの 59% にいて、step 0–149 の平均 LR が **1.56 倍**違う。$b$ の一次寄与は RL 自身の 0.25〜0.99% なので、この差は測りたい効果より桁が大きい。**このプロジェクトの他の $\beta$=0.01 アーム（klw / klw_control / signweight）が揃って 300 step である**ことも合わせ、300 に統一する。1 アーム約 49 時間（実測 590 秒/step）。

| アーム | $b$ | 実効 $\beta b_j$ | 役割 |
|---|---|---|---|
| **control** | (1, 1, 1) | 0.01 ×3 | 基準 |
| **一様** | (1.111, 1.111, 1.111) | 0.0111 ×3 | **校正 checkpoint 上で OPD 合成勾配の RMS を再配分に合わせた比較対象** |
| **再配分** | (1.076, 1.191, 0.500) | 0.0108 / 0.0119 / 0.0050 | 処置 |

一様アームは学習中ずっと更新の強さを一致させる対照ではなく、配分効果だけを完全に分離する対照でもない。
再配分が両対照を上回れば**この係数設定の有用性**は示せるが、それだけで「干渉情報を使ったことが改善原因」
とまでは特定できない。

**事前に固定するもの**: 主評価タスク、他タスクの許容悪化幅、評価 seed、学習が分岐する前の共通初期条件。

**学習 run は学習だけを行う（`test_freq=-1`）。** 学習中の val は無効にしてある。理由は 2 つで、
どちらも実測に基づく: 学習単独で host RAM のピークが 251 GB のうち **183 GB** に達し、val は
その上に 1 タスク 126 インスタンス分の環境と per-instance のテキスト出力を積む（過去に host の
RAM を枯渇させている）。そして**ループは save より先に validate する**
（`opd_ray_trainer.py:1579` → `:1586`）ので、step 150 の val で OOM すると
**その step の checkpoint ごと 24 時間分を失う** —— checkpoint から 1 時間で再計算できる量のために。
`test_freq` は最終 step の val も同じ条件で塞ぐので、`-1` は本当に「val なし」を意味する。

**評価は別 run（`VAL_ONLY=1`）で、`save_freq=25` が残した checkpoint から行う。** 150 と 300 は
どちらも保存境界に乗る。step 150 / 300 の checkpoint を同一プロトコルで 3 回評価する
（`RUN_TAG` を変える。同じ step を再評価すると per-instance dump が上書きされる）。これは
**評価の乱数変動**の見積もりであり、**学習 seed による変動ではない**。学習 run は各条件 1 本なので、
差が出ても出なくても学習 seed の反復無しには確定できない。有望なら学生モデルの学習 seed を
増やす、という段階判断とする。タスク別に報告し、pooled は出さない。

### 3.1 測定点: A を pilot として固定（B は後続）

| 案 | 測定・適用 | 答える問い |
|---|---|---|
| **A（採用）** | step 300 で係数決定、0→150 に適用 | 後期の測定に基づく固定配分が、初期学習にも有用か |
| B（元案） | step 50 で係数決定、0→150 に適用 | **測定点と適用点が一致していない**（step 50 で測り step 0 から適用）。A と同型の問いで測定点が違うだけ |
| B'（局所介入） | step 50 で測定し、**同じ checkpoint から 3 条件へ分岐** | その状態での測定に基づく配分が、その後の学習に有用か。測定点と適用点が一致する |

追加測定を先に要求しないという方針で **A を pilot として固定**する。B1/B2 は起動条件ではない。
早期の $C$ を測るなら B' の形で別実験にする。**「B1 の順位が step 300 と同じなら同じ $b$ になる」は誤り**
（$b$ は順位以外にも依る: §1.1）。

B1（`~/checkpoints/verl_agent_opd_grpo_multitask/global_step_50`、world size 3、`optim` あり）と
B2（`~/checkpoints/verl_agent_opd_grpo_tmp_multitask/global_step_50`、world size 2、`optim` あり）は
実在を確認済み。B2 は別アームなので、その Adam 幾何が $P=I$ と一致しても **control の Adam 効果を
検証したことにはならない**。$\|d_j\|$ の比は学習段階で動く（純 OPD step 150 で search ×4.47、
OPD+GRPO step 300 で ×1.94）ので、B' では $q_j$ も取り直す。

生存群数は**診断値として記録する**（特定タスクを保護する go 条件にはしない —— それは「タスクを区別しない」
と一致しない。保護条件にするなら明示して別途決める）。

### 3.2 事前予測

**最も直接の観測は「webshop の OPD が alfworld の RL を押し戻す向き」である**（$C_{\rm alf,web}=-0.191$、
7/8 で負）。したがって **alfworld の改善は本来の仮説に含まれる**。例外扱いにしない。

| タスク | $b$ | 予測 | 備考 |
|---|---|---|---|
| **alfworld** | 1.08 | 干渉が本物なら **≥ control**。ただし一次量は RL 自身の 0.56% で小さい | これが機構の主経路。動かなくても「干渉が無い」とは言えない（下記） |
| search | 1.19 | ≥ control、差は小さい | OPD が主信号（生存群 1〜5/15）。< control なら教師寄りが強すぎる |
| webshop | 0.50 | 2 経路が逆向き。干渉の解消は ≥、蒸留信号の半減（$A=0$ 群 62.3%）は ≤ | どちらが出ても単独では識別できない（§6） |

**null の解釈**: 言えるのは「今回の係数・開始点・期間・seed・評価精度では差を検出できなかった」まで。
**タスク別係数の機構族を閉じることはできない。**「5pp 未満は決められない」という閾値も、
評価反復の SD だけからは導けない（学習 seed の変動を含んでいない）。

150→300 の区間について「3 アームとも区別できない」と断定はしない（§5）。0→150 を選ぶのは、
OPD の効果が観測された区間（§4.3）を含めるためである。

| 起動スクリプト | `examples/opd_grpo_trainer/run_multitask_opd_coef_qwen3.sh`（`ARM=control\|uniform\|redistribute`）。`run_multitask_cross_teacher_klw_control_qwen3.sh`（$\beta$=0.01）から派生。`run_multitask_qwen3.sh` は $\beta$=1.0 なので使えない |
| control は `null` を**明示的に渡す** | キーを省くと `algorithm.opd.kl_loss_coef_by_task` が `<<MISSING>>` のままで、3 アームすべてに `null` を固定した lock が起動を止める。actor 側では `None` になり従来の損失経路を通る |
| 算出スクリプト | `scripts/opd_cross_effect_qp.py`（別 worktree から移送し、下記 3 点を修正） |
| 試験 | `tests/trainer/test_teacher_kl_coef_by_task.py` 22 件、`test_opd_task_diag.py` 29 件、`test_opd_coef_arm.py` 33 件、`test_opd_cross_effect_qp.py` 14 件。既存の失敗 1 件（`test_cross_teacher_kl_weight.py::test_the_reliability_pass_...`）は base 39bfffe から存在し、この作業とは無関係 |

**アーム同士の差が $b$ だけであることは、読み比べではなく試験で固定した**:
`test_opd_coef_arm.py` が 3 つの期待値ファイルを平坦化して差分を取り、
`kl_loss_coef_by_task.*` と `trainer.experiment_name` 以外に差があれば落ちる。
control は $\{1,1,1\}$ ではなく `null` を渡す —— $\{1,1,1\}$ は $b$ 対応の分岐を通り、
同じ値に別経路で到達してしまうため。

**ただし lock 同士の差分だけでは足りなかった。** スクリプトが**渡さない**キーは
ファイル比較では捕まらず、実際に control だけが `<<MISSING>>` で lock に落ちていた
（ファイル側の試験は全部通ったまま、アームは起動時に死ぬ）。そこで
「実引数 → Hydra 合成 → 設定注入 → lock 照合」を 3 条件で回す試験を足した。
実引数はスクリプトのテキストを読み直すのではなく、`python3` をシムに差し替えて
スクリプト自身に答えさせる。

**算出スクリプトの修正 3 点**（いずれもレビュー指摘、実行前に発見）:

1. **RL 勾配ゼロの行で $b=\mathrm{NaN}$ になっていた。** $C_{ij}/(\|r_i\|\|d_j\|)$ は
   そのバッチでタスク $i$ に方策勾配が無いとき 0/0 になる —— 付則が落とせと言っている
   まさにその場合。セルごとに使用可能バッチ数を持ち、使えないバッチはそのセルの平均から
   落とす。有効数が閾値（既定 $N/2$、`--min-batches`）を切れば **b を出さずに落ちる**。
   `diag=False` で意図的に除いた対角は「欠測」と数えない。
2. **bootstrap の順位判定が search > alfworld > webshop に固定されていた。**
   標本自身が与える順位の再現率（`rank_reproducibility`）と、参照順位との一致率
   （`agreement_with_reference`）を**別項目**として出す。go 条件が要求するのは前者。
3. **合成ノルムがバッチ単純平均だったが文書は RMS を引いていた。** 両方を別名で出し、
   一様アームの倍率は RMS 由来（1.110833）と明示する。

`--json` で $C$・$\|d\|$・$q$・$c$・$b$・$\sum q_j b_j$・両不変量・バッチ別線形比・
順位再現率・leave-one-out を書き出す。step 300 payload での出力は §2 の表と一致する。

### 4.2 走行中の readout（`algorithm.opd.task_diag=True`）

`verl/trainer/ppo/opd_task_diag.py`。update あたり all-reduce 1 回・host read 1 回。

**校正はパラメータ空間の勾配で行い、ここで測るのはロジット空間である。** ロジット勾配を
$u_R,u_D$、モデルの Jacobian を $J$ とすると、ロジット上の内積は $u_R^\top u_D$、
パラメータ上は $u_R^\top JJ^\top u_D$ で、**同一タスクでも符号は保証されない**。
したがって以下のどの量も「校正した量をもう一度測ったもの」ではなく、校正データ上でさえ
校正値を再現する保証はない。これらが与えるのは、**optimizer が実際に取った項の読み**である。

| 指標 | 何を答えるか |
|---|---|
| `kl_ratio_eff_base/{task}`、`push_l2_ratio_eff_base/{task}` | **$b$ が損失に届いたか。** 同一 forward・同一トークンの eff/base なので、分母が非ゼロなら $b_j$ に一致する。config を言い直したものではなく、損失が何をしたかの読み |
| `kl_share_eff/{task}`、`kl_share_base/{task}` | 項が**どこへ**行ったか。**$b_j$ ではない** —— 分母が全タスク合計で動くので、一様増幅では両方の割合が変わらず比は 1 になる |
| `kl_sum_eff/{task}`、`kl_sum_base/{task}` | その絶対量。割合だけでは「割合は同じだが総量が動いた」を無変化と報告してしまう |
| `push_l2_logit_base/{task}`、`push_l2_logit_eff/{task}` | ロジット空間での OPD 押しの L2。**損失の行重み（`task_loss_weight`）込み**で、二乗和には重みの二乗が入る |
| `budget_ratio_logit` | $\sum_j b_j L_j / \sum_j L_j$（$L_j$ は上の base）。一様アームでは構成上そのアームの $b$。**校正が 1.000 に置いた量ではない**（上記のとおり空間が違う）。読み方は「その step にロジット空間で OPD 勾配をどれだけ増減させたか」 |
| `adv_zero_frac/{task}`、`pg_live_frac/{task}` | advantage が非ゼロのトークン割合と、**clip 後の PG 導関数が非ゼロ**のトークン割合。後者の方が小さい |
| `kl_mean_adv_zero`、`kl_mean_adv_live` | 蒸留項が報酬の台に対してどこに乗っているか。**2 つの因果経路の分離ではない**（下記） |
| `pg_dot_mean/{task}`、`pg_cos_mean`、`pg_dot_neg_frac` | 同一トークンのロジット上で、報酬の押しと教師の押しの内積（降下規約、負 = 対立）。**clip 反映済み**。位置づけは補助的なロジット整列 |
| `align_tokens`、`align_cover/{task}` | 上の整列指標が定義されているトークン数と、PG 生存トークンに対するその割合 |

**この readout が言えないこと**:

* **交差効果行列の対角ではない。** 符号が $JJ^\top$ を通って保存されないうえ、
  トークンは 1 つのタスクに属するので非対角 $C_{ij}\ (i\ne j)$ は原理的に載らない。
  「同一トークンのロジット上での方策と教師の局所的な関係」として読む。
* **advantage による KL 分割は 2 経路の分離ではない。** advantage が生きていても clip で
  PG 勾配が消えるし（だから `pg_live_frac` を併記する）、共有パラメータは同じ batch の
  他トークン・他タスクからも更新される。信号の分布を示す**補助分析**として有用。
* **`align_cover` は tail 近似の精度指標ではない。** この recipe は
  `student_indexed_topk=True` なので支持集合は**学生の** top-20 で、サンプルされた
  トークンはほぼ常にその中にある（実測 0.999〜1.000）。近似の精度を主張するには
  被覆率ではなく**支持集合外の確率質量**が必要で、それは測っていない。
* **落ちるのは台の外。** 内積・ノルムは KL 自身の支持集合上の和で、KL が tail を
  1 個の塊にしている以上その per-symbol 分割は無い。落ちる項は $p(v)^2$ を持つので
  peaked な方策では小さく、`test_opd_task_diag.py` がその減衰の速さを固定している。
* $g_{\rm opd}$ の式は autograd と照合済み。top-k+tail KL の tail が台の各ロジットに
  持つ依存は厳密に相殺するので、台の上では近似ではなく厳密。

**PG 側は $-A\rho$ ではなく `policy_loss_gradient_coef()` を使う。** $-A\rho$ は clip の
外でしか導関数ではなく、clip 枝・dual-clip 枝では真の導関数は厳密にゼロである。
$-A\rho$ で読むと、目的関数がもう押していない位置を**全振幅の対立**として報告する。
実際に起きた: 修正前の実機 step 1 で `pg_cos_mean` が $3.3\times10^{10}$ になった
（cosine は $[-1,1]$）。両ノルムが 0 の位置を整列母集団に入れ、分母を $10^{-20}$ で
clamp していたためで、いまはノルム 0 を**評価不能として除外**する。

**既存の `opd/…` 系にも $b_j$ が届く。** `opd_logit_push()` / `opd_attribution_terms()` は
行ごとの係数を受けるようにし、`_opd_effective_coef = \beta \cdot b_{\rm row}` を渡す。
$b$ は **OPD 側だけ**に入る —— `row_weight` は PG 側と共有なので、そこに $b$ を折り込むと
報酬側の勾配まで動き、対から作る cosine と比が「アームが適用していない理由で」動く。
$g_0$ が $b$ を持つので、内積は $b$、二乗ノルムは $b^2$ で変わる（損失中でそうなる通り）。
klw / signweight アームの event 系はスカラーのままで、この recipe では無効。

## 5. 理論的な位置づけ（主張の範囲を限定する）

* 命題 2 の指数型の固定点 $\pi^\star\propto\pi_d\exp(\tilde Q/(\beta b_j))$ は、位置ごとの独立最適化などの
  理想化に依る。実装は共有ネットワーク・PPO surrogate・top-k+tail の KL で、この式を根拠に
  「150→300 では 3 アームが区別できない」とは断定できない。
* OPD の一次寄与が RL 自身の 0.25〜0.99% と小さいことから、**成功率への経路を固定点移動だけに限定はできない**。
  この比は特定 checkpoint における射影の比で、複数 step の蓄積・曲率・訪問状態の変化を除外しない。
* 信頼を教師と独立な信号（報酬勾配）で決めているので、cross-teacher の識別不能性定理には触れない。
* 同一タスク対 $\tilde C_{ii}$ には共分散が混入する（$r_i$ と $d_i$ は同じ軌跡から）。
  **対角を除くと順位は同じまま $b$ は (1.076, 1.191, 0.500) → (0.993, 1.234, 0.500) に変わる**
  —— alfworld は増幅から微減へ。改訂 1 の「対角を除いても $b$ に効かない」は誤り。
  webshop 列の負性の 40% は対角（自分の教師と自分の報酬の対立）であり、これは干渉ではない。
  対角を含める現行の選択は、$c_j$ を「その教師の押す向きと全タスクの報酬勾配の整列」と定義した帰結であって、
  干渉だけを測る選択ではない。
* 勾配類似度を補助損失の重みに使う先行研究（Du et al. 2018）はあるが、そこでの保証は本案の
  静的な再配分に移せない。

## 6. 限界（走らせる前から分かっていること）

* **$C$ は一次・局所・$P=I$ の量。** Adam 幾何の $C$ は control では本ホストで測れない（HF マージで `exp_avg_sq` を失う）。
* **保存されるのは校正データ上の線形予算だけ。** 合成ノルムは +11.1%（RMS）、batch 別の線形予算比は 0.973〜1.014。
  KL 損失値・Adam 更新量・学習中の累積的な拘束は保存しない。一様アームはこの合成ノルムを校正 checkpoint 上で
  合わせた比較対象であり、学習中の更新強度を一致させ続ける対照ではない。
* **box $[0.5,1.5]$ は選択であり、測定から出ていない。** $b_{\text{webshop}}=0.5$ は $\kappa$ を境界まで進める設計の帰結。
* **順位は checkpoint 1 点・プロンプト列 1 本から出ている。** 8 バッチは同じデータローダから続けて引いたもの。
* **A は測定点（step 300）と適用点（step 0）が一致しない。** 検定できるのは「後期の測定に基づく固定配分が
  初期学習に有用か」であり、null が出ても「早期の順位が違った」と「配分が効かない」を区別できない。
* **タスクごとに OPD 依存度が違う。** $A=0$ のトークン（OPD が唯一の勾配）は alfworld 21.5%・webshop 62.3%・
  search 76.1% で、$A=0$ は群まるごとの単位。これは機構の非対称ではない（規則は同一、データが違う）が、
  webshop の結果は「干渉の解消」と「蒸留信号の半減」の両方から出るので単独では識別できない。
  退化群・生存群での層別評価は**補助分析**にはなるが、各アームの結果から群を分類すると処置後の状態で
  比較対象を選ぶことになる。共通の baseline 分類を固定しても、まず関連の分析として扱う。
* **判定の根拠は交差効果だが、係数が効くのはそのタスク自身の学習である。** タスク $j$ の OPD 項は
  タスク $j$ の行にしか触らないので、「他タスクへの害を減らす」ための唯一の操作が「そのタスク自身の
  蒸留を減らす」になる。(source teacher, target task) の重みが要るが、この損失にその自由度は無い。
* **各条件 1 学習 run。** 評価 3 回は評価雑音の見積もりで、学習 seed の変動を含まない。
* **1 step は実測 590 秒**（RTX PRO 6000 ×2、`rollout.n=8`、3 タスク。4 step の平均 588 秒）。
  300 step で **約 49 時間/アーム**、3 アームで約 147 時間。update の peak reserved は 103 GB。
* **step 0 の信号分布は校正時（step 300）と大きく違う。** 実測の `adv_zero_frac` は
  alfworld 0.000・search 0.000・webshop 0.223 で、校正時の 0.215 / 0.761 / 0.623 とは
  別物である。$b$ は step 300 の測定から作られているので、これは §3.1 の
  「測定点と適用点が一致しない」が具体的にどれだけ効くかの実測値になる。
* **`total_training_steps` は cosine スケジュールの分母である**（`ray_trainer.py:819` → `fsdp_workers.py:498`）。
  300 に揃えたので、既に走り終えた `verl_agent_opd_grpo_cross_teacher_klw_control_multitask_xt1`
  （$\beta$=0.01、`cross_teacher_kl_weight.enable=False`、すなわち機構的には素の OPD+GRPO、step 300 完走）と
  **スケジュールが一致する**。ただしスケジュール一致は流用可能を意味しない: 別ホスト（A6000×3）で、
  コード版が違い、`opd_diag` の readout を持たない。流用するなら、その 3 点を明記した上で
  「参考」ではなく対照として使う根拠を別に示す必要がある。
* **走行中の readout は対角しか測れない。** トークンは 1 つのタスクに属するので、
  トークンごとの量に非対角 $C_{ij}\ (i\ne j)$ は載らない。アームが前提にしている干渉そのものを
  学習中に測る手段は、いまも 6 倍の backward を要する測定 step しかない（下記）。
* **適応版（学習中に $C$ を測って $b$ を更新する）は採らない。** backward が 6 倍になる測定 step が要り、
  FSDP の勾配取得は 2 度の取り違え（mini-batch 1 つ分、gathered buffer）を起こした経路である。

## 7. 判断済み

* $S$ は全 3 タスク（等しい票）。
* 一様アームを足す（3 アーム）。倍率は RMS 基準の 1.111。
* **A を pilot として固定。** B1/B2 は起動条件にせず、早期の $C$ は B' の形で別実験にする。
* 3 アームは 1 本のスクリプト（`ARM=...`）に置く。アーム間の差が $b$ だけであることは
  試験で固定してあり、ファイルを分けるとその担保が読み比べに戻る。
* 走行中の readout を 3 アームすべてで on にする（lock に固定）。片方だけ計測した比較は、
  後から埋められない穴になる。
* 撤回した主張（機構・理論）: 「負の内積は有益な正則化の証拠」「総量を委ねると必ず縮む（定理として）」
  「一次寄与が小さいから固定点だけが経路」「150→300 では区別できない」「cosine が小さい = 信頼度割引済み」
  「対角を除いても $b$ に効かない」「同じ順位なら同じ $b$」「null で機構族を閉じる」「5pp 未満は決められない」。
* 撤回した主張（readout）:
  「`budget_ratio_logit` は校正が 1.000 に置いた量で、1 からのずれが予算保存の崩れである」
  —— 校正はパラメータ空間、これはロジット空間で、$JJ^\top$ を挟むので同じ量ではない。
  「`pg_dot_mean` は交差効果行列の対角である」—— 符号が保存されず、非対角は原理的に載らない。
  「`kl_share_eff/kl_share_base` で $b$ の適用が確認できる」—— 分母が動くので一様増幅では比が 1。
  適用確認は `kl_sum_eff/kl_sum_base`（実機 step 1 で $b$ に一致）。
  「advantage ゼロ／非ゼロの KL 分割が 2 つの因果経路を分ける」—— clip と共有パラメータがあるので分けない。
  「`align_cover` は tail 近似の精度を示す」「支持集合は教師の top-20」
  —— `student_indexed_topk=True` では**学生の** top-20 で、被覆率は近似精度の指標にならない。
