## A. 実装と食い違う点(最重要)

### A-1. 重み付けの説明が、実際に走らせた機構と違う

原稿: 「本来の学習信号に、増強時は1.25倍、減衰時は0.75倍の重みづけを行った」

実際に走ったのは **target モード**で、教師の目標分布そのものを書き換えている:

$$\tilde p(v) \propto w(v)\, p_{\text{teacher}}(v), \qquad
\log \tilde p(v) = \log p_t(v) + \log w(v) - \log Z$$

$Z = \sum_v w(v)p_t(v) + \text{tail}$(top-k 外の質量は重み 1.0 のまま)。

**「学習信号に 1.25 倍を掛ける」と書くと、別物かつ逆効果の操作を指す。**
蒸留損失は reverse KL $\sum_v p_s(v)(\log p_s(v) - \log p_t(v))$ であり、
候補 $v$ の項は**生徒自身の質量が払うコスト**なので、そこに 1.25 を掛けると
生徒はその候補から確率を逃がす。数値確認済み: 教師が (0.5, 0.5) のとき
候補1に1.25・候補2に0.75を掛けて最小化すると、生徒は候補1を **0.38 に下げる**。

修正: 「off-task 教師の符号一致に応じて on-task 教師の**目標分布を候補ごとに
重み付けして再正規化**し、その分布へ蒸留した」と書く。
重み 1.25/0.75 は目標分布に掛かる係数であって損失の係数ではない。

### A-2. policy shift の定義が対数空間でない

原稿: $\delta_i = \pi_i(\cdot|x_{<t}) - \pi_0(\cdot|x_{<t})$(確率の差)

実装: $\delta_m(v) = \log \pi_m(v|s) - \log \pi_0(v|s)$(**対数**確率の差)

符号だけなら両者は一致するので、4パターン表の議論は成立する。
しかし**デッドゾーン閾値 0.1 は nats(対数空間)の量**であり、
確率差として定義すると意味が変わる。原稿はデッドゾーンに言及していないが、
実装では中立が全候補の 60% を占める主要な状態なので、記述が必要。

修正: 定義を $\log$ 差にし、$|\delta| < \varepsilon$(= 0.1 nats、
「そのトークンの確率を約10%動かした」に相当)を「判断なし」とする旨を追記。

### A-3. 4パターン表が網羅的でない

原稿の表は4パターンを尽くしているように読めるが、実装には**中立が2種類**ある。

| 状態 | 実測比率(step1) |
|---|---|
| 一致(正・正) | 0.261 |
| 一致(負・負) | 0.030 |
| 対立(正・負) | 0.061 |
| 対立(負・正) | 0.047 |
| **中立: on-task がデッドゾーン内** | 0.040 |
| **中立: off-task 2教師が割れる/沈黙** | **0.561** |

**候補の 60% は4パターンのどれでもない。**特に「off-task 教師が全会一致でなければ
重み付けしない」は機構の中核仕様であり、表から漏れていると
「対立時に何をするか」の説明が不完全になる。

また表の「減衰または普通」は曖昧。実装は 0.75 で確定しているので
「減衰(0.75)」と書き、中立行を追加すべき。

## B. 実測データと食い違う / 主張が強すぎる点

### B-1. 「AlfworldとWebshopは期待通り精度向上し」→ WebShop は有意でない

自己相関補正つき対応あり検定(学習ロールアウト、step 1-202):

| | 平均差 | p |
|---|---|---|
| AlfWorld | +0.0530 | **1.4e-06** |
| WebShop SR | +0.0134 | **0.33** |
| Search | +0.0006 | 0.85 |

検証(N=126)でも WebShop Acc は +0.055、z=0.92、**p=0.36** で有意でない。

修正: 「AlfWorld は明確に向上し、WebShop も同方向だが有意水準には達しなかった。
Search は変化なし」。3タスクを2群に分けるのではなく、**AlfWorld と Search の
コントラスト**(p=1.4e-06 対 p=0.85)を主張の軸に置く方が強い。

### B-2. 300step で5手法を超えるという見通しは、自分の表が否定している

原稿は「原理的には300step目において5手法の値を超える」と書き、
その後の300step表で重み付け後を示すが、**5手法最高値との比較を書いていない**。

| 300step | 重み付け後 | 5手法最高 | |
|---|---|---|---|
| AlfWorld | 0.810 | 0.849 (SDAR) | −0.039 |
| WebShop Score | 0.838 | 0.869 (OPD+GRPO) | −0.031 |
| WebShop Acc | 0.730 | 0.738 (OPD+GRPO) | −0.008 |

**3指標すべて未達。**目標が達成されていないことを明記しないと、
読者が表を見て自分で気づいたときに信用を失う。

さらに step 201-298 の学習曲線では:

| | 1-202 | 201-298 |
|---|---|---|
| AlfWorld | +0.0530 (p=1.4e-06) | **+0.0008 (p=0.90)** |
| WebShop SR | +0.0134 (p=0.33) | **−0.0207 (p=4.5e-04)** |
| WebShop score | +0.0098 (p=0.37) | **−0.0253 (p=1.6e-07)** |

**後半は AlfWorld で利得ゼロ、WebShop で有意に劣化。**
「300step の上昇はほぼ GRPO」だけでは、この縮小と反転を説明できない
(GRPO のおかげなら150stepで得た差はそのまま持ち越されるはず)。

修正: 「蒸留信号は150stepで飽和し、**かつ両アームが共通の GRPO 最適解へ収束する**ので、
蒸留側で作った差は後半で吸収される。WebShop では生徒が既に教師を超えているため、
書き換えた目標が**古い教師へ引き戻す錘**として働き、劣化に転じる」。
この説明は理論(3タスク同時の最適解は routed OPD で、そこに転移は無い)から
演繹でき、**アニーリングという処方箋も同時に導ける。**

### B-3. 「蒸留は原理的に教師性能を上界とする」は成り立たない

冒頭の論証の要だが、**SFT(教師軌跡への NLL)では定理でない。**
教師の成功率は T=0.4 サンプリング下の測定値であり、
BC は分布を先鋭化して**サンプリング平均を超えうる**。

修正: 「on-policy 蒸留(reverse KL)の固定点は教師分布であり、
教師を超える機構を持たない」に限定するか、
「SFT/オフポリシー蒸留の教師超えは、分布の先鋭化でも説明しうる」と
対抗仮説を明記した上で「跨タスク転移が寄与している可能性」と留保する。

### B-4. 「単にOPD手法として提案した方が良い」— 純OPDには別の問題がある

純OPD@300 の AlfWorld は **0.611 で、教師 0.667 を下回っている**(原稿の表にある)。
150step では 0.683 > 0.667 で超えているが、300step で崩れる。
「上界突破」を主題にするなら、この崩壊を説明できないと苦しい。

## C. 関連研究の誤り(新規性主張に直結)

### C-1. MAD-OPD は「教師の上界突破を狙った研究ではない」→ 誤り

MAD-OPD の**タイトルが "Breaking the Ceiling in On-Policy Distillation"** であり、
結論部は「OPD のボトルネックは**教師プールの多様性**であって単一教師の能力ではない」
と述べ、**4B が 14B を上回る事例**を挙げている。上界突破そのものが主題である。

**生き残る差別化は「single-task か multi-task か」。**
MAD-OPD の教師は同族サイズ違いの汎用モデル(Qwen3 14B+8B / 32B+30B-A3B / Qwen3.5 27B+9B)で、
タスク特化の概念がない。**多教師ではあるが多タスクではない。**

修正: 「MAD-OPD は多教師による上界突破を扱うが**単一タスク**であり、
タスク特化教師間の跨タスク転移は扱っていない」。

### C-2. PromptSD を「単OPSD手法で、MOPD手法ではない」→ 誤り

PromptSD の正式タイトルは
**"One Student, Many Teachers: Multi-Task On-Policy Distillation via Soft-Prompt Privileged Context"**。
タイトルに Many Teachers と Multi-Task が入っており、
実装もタスクタグ $k$ ごとにソフトプロンプト教師 $\pi_{\theta+P_k^\star}$ を
ルーティングする多教師構成である。

さらに**正の跨タスク転移を明示的に報告している唯一の論文**でもある:
> "Multi-task exposure thus provides **positive cross-task transfer**"

Math で単一タスク OPD 51.0% → マルチタスク 67.2%(+16.2pp)、
leave-one-teacher-out(Math の教師とデータを両方除外)でも Math 61.0%。

**これは本研究の最近接競合である。**「単OPSD」と書いて退けるのは通らない。

生き残る差別化:
- PromptSD の教師は**同一凍結バックボーン + ソフトプロンプト**(共有表現型)。
  本研究の教師は**独立に RL 訓練された単一タスクチェックポイント**
- PromptSD の転移経路は共有表現。本研究は**教師間の policy shift の符号一致**
- PromptSD は「転移が起きた」を報告。本研究は**「どのタスク対で起き、どこで起きないか」を
  事前に予測できる量で説明する**

### C-3. 「MOPDにおける知識転移による教師の上界突破の研究は見つからなかった」

C-1/C-2 を踏まえると、この主張はそのままでは通らない。
正確には次のように狭める必要がある。

> 多教師 OPD で上界突破を扱う研究(MAD-OPD)は単一タスクであり、
> 多タスク OPD で正の転移を報告する研究(PromptSD)は共有表現を課した教師を使う。
> **独立に訓練された単一タスク教師どうしの policy shift の一致を転移信号とする研究**は、
> 調べた限り見当たらない。

この形なら、私が精読・掃引した範囲(MOPD/Two-Phase/CaMOPD/UI-MOPD/MAD-OPD/PromptSD/
ATOD/Direct-OPD/ExOPD/Revisiting-OPD + トークン重み付け20本超 + サーベイ2本)と整合する。

### C-4. 脚注しておくべき事実

- **MOPD (2606.30406)** は MiMo-V2-Flash で生徒が教師を上回る事例を報告している
  (HMMT25 +1.8 等)。著者は反復ラウンドの効果に帰属させており跨タスク転移とは
  主張していないが、「MOPD は上界突破を扱わない」と書くならこの事例に触れておくと安全。
- **ExOPD (2602.12125)** に上界突破の**形式的定理は存在しない**(informal な Remark のみ)。
  「理論」と書くと過大。
- **Two-Phase (2606.30044)** も Phase 2 で per-task 教師ルーティングを持つ。
  外部手法が軒並み転移経路を遮断している、という構図の補強に使える。
