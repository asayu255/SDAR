記録日: 2026-08-15 / アーム: `sdar_multitask_opd_grpo_signweight_target_qwen3_1.7b`
対照: 1本目実験の OPD+GRPO アーム(`sign_weight.*` 以外は同一設定、ロックテストで機械検証済み)。

## パターンとしての証拠(単独 z より強い部分)

1. **事前予測の的中(負の対照)。**「Search は動かない」は
   `docs/multitask_mechanism_v2_proposal.md` §3.5 に**走行前(8/10)にコミット済み**の予測。
   実測 −0.001。動くと予測した2タスク(界面・プロンプトを実装レベルで共有)だけが動いた。
2. **6アーム包絡の外。**1本目5アーム@150 の範囲は AlfWorld 0.540–0.683 /
   WebShop Score 0.760–0.785 / Acc 0.611–0.659。重み付けアームは3指標すべてで
   包絡上端を超える(+0.079 / +0.030 / +0.031)。目的関数が大きく異なる5アームの
   ばらつき幅を超えており、「アーム間ノイズの範囲内」では説明しにくい。
   (ただし包絡最大値との比較は選択バイアスを含むため記述統計に留める。)
3. **サンプル効率。**AlfWorld 0.762@150 は対照の 300step 値 0.754 を既に超える
   (半分のステップで対照の到達点)。WebShop は未達(score 0.869 / Acc 0.738@300)。
4. **教師超えマージンの拡大。**WebShop Acc の教師超えは対照でも +0.048 あったが
   +0.103 に拡大。AlfWorld は対照が教師未満(−0.016)だったのが +0.095 に。
   target モードは固定点を教師から動かす唯一の変種であり、教師超えの拡大は機構の
   予測方向と整合する。

## 検討して棄却した交絡: 「再正規化そのものが効いたのでは」

target モードは `reweight_teacher_logprobs` の中で再正規化を行う。元の OPD には
無かった処理なので、利得が符号情報ではなく再正規化に帰属する可能性を検討した。

**棄却の根拠1(厳密)。**tail(top-k 外の質量)を別枠で保持しているため、
w≡1 のとき $Z = \sum_v p_t(v) + \text{tail} = 1$ となり、関数は**厳密な恒等写像**になる
(数値確認済み: max|out−in| = 0.000e+00)。Revisiting OPD 方式の
「top-k 内で再正規化して推定量を変える」には**なっていない**。重みが一様なら
何も起きない以上、再正規化は独立した介入たりえない。
テストで固定: `test_target_shift_is_exactly_zero_when_nothing_is_flagged`。

**棄却の根拠2(より厄介な変種)。**「重み付けが目標分布を系統的に鋭く/平坦にした
=温度変更だったのでは」という交絡。step151 実測の状態比率で、重みと候補順位の相関を
3通り(無相関/高確率ほど増強/その逆)に振って測定した結果、
エントロピー変化は −0.003〜−0.005 nats、**等価温度 T≈0.998**。温度換算 0.2% であり、
AlfWorld +0.111 を説明できる量ではない。

**重要な副次的帰結。**この交絡が小さいことが、符号シャッフル対照の解釈を可能にする。
シャッフルは符号情報と系統的シャープ化の**両方**を同時に壊すので、もしシャープ化が
効いていたなら「シャッフルで利得消失」は符号情報の証拠にならなかった。
T≈0.998 が確認できているので、シャッフル対照は符号情報を特異的に検定できる。

**次回走行では実測する。**`sign_weight/target_kl`(= KL(教師‖書換後目標)、
`actor/teacher_kl_loss` と同単位なので比が読める)と
`sign_weight/target_entropy_delta` をステップ毎に記録するよう実装済み。
上記はシミュレーションによる推定なので、実測値で置き換えること。

なお参考として、シミュレーション上の目標移動量は 0.004〜0.008 nats。
step151 の `actor/teacher_kl_loss = 0.222` に対して **2〜4%** にあたる。
「わずか数%の移動が +0.111 を生んだ」は、150step × 数百万トークンにわたる
一貫方向のバイアス蓄積として説明可能だが、同時に「その程度で動くなら中身ではなく
摂動の存在自体では」という反論も呼ぶ。シャッフル対照の優先度を上げる根拠。

## まだ言えないこと(誠実性のための列挙)

- **帰属は未確定。**利得が「教師間符号情報」によるのか「教師分布への摂動一般
  (label smoothing 的正則化)」によるのかは、符号シャッフル対照(同じ重み分布を
  ランダム割当)か position モードを走らせるまで分離できない。
  Search の不動は摂動一般説への部分的反証だが、Search は飽和気味(ATOD の外部傍証)
  なので決定打ではない。
- **シード1本。**デコード分散(T=0.4)も1回分。再評価×3が最安の頑健化。
- **300step での残存は未知。**1本目の転移は 150→300 で消えた。同じ消え方をするか、
  target モードの固定点移動が残るかが、次の決定的観測。
- **完遂規律への集中は弱い。**SR/score 比 0.836 → 0.847(+0.011)。利得は
  score と Acc に比例的で、v2 提案 §3.5 の予測1(空白ゲート付き K′ 用)を
  この簡易版が再現しているとは言えない。
- 対照の数値は1本目実験時の評価。同一プロトコルだが同時再評価ではない
  (GPU 数 3→2 の差もあり — 配置のみで目的関数は不変)。

## 300step の解釈: 何が支持され、何がされないか

**支持される: サンプル効率としての転移増強。**150step で開いた差が 300step で
50%(AlfWorld)/ 115%(Acc)/ 156%(Score)縮小した。両アームが共通の到達点へ
収束する形であり、1本目で観測された「転移は150stepで大きく300stepで消える」
パターンの再現である。理論(§5: 最適解に転移は存在しない)の予測とも一致する。

**支持されない: 到達点の押し上げ。**target モードは OPD 項の固定点を動かすが、
その OPD 項は損失全体の 3〜6% でしかない(`teacher_kl_loss_weighted × 0.01`
対 `pg_loss_weighted × 1.0`)。合成された最適解は GRPO が支配し、その最適解は
報酬最大化方策であって重み付けの影響を受けない。**固定点を動かす設計であっても、
動かした先が支配的でなければ到達点は変わらない** — これが観測と整合する説明である。

**要注意: WebShop の反転。**単独では有意でない(Acc z=−0.14)が、
Score/Acc の両方が同方向に負であり、単なるノイズと断じるには弱い。
対抗する読みが2つある。

1. 収束の行き過ぎ(初期値が高かった分だけ余地が少なく、たまたま下回った)
2. 後半で蒸留項が GRPO と綱引きし、重み付けが有害化した

区別する材料: 対照の 150→300 の伸びは3指標とも +0.10 前後で揃うのに対し、
重み付けアームは +0.048 / +0.040 / +0.023 と一貫して小さい。
「高い所から始めたので伸びしろが少ない」で説明できる範囲かどうかは、
**中間ステップ(200, 250)の評価**で決まる。単調に縮むなら 1、
どこかで頭打ち・下降に転じるなら 2。チェックポイントは `save_freq=25` で
残っているので追加学習なしで測れる。**最も安い決定的観測。**

## 「300step の上昇は GRPO によるもの」という主張について

方向としては1本目のデータに支持される(純OPD は Alfworld 0.683@150 → 0.611@300
と実際に劣化しており、蒸留信号は150step で頭打ち)。ただし論文に書く際は
**主張が一段強すぎる**点に注意。

- 「上昇量はほぼ GRPO」なら、150step で得た差は**そのまま持ち越されるはず**で、
  縮小・反転は説明されない。実際に必要な主張は
  「蒸留信号は 150step で飽和し、**かつ**両アームが共通の GRPO 最適解へ収束するので、
  蒸留側で作った差は後半で吸収される」である。
- この主張は §5 の理論(3タスク同時の最適解は routed OPD で、そこに転移は無い)
  から演繹でき、1本目の5アーム全体の 150→300 挙動とも整合する。
  **理論からの予測が2本の独立な実験で当たった**という形にできる。

### ステップ単位の検定 — 何を計算したか

wandb には `episode/<task>_success_rate` が **1 step につき 1 値**記録される
(その step の学習ロールアウト 15 prompt × 8 rollout = 120 軌跡、**温度 1.0**)。
報告している差は、**その値の 202 step 分の平均の差**(重み付け − 対照)である。
検証(T=0.4、N=126、別プロセス)とは測っているものが違う。

検定は3段階で見直した。**当初報告した対応なし Welch は誤りで、下の(3)を正とする。**

| | AlfWorld 全202 | AlfWorld 後半101-202 | Search 全202 | WebShop SR 全202 |
|---|---|---|---|---|
| 平均差 | +0.0530 | +0.0694 | +0.0006 | +0.0134 |
| (1) 対応なし Welch(当初報告・**不適切**) | t=+2.52, p=0.012 | t=+5.06, p=4.2e-07 | t=+0.06, p=0.96 | t=+0.62, p=0.53 |
| (2) 対応あり t 検定(**過大評価**) | t=+10.1 | t=+9.94 | t=+0.19, p=0.85 | t=+2.58, p=0.010 |
| **(3) 自己相関補正(採用)** | **t=+4.82, p=1.4e-06** | **t=+6.49, p=8.7e-11** | **t=+0.19, p=0.85** | **t=+0.97, p=0.33** |
| (4) ブロックブートストラップ(L=20) | p<0.0001 | p<0.0001 | p=0.80 | p=0.22 |

**(1) が不適切な理由**: 両ランは `data.seed=1` で同じスケジュールを走るので、
step k は両アームで同じプロンプト集合を見る。**観測は対応がある**のに、
対応なし検定は各アームの学習曲線そのものの分散(0→0.7 への上昇)を誤差に数えてしまい、
検出力を捨てている。実際 AlfWorld の差の標準偏差は 0.0745 で、
各アームの曲線の標準偏差よりはるかに小さい。

**(2) も不適切な理由**: 連続する step は方策を共有するため自己相関がある
(AlfWorld: ρ1=+0.19, ρ2=+0.26)。n=202 を独立標本として扱うと有意性を過大評価する。

**(3) の方法**: 対応差 d_k = sw_k − ctrl_k の自己相関から実効標本数
n_eff = n / (1 + 2Σρ) を求め、SE を n_eff で計算した。
AlfWorld は n_eff=46.0(202 の 23%)、Search は n_eff=201.1(ほぼ独立)、
WebShop は n_eff=28.8(最も自己相関が強い)。
(4) のムービングブロックブートストラップ(ブロック長20)も同じ結論を与える。

### 補正後の結論

- **AlfWorld: 頑健**。実効標本数を 1/4 に割り引いても p=1.4e-06、後半は p=8.7e-11。
- **Search: 完全な帰無**。しかも自己相関がほぼ無く(n_eff=201)、
  「差が無いことを 201 の独立観測で確認した」に近い。負の対照として最も強い形。
- **WebShop: 有意でない**(p=0.33)。自己相関が最も強く実効標本数が 28.8 しかない。
  検証で 150step +0.055 / 300step −0.031 と揺れたことと整合する。
  **WebShop は「動いた」と主張できない。**

したがって、学習曲線が支持するのは
**「AlfWorld のみ明確に加速、Search は完全に不変、WebShop は判定不能」**である。
当初「AlfWorld と WebShop が動いた」と書いたが、WebShop は補正後には支持されない。

### この比較が加えるもの

1. **負の対照が桁違いに強くなった。**Search は 202step 通じて差 +0.0006(p=0.96)。
   検証の1点(−0.001)ではなく202点の帰無。事前登録した予測の的中として、
   これが最も強い形。
2. **AlfWorld の優位は一過性ではない。**4帯すべてで正、後半で拡大(+0.034→+0.080)。
   自己相関補正後も p=1.4e-06(後半 8.7e-11)で、検証@150 の z=1.95(p=0.051)より遥かに堅い。
3. **完遂規律の証拠が別経路で出た。**v2提案 §3.5 の予測1(利得は完遂規律に集中)は
   検証の SR/score 比では確認できなかったが、学習側では
   **エピソード長 −0.84 turn(p=0.003)、応答の 512 トークン打ち切り率 −0.021(p=2.5e-06)**
   として明確に出ている。「だらだら書かず早く終える」= 完遂規律であり、
   予測は当たっていたが測る場所が違った。
4. **WebShop は判定不能。**帯ごとに符号が反転し(+0.024 / −0.032 / +0.052 / +0.010)、
   自己相関補正後の p=0.33。検証で 150step +0.055 → 300step −0.031 と反転したのは
   この不安定性の反映であり、「後半で有害化した」の証拠にはならない。
   同時に「150step で WebShop が改善した」も主張できない。

## 後半 201-298 の学習曲線(継続ラン `verl_agent_opd_grpo_tmp_multitask/i1nbo7wz`)

再開後の方がむしろ高い。`_fast_forward_env_schedules` は正しく巻き戻しており、
**201-298 も対照と同じ問題セットの比較として有効**。前回挙げた「再開後のずれ」懸念は解消。

### 自己相関補正つき対応あり検定

| 指標 | 区間 | n_eff | 平均差 | p |
|---|---|---|---|---|
| AlfWorld | 1-202 | 46.0 | **+0.0530** | **1.4e-06** |

### これで確定したこと

**1. AlfWorld の利得は完全に消える。**+0.053(p=1.4e-06)→ **+0.0008(p=0.90)**。
「縮小」ではなく**厳密にゼロ**。両アームが同じ到達点へ収束したという読みが、

検証の 300step で WebShop が −0.031 / −0.008 だったのは、この持続的な劣位の反映であり、
**「収束の行き過ぎで偶然下回った」ではなく「後半は実際に不利」**が正しい。

**3. Search は全区間で不変。**1-202 も 201-298 も帰無(p=0.85 / 0.77)。
事前登録した負の対照は 300step 通じて成立。

### 機構の総合像(修正版)

| 区間 | AlfWorld | WebShop | Search |
|---|---|---|---|
| 前半 1-200 | **加速(p=1e-06)** | 判定不能 | 不変 |
| 後半 201-298 | **利得ゼロ** | **有意に劣化(p=1e-04〜1e-07)** | 不変 |

つまりこの機構は **前半の AlfWorld を加速し、後半の WebShop を損なう**。
「サンプル効率を買うが到達点は変えない」という当初の総括は、AlfWorld については正しいが、
WebShop については**到達点を下げている**ので不十分。正確には:

> 蒸留項の目標を跨タスク合意で書き換えると、共有構造の多いタスクでは
> 学習前半を加速するが、その書き換えは後半 — GRPO が支配的になり、
> 生徒が教師を追い越した後 — には**古い教師の方へ引き戻す錘**として働く。

これは §5 の理論(最適解に転移は無い)のより強い形の確認であり、
同時に**アニーリングの必要性**を示している。ATOD (2606.27814) の
annealed OPD→RL が同じ問題への処方箋であり、本機構と直交して併用できる。


## なぜ AlfWorld↔WebShop で転移し、Search で起きないのか — データセット側の性質

機構が測っているのは「on-task 教師の top-20 トークン上で、off-task 教師の
policy shift の**符号**が一致するか」である。したがって効くのは入力の意味的近さではなく
**出力分布の近さ**であり、それを決めるデータセットの性質は以下の3層。

### 第1層: 応答フォーマットが同一(最も直接的)

| | 生成すべきタグ |
|---|---|
| AlfWorld | `<think>` `</think>` `<action>` `</action>` |
| WebShop | `<think>` `</think>` `<action>` `</action>`(**完全一致**) |
| Search | `<think>` `</think>` + `<search>`/`<answer>` の**排他選択** |

`projection.py` も AlfWorld と WebShop は行単位でほぼ同一(差は失敗時の切り出し長
`[-30:]` vs `[-20:]` のみ)。Search は別実装(`<search>` XOR `<answer>`、両方あると無効)。

機構は top-20 の**トークン**を見る。応答の骨格が同じなら、教師2人が同じ位置で
同じ構造トークンに同じ向きの shift を持つ。これが `agree_pos` の主要な供給源である。
step1 で `agree_neg`(0.030)より `agree_pos`(0.261)が圧倒的に多いのは、
サポートが on-task 教師の top-20 =「教師が確率を上げたトークン」に偏るためで、
その上位を占めるのが共有された構造トークンだと考えると整合する。

### 第2層: 行動空間が列挙されるか(タスクの型そのものが違う)

| | 行動の与えられ方 | 課題の型 |
|---|---|---|
| AlfWorld | `admissible_actions` がプロンプトに列挙 | **選択問題** |
| WebShop | `available_actions` がプロンプトに列挙 | **選択問題** |
| Search | 列挙なし。クエリ/答えを自由生成 | **生成問題** |

これは第1層より深い差である。選択問題では、決定点での出力分布は
「列挙された候補の先頭トークン」に集中する(`go`, `take`, `open`, `click`, `search[`)。
2つの教師が同じ「候補集合から1つ選ぶ」形式で訓練されていれば、
**探索を続けるか / 確定するか**という判断が同じ語彙で表現され、符号も揃う。

Search は開語彙の自然言語生成なので、top-20 の中身が問題ごとに入れ替わる。
off-task 教師がそこに意見を持つ理由がなく、`neutral_off_task_split` に落ちる。

### 第3層: プロンプト文面の逐語共有

履歴あり版テンプレートの語彙 Jaccard 一致率:

| ペア | Jaccard | 逐語一致行 |
|---|---|---|
| **AlfWorld ↔ WebShop** | **0.798** | **2行**(履歴提示文と行動提示文がそのまま同一) |
| AlfWorld ↔ Search | 0.320 | 0 |
| WebShop ↔ Search | 0.304 | 0 |

逐語一致している2行:
- `Prior to this step, you have already taken {step_count} step(s). Below are the most recent {history_length} observations and the corresponding actions you took: {action_history}`
- `Once you've finished your reasoning, you should choose an admissible action for current step and present it within <action> </action> tags.`

同じ文面が同じ位置に来るので、その直後の状態が2教師で近くなる。
**入力側の一致が、出力側の一致を支える。**

### 第4層(補助的): 地平と報酬の密度

| | 最大ターン | 報酬 |
|---|---|---|
| AlfWorld | 50 | 成功で 10、無効行動に −0.1 |
| WebShop | 15 | 部分点あり(task_score)+ 無効行動に −0.1 |
| Search | **4** | **strict EM の完全二値**(`format_score=0.0`、中間報酬なし) |

AlfWorld/WebShop は「長い地平で探索し、いつ確定するか」を学ぶ課題であり、
1本目のスキルライブラリ対応(Systematic Exploration ↔ Query Refinement、
Terminate Only On Success ↔ Purchase Decisively)はこの共通性の言語化である。
Search は4ターンで二値判定なので、学習されるのは「探索の打ち切り規律」ではなく
クエリ設計であり、共有する余地が構造的に小さい。

実測でもこの層は裏付けられる: 本機構が実際に動かしたのは
**エピソード長 −0.84 turn(p=0.003)と 512 トークン打ち切り率の半減(p=2.5e-06)**、
すなわち「だらだら続けず早く終える」であった。これは第4層が共有する規律そのもので、
Search には(4ターン上限のため)そもそも学ぶ余地がない。

### 帰結: 何が「共通知識」の実体か

したがって「AlfWorld と WebShop は共通知識が多い」の内実は、意味的な近さ
(家事 vs 買い物)ではなく、**同じ出力言語で書かれた同じ型の課題**であることに尽きる。
反例予測として: 意味的には遠くても
「`<think>/<action>` 形式・admissible actions 列挙・長い地平」を満たす第4のタスクを足せば、
この機構は AlfWorld/WebShop と同様に転移するはずである。逆に、意味的に近い
買い物タスクでも自由生成形式なら転移しない。**これは検証可能な予測であり、
機構が意味ではなく形式に反応していることの決定的な検定になる。**
