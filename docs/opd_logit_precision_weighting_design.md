## 0. 本案が答えない問い（先に書く）

これまでの機構（静的 redistribute、pushback、cross gate、S-LP）は**タスク間の負の転移**を
扱おうとしていた。alfworld が +6pp 伸びる裏で search が −0.70pp 下がる、というシーソーである。

**本案はその問いを扱わない。** §3 の通り、等重み目的 $J=\sum_i J_i$ の下ではタスク間の
「対立」は誤りではなく和が正解なので、機構はタスク間に門を置かない。結果として決定則は
**完全に単タスク**に分解し、マルチタスクであることは最後の総和にしか現れない（§10）。

これは一般化ではなく**問いの差し替え**である。「3 タスクを同時に改善できるか」に答えたいなら、
等重み目的を捨てる宣言（§8-3）が別途要る。本案が改善しうるのは各タスクの蒸留の質だけである。

## 1. 問題の所在

1 step の中で共有パラメータは 6 本の信号を受ける。RL 3 本と OPD 3 本。
**同じ座標の上で出会う場所**でなければ「対立」は定義できない。

位置では出会わない。タスク $i$ の位置には RL$_i$ と OPD$_i$ しか乗らない。
出会うのは**共有された語彙 id** で、id $v$ のロジットはすべての位置で同じ出力行 $w_v$ から作られる。

$$
a_i[v]=\sum_{t\in T_i}\rho_t c_t\big(\mathbb 1[y_t=v]-\pi_t[v]\big),
\qquad
d_j[v]=\sum_{t\in T_j}\rho_t\, g^{\rm opd}_t[v]
$$

$c_t$ は `policy_loss_gradient_coef`（advantage・ratio・clip 分岐込み）、$\rho_t$ は `task_loss_weight`。

**$g^{\rm opd}$ は reverse KL の勾配である。** 走っている損失は
`core_algos.topk_kl_per_token`、すなわち student の top-k 支持上の
$\sum_{v\in A}p_s(\log p_s-\log p_t)+\text{tail}$ で、そのロジット勾配（降下方向）は

$$
g^{\rm opd}[u]=\pi[u]\,\kappa+\mathbb 1[u\in A]\,\pi[u]\,(F-f(u)),\quad
f=\log p_s-\log p_t,\; F=\log\text{tail}_s-\log\text{tail}_t,\;
\kappa=S_1-P_A F
$$

（$S_1=\sum_A p_sf$, $P_A=\sum_A p_s$。tail clamp が効く位置では $F=-1$ に置き換わる。）
**初版が書いた $(\tau-\pi)$ は forward KL の勾配で、誤りだった。** そのまま実装すれば目的関数が
mode-seeking から covering に黙って変わっていた。実装 (`topk_kl_logit_grad`) は上式で、
`topk_kl_per_token` を autograd で微分した値と一致することをテストで固定している。

**総和ゼロは厳密に成り立つ。** tail 項の勾配は全 id に $\propto\pi[u]$ で配られる（$\kappa$ の中の
$-P_AF$ がそれ）ので、$\sum_u g^{\rm opd}[u]=0$ が語彙全体で成立する（テストで $10^{-12}$）。
「tail を id に配れないから近似」というのは当たらない。

副次的に $g^{\rm opd}\propto\pi[u]$ なので、押しは **student が既に質量を置いている id に集中する**。
§6 の集中度はこの $\pi$ 因子と書式トークンの頻度を切り分けていない。

## 2. モデルと、その代償

座標 $v$ ごとに独立に扱う。$\theta_i[v]=\partial J_i/\partial b_v$ を真の勾配として

$$a_i[v]=\theta_i[v]+\varepsilon_i[v],\quad \mathrm{Var}=\sigma_i^2[v];
\qquad d_j[v]=\lambda_j\theta_j[v]+\zeta_j[v],\quad \mathrm{Var}=\varsigma_j^2$$

仮定は 4 つ。(1) 共有座標への押しは発信源について加法的。(2) 目的は等重み和
（`normalize_loss_by_task=True` が宣言済み）。(3) 教師はタスク $j$ の目的についての証拠である。
(4) 座標ごとの大きさは最適化器がある程度正規化する。

### 2.1 仮定 3 の代償: $\hat\lambda/\hat\varsigma^2$ は信頼ではなく「報酬との冗長度」

$d_j=\lambda_j\theta_j+\zeta_j$ と置いた時点で、**教師が $\theta_j$ と直交する系統的成分
$b_j[v]$ を持てば、それは $\zeta_j$ に、すなわち $\hat\varsigma_j^2$ に吸収される。**
蒸留の価値はまさにそこにあるはずなので、これは軽い近似ではない。

* BLUE は $u_jb_j$ だけ偏る。
* §4.4 の回帰は「教師の押しのうち、いま報酬が押しているのと同じ向きの成分」だけを数える。
* したがって $\hat\lambda_j/\hat\varsigma_j^2$ が大きい教師とは、**報酬と冗長な教師**である。
  報酬がまだ見つけていないことを知っている教師は、その分だけ低く出る。

**これは設計判断として引き受けるか、引き受けないかを決めなければならない。**

* 引き受ける場合: 本案は「教師のうち報酬と整合する成分を、その精度に応じて使う」機構である。
  教師固有の知識は使わない。$\beta$ を測定で決める、というのがそのまま到達点。
* 引き受けない場合: $\hat\lambda_j$ は**重みではなく診断**に格下げし、
  $\beta_j$ を動かす根拠としてのみ使う。§8-4 の「正の事前分布 + EMA」は後者の立場の処置であって、
  前者と両立しない。**初版はこの 2 つを混ぜていた。**

事前実験（§7）はどちらの立場でも同じものを測るので、判断は結果を見てからでよい。

### 2.2 $\hat\lambda_j<0$ の扱い

式のままなら $u_j<0$、すなわち**教師の押しを符号反転して適用する**。
「$\beta_j$ を下げる根拠」ではない。実装は既定で $\hat\lambda\ge0$ に clamp し、
clamp 前の値を `lam_raw` として必ず出す。反転を許すのは `allow_negative_lambda=True` の明示的な選択。

### 2.3 $\varepsilon$ と $\zeta$ の独立性

両者は同じ rollout の同じ位置から作られるので無相関は自明でない。
§4.4 の減衰補正は $\mathbb E[\varepsilon d]=0$ を使っている。**未検証の仮定**である。

## 3. 最適な結合と、それが担保しないこと

**命題（Gauss–Markov）。** $P=\sum_iw_ia_i+\sum_ju_jd_j$ が各 $\theta_i$ について不偏
（$w_i+u_i\lambda_i=1$）の下で分散最小にする係数は一意に
$w_i\propto1/\sigma_i^2$、$u_i\propto\lambda_i/\varsigma_i^2$。Gauss 性は不要。

**これが担保するのは「id ごとのバイアス勾配の最小分散不偏推定」までである。**
初版は「Adam が座標ごとに正規化するので分散最小＝期待進行最大」と書いたが、
**Adam が正規化するのはパラメータごとであって、ロジット座標ごとではない。**
$g_z[v]$ は出力行 $w_v$（2048 次元、しかも `tie_word_embeddings=True` なので入力埋め込みでもある）と
trunk の両方に流れ、trunk では全 $v$ の寄与が混ざってから正規化される。
id は**信号が出会う場所**であって、最適化器が対角になる基底ではない。§8-1/8-2 が
id 座標の粗さを限界として認めているのと、それを最適性の根拠に使うのは両立しない。撤回する。

残る主張は限定的だが有用である。**2 つの雑音のある測定値を 1 つの座標で束ねるとき、
精度重み付けは符号ゲートより良い。** 符号は雑音の多い推定量の最も当てにならない部分だからである。

## 4. 推定量

### 4.1 集約
§1 の 2 式。どちらの勾配も (疎) + (スカラー × $\pi$) なので、$k$ 個の scatter と
$\pi$ の重み付き列和で足りる。トークン × 語彙の中間テンソルは持たない。

### 4.2 RL の雑音床（順列、閉形式）

$$\sigma_i^2[v]=\sum_{r\in i}\frac{\big(\sum_r A_r^2\big)\big(\sum_r (m_r[v]-\bar m[v])^2\big)}{N-1}$$

$m_r$ は行の advantage-free id プロファイル。**母集団は「行」である。**
`compute_grpo_outcome_advantage` は `compute_mean_std_cross_steps=True` で平均・std を群の
**行**（trajectory × turn）で取るので、行単位では $\bar A=0$ が厳密に成り立つ。
trajectory 単位では turn 数が違うので成り立たない。初版は「prompt 群」と書いていた。訂正。

**改訂 3: これは本線ではなくなった。** 下の 3 つの但し書きのうち 1 番目が致命的だった。

* これは **H0（id の出現が報酬と無関係）の下の分散**であって、§2 の $\mathrm{Var}[\varepsilon_i]$
  そのものではない。$\sigma^2_{\rm perm}[v]=\text{spread}[v]\cdot\sum_rA_r^2/(N-1)$ で
  **id に依存するのは spread だけ**なので、これを使うと測定された係数の id 方向の形は
  「その id の出現プロファイルが行間でどれだけばらつくか」になる。報酬の情報量ではない。
  さらに advantage が消えると $\sum_rA_r^2$ が $a[v]$ と一緒に 0 へ行くので、
  **BRUE は厳密にゼロの押しに無限の精度を与え、教師の重みを 0 にする。**
  モデルが「測っていない」を「ゼロと精密に測った」と読む。webshop の 62% がその領域である。
  本線は §4.2' の step 間分散に移した。順列帰無は診断として残す。
* 群をまたいで並べ替えるので群識別も壊す、より広い帰無になる。雑音床を**大きめ**に見積もる側に
  倒れるので安全方向。
* $m_r$ は clip 分岐を無視して ratio だけを使う。k100 run 実測の clip 率は
  **1.28%（alfworld 1.37 / webshop 1.11 / search 0.49）**。初版が引いた 0.085% は
  term probe の alfworld stage 0 の値で、run の値ではない。訂正。点推定 $a_i$ は正確な $c_t$ を使う。

### 4.2' 本線: step 間分散

$\sigma^2[v]$ は「$a[v]$ が $\theta[v]$ の推定量として持つ分散」なので、
EMA が覆う step にわたる $a$ のばらつきがそれである。per-step の 1 次・2 次モーメントを
どちらも平滑化しているので直接取れる。

$$
\mathbb E[a^2]=\theta^2+\sigma^2,\quad \mathbb E[\bar a^2]=\theta^2+\sigma^2/n
\;\Rightarrow\;
\hat\sigma^2[v]=\big(\overline{a^2}[v]-\bar a[v]^2\big)\frac{n}{n-1}
$$

$n=w^2/w_2$ は EMA の実効 step 数（1 step 後に 1、極限で $(1+d)/(1-d)$、decay 0.8 で 9）。
$\tau^2=\overline{a^2}-\overline{\sigma^2}$ の形は**不変**なので、変更は $\sigma^2$ の 1 箇所だけである。

advantage の抽出自体のばらつきを含むので、1 step が平坦でも 0 に落ちない。
代償は step を要すること: $n<$ `min_eff_steps`（既定 3）の間は順列帰無に落ち、
判定コードは `warming_up` になる。**`lprecw` の適用パスは warm-up の当てはめを使わない**
（`beta_ratio_matrix` が係数 1 を返す）。

### 4.3–4.4 事前分散と教師の重み

$\hat\tau^2=\max(0,\overline{a^2}-\overline{\sigma^2})$、
$\hat\lambda_j=\overline{a_jd_j}/\hat\tau_j^2$、$\hat\varsigma_j^2=\overline{d_j^2}-\hat\lambda_j^2\hat\tau_j^2$。
$\hat\varsigma^2$ は負になりうる（事前分散の過小推定の徴候であって教師が無用という意味ではない）ので、
$\overline{d^2}$ の `min_residual_frac`（既定 $10^{-3}$）で下限を切り、`residual_floored` として報告する。

**$\hat\lambda$ は不確かさとともに出す。** §6 の通り押しは数個の書式トークンに集中するので、
名目上数千 id の回帰が実際には 10 個で決まりうる。Kish の有効標本数 $n_{\rm eff}$ と
id についての jackknife 標準誤差、$t=\hat\lambda/\mathrm{SE}$ を必ず記録する。
これを出さずに回帰係数を使うのは、符号門を「最も当てにならない部分」と批判した §9 の基準を
自分に適用していないことになる。

### 4.5 識別と適用を分ける（レビューで見つかった欠陥の修正）

**初版の推定量は、報酬が沈黙している座標で教師を切っていた。**
$\hat\tau^2$ は RL の押しだけから推定されるので、報酬が無情報な領域では 0 に落ちる。
そこで縮小係数 $k=\hat\tau^2/(\hat\tau^2+s^2)\to0$、$\hat\lambda=\overline{ad}/\hat\tau^2$ は発散または未定義。
**両方の重みが 0 になり、その座標は何も更新されない。**
この run script 自身が webshop の zero-advantage token を 62.3% と記録し、
そこでは OPD 項が唯一の勾配だと書いているので、仮想の話ではない。
さらに悪いことに、その領域をプールに入れると $\hat\tau^2$ が負に振れ、**タスク全体の推定が拒否される。**

修正（実装済み、テストで固定）:

1. **識別**は、報酬の押しが自身の帰無を超える活動量十分位（signal strata）でのみ行う。
2. 得られた $\hat\lambda,\hat\varsigma^2$ を**全 id に適用**する。
   **改訂 3 の訂正**: 初版はここで「沈黙している座標では $\sigma^2$ が大きいので $\beta$ も大きい」
   と書いたが、順列帰無の下ではこれは**逆**だった（§4.2）。$\sum_rA_r^2$ が縮むので
   $\sigma^2$ も $\beta$ も一様に小さくなる。step 間分散に替えて初めて、
   「報酬の推定が当てにならない座標では教師が重い」が実際に成り立つ。
   修正（識別と適用の分離）自体は正しく、タスク全体の拒否と縮小係数による教師の消失を防いでいる。
   誤っていたのは理由の説明だけである。
3. **縮小係数は適用しない。診断として報告するだけ。** 理由は上の失敗様式**のみ**である。
   初版はここでも「Adam の下では座標ごとの再スケールはほぼ無作用」と書いていたが、
   §3 でその議論は撤回済みであり、撤回した前提を別の箇所で根拠に使っていた。訂正する。
4. `no_rl_signal_frac` を出し、その領域の大きさを可視化する。

適用される量は**一つだけ**である。

$$\omega^R_i[v]=1,\qquad \omega^D_i[v]=\beta_i[v]=\hat\lambda_i\,\sigma_i^2[v]\,/\,\hat\varsigma_i^2$$

$\beta_i[v]$ は run の `kl_loss_coef`（現行 0.01）と**同じ単位**である。
暴走を防ぐため `max_beta_ratio`（既定 1000 倍）で上限を切り、`beta_at_cap_frac` を出す。
cross gate の $\lambda_{\max}$ が事後的に機構の実体だったと判明した件の再発防止である。

## 5. 実装

### 5.1 計測（実装済み、追加 forward/backward なし）

`logits_resp`（パック済み、(T, V)）は `response_only_logits` の forward が既に作っている。
そこから 4 本の重みを作り、$\pi$ を位置のチャンクに切って重み付き列和を取る。
最大の中間テンソルは (chunk, V) = 既定 19 MB。**トークン × 語彙は一度も持たない。**

### 5.2 適用（実装済み）とそのコスト

**改訂 2 が予告した密 cotangent 3.1 GB は不要だった。** 回避できる構造がある。

OPD 損失がロジットに届く経路は student の top-k 対数確率 $s$（(T, k)）だけである。
そのような損失なら必ず

$$\frac{\partial L}{\partial z_u}=\mathbb 1[u\in A]\frac{\partial L}{\partial s_u}-\pi[u]\sum_j\frac{\partial L}{\partial s_j}$$

すなわち **支持上の疎な項 + rank-1 の背景**である。したがって **$k$ 個の係数の側を重み付けして
log-softmax の backward をそのまま走らせれば**、

$$\mathbb 1[u\in A]\,w_u\frac{\partial L}{\partial s_u}-\pi[u]\sum_j w_j\frac{\partial L}{\partial s_j}$$

が得られる。支持上では $w$ が厳密に効き、背景には支持の加重平均が効き、
**同じ log-softmax の引き戻しなので語彙総和ゼロが自動的に保たれる**
（総和ゼロでない cotangent はロジットの全体水準を押す。方策は無視するがパラメータは動く）。
背景を id 別ではなく平均で重み付けするのは、背景が正規化子の反作用であって
教師の id 別の選好を含まないことの素直な帰結である。

実装は `reweighted_opd_surrogate`。$\partial L/\partial s$ は KL ヘッドだけを通る
backward 1 回（trunk に入らない）で取れ、あとは代理スカラーを損失に足すだけ。
**$w\equiv1$ で元の勾配を厳密に再現する**ことをテストで固定している（$10^{-12}$）。

**回帰が当てはめた対象と、適用する介入は同じものではない。** 測っている $d[v]$ は
rank-1 背景 $\pi\kappa$ を含み、その総量は支持側と同じ大きさ（符号は逆）である。つまり勾配の半分。
一方で適用側は支持に $w$ を厳密に当て、背景には**支持の加重平均**を当てる。
低活動 id の $d[v]$ はほぼ全部が背景成分なので、$\hat\lambda$ を決めている回帰は背景に強く駆動され、
適用側は支持しか制御しない。総和ゼロを保つには背景を id 別に重み付けできないので、
この非対称は避けられない。**評価のときにこの差を勘定に入れる必要がある。**

| 項目 | 量 |
|---|---|
| 追加 forward / backward | なし（KL ヘッドのみの VJP 1 回、trunk には入らない） |
| 計測の一時領域 | (chunk, V) = 19 MB、集約 3.6 MB、per-row プロファイル (bs, V) = 6 MB |
| 適用時の密テンソル | **不要** |
| 重み行列 | (n_tasks, V) = 1.8 MB、gather は (bs, resp, k) |
| 順列統計 | 行単位なのでタスクあたり 2 本の V ベクトル。群単位なら 45 群 × 8 × V ≈ 219 MB が必要だった |

**タイミング。** $a_i[v]$ はその step の全 micro-batch の forward が終わるまで確定しないが、
backward は micro-batch ごとに走る。**同一 step の重みは 1 パスでは作れない。**
実装は EMA を使うので構造的に **1 step 遅れ**（cross gate と同じ）。
初版の §5.1 擬似コードは同一 step に読めた。訂正。2 パスにするなら宣言が要る。

`torch.autograd.grad(logits, params, ...)` は FSDP 下では `logits.backward(g_z)` の形になる。
`entropy_coeff=0`、`use_kl_loss=False` なので他の損失項が無いことが前提で、
どちらかが変われば cotangent の組み立ても変わる。

## 7. 事前実験

| 手順 | 内容 | GPU | 時間 |
|---|---|---|---|
| 1 | 計測・適用の両方と 2 アーム（`ARM=lprec` / `lprecw`）。**実装済み**、199 テスト | 不要 | — |
| 2 | `ARM=lprec` の観測 run。学習は変えないので control 兼用 | 要 | 1.5 h |
| 2' | early（step 25）と late（step 150）の 2 点 | 要 | +1.5 h |
| 3 | 判定（下記） | — | — |
| 4 | 通れば `ARM=lprecw` | 要 | 18 h |

`lprec` と `lprecw` のコマンドラインは `observe_only` の 1 フラグだけが違う。
アームの中身とロックは `run_multitask_opd_coef_qwen3.sh` と
`expected_multitask_opd_coef_lprec{,w}_config.yaml`（各 120 キー固定）。

**判定基準（事前に固定）**

1. **$\hat\lambda_i\sigma_i^2/\hat\varsigma_i^2$ が 0.01 と桁で違うか、タスク間で桁で違うか。**
   違えば本 run に進む価値がある。3 タスクで同じで 0.01 に近ければ、取り分は id 依存だけ。
2. **$\hat\lambda$ の $t$ 値と $n_{\rm eff}$。** $n_{\rm eff}$ が 10 前後なら、
   $\hat\lambda$ は「回帰係数」ではなく「数個の書式トークンの比」である。$|t|<2$ なら使わない。
3. **RL 無情報領域の大きさ（`no_rl_signal_frac`）。** タスク・役割・活動量十分位ごとに数える。
   大きければ $\hat\lambda$ を識別できる id が少ないということで、
   それは $n_{\rm eff}$ と併せて基準 2 に効く。
   なお**この基準の読み方は改訂 3 で変わった**（§4.5-2）: 順列帰無の下では
   この領域で $\beta$ は逆に小さくなっていた。step 間分散に替えたので、
   いま見ているのは「報酬の推定が当てにならない座標で教師が重くなる」かどうかである。
4. **`sigma2_across_step` と `n_eff_steps`。** 0 のままなら全 step が warm-up で、
   読んでいるのは順列帰無、つまり §4.2 の欠陥のある量である。判定は無効。
5. **$\hat\lambda_j\le0$ のタスクの有無。** あれば §2.2 の判断（clamp か反転か）が必要になる。
6. **early と late で $\hat\lambda$ が大きく違うか。** 違えば静的較正はすべて無効。
7. **$a_i$ の時間相関。** EMA 窓はこれで決める。$d_j$ の 0.98 ではない。

観測 run は学習を変えないので control としても使える。

## 8. 限界

1. **id 座標は文脈を潰す。** 実際の共有は lm_head の行（2048 次元、入力埋め込みと tied）。
   同じ id を文脈 A で上げ B で下げる信号は和の中で消える。細分（id × 役割、id × 隠れクラスタ）で改善する。
2. **head 経路のみ。** trunk 経由の結合は捉えない。プローブの `root` unit（勾配エネルギーの **3.13%**）と
   全体の交差効果行列の一致は、**9 セルすべて符号一致**、相関は正規化のしかたで
   **生の内積 +0.551 / cosine +0.705 / $C_{ij}/R_i$ +0.785**、絶対値の比は
   生で 0.01–1.5 倍、$C/R$ で 0.14–22 倍。初版が挙げた 0.785 は 3 番目の定義。
   **向きは捉え、大きさは外す**と読む。
3. **等重み目的を仮定する**（§0）。
4. **教師の非冗長成分は $\hat\varsigma^2$ に入り一律減衰される**（§2.1）。これが本案の最大の限界。
5. **$\varepsilon$ と $\zeta$ の独立性は未検証**（§2.3）。
6. **$\sigma^2$ は H0 の分散**であって標本分散ではない（§4.2）。
7. **RL–RL の対立は解消しない。設計上そうする。**
8. **回帰の実効標本数が小さい**（§4.4、§7-2）。

## 9. 既存機構との関係

**§0 の通り、本案は問いを差し替えている。** 以下は「等重み目的を受け入れた場合に」成り立つ対応であって、
本案が既存機構の一般化であるという主張ではない。

| 機構 | 等重み目的の下での位置 |
|---|---|
| 単純和 $\sum a_i+\beta\sum d_j$ | $\sigma_i^2$ と $\hat\lambda^2/\hat\varsigma^2$ を定数に固定した場合。$\beta=0.01$ は $\lambda\sigma^2/\varsigma^2$ についての未測定の値。ただし RL 勾配（$\lvert A\rvert\sim1$）と OPD 勾配（$\pi(F-f)\lesssim10^{-2}$）の単位差も $\beta$ が吸収しているので、「教師は 100 倍精度が低いという主張」と言い切るのは行き過ぎ |
| 静的 redistribute | $\beta$ をタスク別にした。id 依存なし、step 300 の 1 点で較正 |
| pushback / cross gate | $\omega^D$ を符号で 2 値にした粗い近似。ただし**タスク間の負の転移**という別の問いを扱っていた |
| S-LP | 同上。タスク間に門を置く |
| PCGrad / MGDA | 争われた座標を凍結。Pareto 基準への目的変更 |
| CAGrad($c$) | 争われた座標を $(1-c)$ 倍。和の停留点に収束するので目的は保つ。§8-3 の選択肢 |
| Du et al. 2018 | 「補助損失に固有の価値は無い」前提。蒸留では半分しか成り立たない |

## 10. 単タスクでも成り立つ

推定量に交差タスク結合はゼロである（$\sigma_i^2$、$\hat\tau_i^2$、$\hat\lambda_i$、$\hat\varsigma_i^2$ すべて同一タスク内）。
タスク数を 1 にしても退化する項はない。**マルチタスクの場合は単タスク機構を 3 個並べて足しただけ**である。

含意は 2 つ。

* **事前実験は単タスクでやるべき。** 環境が 1 つで済み、「精度重み付けは定数 $\beta$ に勝つか」と
  「マルチタスクは効くか」を分離できる。単タスクで勝てないならマルチタスクで勝つ理由もない。
  単タスクの OPD+GRPO recipe は無いが、`env.multitask.tasks` と `data.task_balance.tasks` を
  1 タスクに絞る設定変更で足りるはず（3 タスク以上を要求する assert の無効化が要る）。
* **真にマルチタスクな拡張は 1 つだけ残っている。** 座標が共有されているので、
  タスク $i$ の観測が同じ座標での $\theta_j$ について情報を持ちうる。階層モデル
  $\theta_i[v]=\mu[v]+\delta_i[v]$ にすれば、観測の少ないタスク（search は押しの総量が他の 20 分の 1）が
  他タスクから強度を借りる。ただし $\delta_i$ の事前分散は「タスクはどれだけ似ているか」の宣言であり、
  測定ではなく選択である。完全分離（本案）を基準にしてから測る。
