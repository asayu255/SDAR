## 0. なぜこの機構か

### 0.1 機構は 150step で飽和する

signweight target（1.25/0.75、target mode、OPD+GRPO）の検証を control@150 / control@300 と
並べると、アームと control が**役割を入れ替えます**。

| | control | 重みづけアーム |
|---|---|---|
| alfworld | 0.651 → 0.738（**+8.7pp**） | 0.762 → 0.754（**−0.8pp**） |
| webshop Acc | 0.722 → 0.714（−0.8pp） | 0.667 → 0.746（**+7.9pp**） |
| webshop Score | 0.872 → 0.824（−4.8pp） | 0.783 → 0.849（+6.6pp） |

アームは alfworld を **@150 で 0.762 まで押し上げ、そこで止まります**。control は 150 以降に
+8.7pp 伸びて追いつきます。

### 0.2 飽和の理由は機構の適用先にある

草稿の観測がそのまま効いています。

> 同時OPDは150step時点で頭打ちになっており、300stepにおける上昇量はほぼGRPOによるものと考えられる

そして**今の機構は OPD 項にしか掛かっていません**（「重みづけを行うのはOPD項のみとし」）。

| 項 | 150まで | 150以降 | 機構 |
|---|---|---|---|
| OPD | 効く | 飽和 | **掛かっている** |
| GRPO | ほぼ効かない | 効く | **掛かっていない** |

@150 の利得は前半の OPD を増幅した結果であり、後半を取るには GRPO 側に同じことをする
必要がある、というのがこの設計の仮説です。

### 0.3 alfworld @150 の 2x2 交互作用（4セルすべて一次記録）

| alfworld @150 | 重みづけなし | 重みづけあり |
|---|---:|---:|
| pure OPD | 0.651 | 0.651（**+0.0pp**） |
| **OPD+GRPO** | **0.651** | **0.762（+11.1pp）** |

重みづけ単独もGRPO単独も +0.0、両方揃うと +11.1pp。**機構は既に GRPO との交互作用で
効いています。** PG 項へ直接届かせるのは、その交互作用を明示的な経路にする変更です。

### 0.4 目標

SDAR@300 の alfworld **0.849** に対し、現行アームは @300 で 0.754〜0.778。**7〜10pp 不足**。
飽和を止めて後半も伸ばせるかが、この差を埋める唯一の見込みのある経路です。

## 1. 機構

### 1.1 一つの証拠、二つの正規化器

```
証拠（既存、変更なし）:
    E_t = Σ_v p_s(v) · |c_t(v)|          c は corroboration チャネル、p_s は生徒の質量
共通の生重み:
    W~_t = 1 + E_t

OPD 側（既存）:  W^kl_t = W~_t / μ^kl_d ,  μ^kl_d = Σ W~·D·m / Σ D·m
PG  側（新規）:  W^pg_t = W~_t / μ^pg_d ,  μ^pg_d = Σ W~·|pg|·m / Σ |pg|·m

適用:
    teacher_kld_t *= W^kl_t              （既存）
    pg_loss_t     *= W^pg_t              （新規）
```

`μ` はどちらも **task 別・前 step・自分の重み量で加重した走行平均**です
（`PreviousStepTaskKLWeightedMean` と同じ構成）。前 step の値を使うのは、micro-batch 自身の
平均で割ると目的関数がバッチ分割に依存するためです。

構成上、次の二つが成立します。

```
Σ W^kl·D    = Σ D      → kl_scale = 1     （実測 1.0008）
Σ W^pg·|pg| = Σ |pg|   → pg_scale = 1     （新しい不変量）
```

**ハイパラはゼロ。** 分子は既存の証拠そのまま、分母は既存クラスの重み量を `D` から `|pg|` に
差し替えるだけです。強さの定数を持たないのは klw アームと同じ理屈で、機構は**総量を変えず
再配分だけ**します。

### 1.2 なぜ分母が `|pg|` で `pg` ではないか

`D ≥ 0` なので `Σ D` は素直なスケールですが、`pg_loss` は advantage の符号を持ち、GRPO は
群内で中心化するので `Σ pg ≈ 0` です。**ゼロ近傍で割ると不安定**になります。よって大きさの
総量を保存します。

その代償として、**符号付きの総量は変わりえます**。増幅が adv>0 側に偏れば正味の押しが
変わる。これは再配分の本質なので消せませんが、測る必要があります（§5 の `pg_shift_net`）。

### 1.3 証拠は位置レベルであり、抽出トークンではない

PG 項は形式上 `-A_t · log π(a_t)` で抽出トークンに作用しますが、**証拠は位置レベルを使います**。

理由は2つ。

**(a) 実測で抽出1トークンでは動かない。** §2 参照。

**(b) 動機づけが位置レベルの方が正しい。** GRPO のトークン別 advantage は軌跡の advantage を
ブロードキャストしたもので、`A_t` は位置に固有ではありません。効くのは「この位置で教師が
どれだけ一致しているか」であって、「出たトークンがどうか」ではない。

## 2. 前回案からの訂正

**「抽出トークン1個の証拠 `|c_t(a_t)|` を PG に使う」という案は破棄しました。**

sg1 の `sign_pair_events` から抽出トークン（`is_sampled=True`）だけを取り出すと:

| | 抽出トークン1個 | 位置レベル | 参考: KL 側実測 |
|---|---:|---:|---:|
| `W~` の CV | **0.038** | **0.506** | `w_cv` = 0.402 |

**CV が KL 側の 1/10** で、正規化しても平均が 1 になるだけでほとんど動きません。原因は明確で、
KL 側の証拠が 20候補の和 `Σ_v p(v)|c(v)|` なのに対し、抽出トークンは候補1個だからです。

位置レベルなら CV 0.506 で KL 側と同水準、抽出1トークンの **13倍**の広がりになります。

## 3. 事前確認（実測、sg1 spread 層 n=2,736 位置）

### 3.1 PG への再配分は冗長ではない

| | |
|---|---:|
| Spearman(W~, advantage) | **−0.057** |
| Spearman(W~, \|advantage\|) | +0.098 |
| adv>0 の W~ 平均 / adv≤0 の W~ 平均 | **0.988** |

証拠と advantage は独立です。既存の `kl_weight/outcome/corr_adv_gross_effect` も
pooled **0.046**（alfworld 0.060 / search 0.010 / webshop 0.020）で、**今の機構は advantage とは
無関係に動いています**。PG 項への配分は新しい情報を入れることになります。

**符号方向の構造的バイアスもありません**（比 0.988）。

> 抽出トークン1個で測ったときは adv>0/adv≤0 比が 0.333 と偏って見えましたが n=69 でした。
> 位置レベル n=2,736 では消えます。小標本の見かけです。

### 3.2 介入の広がりは十分

| 位置レベル `W~` | |
|---|---:|
| 平均 | 1.169 |
| 中央 | 1.001 |
| p75 | 1.104 |
| p90 | 1.458 |
| p99 | 3.011 |
| **CV** | **0.506** |
| 証拠ゼロの位置 | 24.5% |

task 別 CV: alfworld 0.314 / search 0.709 / webshop 0.371。**search が最も広く動きます。**

## 4. アーム構成

証拠を共有し正規化器を分けたので、チャネルを独立に切れます。

| アーム | `W^kl` | `W^pg` | 何を答えるか |
|---|:--:|:--:|---|
| 1. `kl`（= 現行 klw） | ✓ | — | 既存。150step で飽和 |
| 2. **`pg` 単独** | — | ✓ | **飽和しない側だけを見る。仮説の直接検定** |
| 3. `both` | ✓ | ✓ | 実運用形 |

**アーム2が本命の実験です。** §0.2 の仮説は「PG 単独で 150 以降も伸びるか」で決まります。
アーム3では OPD 側の飽和と混ざって読めません。

## 5. 計測

KL 側と同じ形で `pg_weight/*` を出します。

| 指標 | 定義 | 役割 |
|---|---|---|
| `pg_weight/effect/pg_scale` | `Σ W·\|pg\| / Σ \|pg\|` | **= 1 が構成上の不変量。崩れたら配線バグ** |
| `pg_weight/effect/pg_shift_gross_frac` | `Σ \|W−1\|·\|pg\| / Σ \|pg\|` | 介入量。KL 側の 0.309 と直接比較できる |
| `pg_weight/effect/pg_shift_net` | `Σ (W−1)·pg / Σ \|pg\|` | **方向の偏り。0 から離れたら「良い方だけ増幅」している** |
| `pg_weight/position/w_mean`, `w_cv` | 既存と同形 | 予測 CV ≈ 0.5 |
| `pg_weight/outcome/adv_{positive,negative}/gross_effect` | 既存 outcome バケットの PG 版 | 符号別の効き |

## 6. 事前登録

### 6.1 配線の検証（結果ではない。最初の数 step で読む）

| 指標 | 期待値 | 崩れたときの意味 |
|---|---|---|
| `pg_scale` | 1（±1e-3） | 配線バグ。結果は無効 |
| `pg_shift_gross_frac` | 0.25〜0.35 | 証拠が共通なので KL 側 0.309 と同水準のはず |
| `pg_shift_net` | \|値\| < 0.02 | 方向バイアスあり。要報告 |
| `pg_weight/position/w_cv` | 0.4〜0.6 | §3.2 の実測 0.506 |

### 6.2 結果の予測

| 指標 | 予測 | 外れたら |
|---|---|---|
| **alfworld @300** | **control 比で伸び続ける（@150 で頭打ちにならない）** | **仮説死亡** |
| alfworld @150 | 現行 klw（+6.3pp）と同程度かそれ以下 | PG は前半には効かないはず |
| `valid_action_ratio` | 悪化しない | §7.2 の罰則再配分が効いている |

**判定は @300 です。** @150 で差が出ないことはむしろ予測どおりで、PG チャネルの主張は
「後半を取る」ことにあります。

### 6.3 検出可能な最小効果

同一 checkpoint を2回検証して測った、評価そのものの揺れ（[cross_teacher_role_mask_arms.md]
§5 と同じ測定）:

| task | n | run 間 SD |
|---|---:|---:|
| alfworld | 126 | **2.11pp** |
| webshop Score | 126 | 2.28pp |
| webshop Acc | 126 | 0.71pp |
| search | 51,713 | 0.09pp |

**alfworld で 1本の run が検出できる最小効果は約 6pp（2σ）です。** @300 の control 比が
数 pp 台に留まる場合、検証を 3 回走らせて平均±SD で報告する必要があります。

## 7. リスク

**1. 勾配分散。** 正規化はスケールを保ちますが分散は保ちません。GRPO の advantage は群内
中心化済みで元々ノイズが大きく、再配分で `actor/grad_norm` が上がる可能性があります。
既存指標で監視できます。

**2. invalid-action penalty との相互作用。** `use_invalid_action_penalty=True`
（係数 alfworld 0.1 / search 0.01 / webshop 0.1）は報酬経由で advantage に入るので、PG を
再配分すると**罰則も再配分されます**。教師が一致する位置で罰則が増幅される形になり、
`valid_action_ratio` に効く可能性があります。§6.2 の監視項目に入れてあります。

**3. 冷間開始。** `μ^pg` は前 step が必要なので step 1 は `W=1`。KL 側と同じ挙動です。

| 箇所 | 変更 |

## 9. 未解決のまま残す点

- **`E_t` は corroboration チャネルのみを使う想定だが、現行 klw の `W~` は source チャネルも
  含む。** §3 の測定は現行 `pre_weight`（両チャネル込み）で行った。corroboration のみに
  絞った場合の CV は未測定。実装前に確認すること。
- **飽和の因果は未確認。** 「OPD が飽和するから機構も飽和する」は観測と整合するが、
  OPD 信号自体の飽和（`actor/teacher_kl_loss` の推移）を per-task で確認していない。
- **PG を再配分して「後半が伸びる」保証はない。** GRPO の後半の伸びが機構と直交する要因
  （探索の進行、環境の学習曲線）由来なら、再配分しても何も起きない。アーム2はその可能性も
  含めて検定する。
- **SDAR の 0.849 に届くかは別問題。** 仮に飽和が止まって @300 で 0.762 を維持できても、
  SDAR には 8.7pp 足りない。この設計は「飽和を止める」ところまでで、差を埋めきる根拠は
  まだない。
