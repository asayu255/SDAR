## 0. 要旨

**機構は設計通り動いているが、載せている信号がほぼ存在しない。** 3つの独立な測定が同じ結論を指す。

1. **介入の実効は「アンラーニング裾」に集中している。** 効果の 69–88% が「生徒が確信し($p_s>0.5$)、自タスク教師がほぼゼロを与える($p_{on}<10^{-3}$)」候補に載る。位置あたりの重みは最大 18.8 倍で、上限が無い。
2. **教師間の一致は、偶然をほとんど超えない。** 周辺分布の偏りを補正した符号一致の $\phi = +0.066$(共有分散 0.4%)。水準での一致は生の Spearman が 0.82 だが、`p_base` を統制すると **−0.003 〜 +0.043** に落ちる。すなわち **off-task 教師が on-task 教師の目標について base を超えて持つ情報は実質ゼロ**。
3. **どの一致測度も advantage を予測しない。** 0 を跨がない CI は1つだけで、それは負。
4. **action 粒度に上げても回復しない。** ターン単位に集約しても off-task 側は $\approx 0$ のまま。唯一粒度で改善するのは *on-task 教師自身* の項($0.03 \to 0.11$)。

**これは「$\delta = \log p_{teacher} - \log p_{base}$ という量に意味がない」ではない。** §4.4 で両者を同一標本に載せて対決させると、$\delta_{on}$ は複数の検定で 0 を跨がず($P(\delta_{on}>0)$ の良否差 +0.069 / +0.055、`L_base` 統制後の span 相関 +0.128)、$\delta_{src}$ は `L_base` を統制したどの形でも null。**本監査が棄却したのは「教師Aの shift が、タスクBについて何か言う」という cross-task の主張だけであり、自タスクの shift の有用性はむしろ支持されている。** この区別は §4.4 と §6 で明示する。

**判断への含意:** 「Z=1 で増減を釣り合わせ、倍率を導出し、deadzone を撤廃する」再設計は機構としては正しい修正だが、**乗せる信号が無いため 150 step を投じても control と区別できない可能性が高い**。§7 に判定、§10 に次に測るべきものを置く。

なお §1–§3 は走行中アームの内部測定のみに依存し、control との環境差(§0.3)に影響されない。control 比較に依存するのは成功率の差だけである。

## 1. 現行機構の問題

### 1.1 構造的にできないこと

**(P1) 位置スカラー重みでは off-task の知識を注入できない。** 適用は `dp_actor.py:3688` の `teacher_kld *= W` 一行のみで、`W` は detach された正のスカラー。$W\cdot \mathrm{KL}(p_s\Vert p_{on})$ の最小解は $W$ に依らず $p_s=p_{on}$ で、**収束先は常に自タスク教師**。off-task 教師が決められるのは労力配分だけ。目標を動かす経路(target mode)は `sign_weights.py:593–627` に `inv_z`/`target_kl` として存在するが、cross-teacher アームは position mode のみで作られている。

**(P2) 候補ごとの証拠が位置スカラーに畳まれる。** `W~ = 1 + Σ_v p_student(v)·e(v)`(`CT:1112`)で候補 $v$ ごとの $e(v)$ が1つの数に潰れてから位置全体の KL に掛かる。同じ位置で候補Aが一致・候補Bが不一致でも同じ倍率。「一致した候補を強める」は表現できない。

**(P3) KL加重 mean-1 正規化がゼロサムを強制する。** $\mu$ は前 step の KL 加重平均で $\Sigma W D/\Sigma D \approx 1$(実測 1.0006)。よって絶対量として「強く蒸留」はできない。実測で `norm_offset` が gross shift の **50.0%**(3タスクとも ±0.001 で一致)、素の `w_mean` は 0.76 — **普通の位置全部から一律24%を徴収**して裾の増幅を賄っている。

### 1.2 測っている量が意図と違う

**(P4) 「一致」が出力分布の一致ではなく base からの移動方向の一致。** `candidate_kl_evidence`(`CT:916`)の入力は shift のみで、$p_{on}$ と $p_{off}$ を水準で比較する項が存在しない。実測で `agree_pos` の $p_{on}$ 中央値は $6\times10^{-7}$ — 「3教師が揃って上げた」の実体は「$10^{-9}$ から $10^{-7}$ へ上げた」。

**(P5) 「自信がない」を測る項が存在しない。** `|hat_on|` が小さいのは「教師が base と同意」であって「教師が自信を持てない」ではない。実測で `neutral_on_task_silent` の $p_{on}$ 中央値は **0.935**、59% が $p_{on}>0.5$ — **教師が最も確信している位置**であり、そこで $W=1.00$(完全に不作為)。

**(P6) 一致と不一致を実質区別できていない。** pair_state 別の選択性(= `kl_shift_gross_share` ÷ `candidate_frac`、1.0 が無差別、steps 61–88):

| pair | agree | conflict | on_silent_source_active | source_silent |
|---|---:|---:|---:|---:|
| alfworld ← search | 0.97 | 0.94 | 2.91 | 0.04 |
| alfworld ← webshop | **0.60** | **1.64** | 7.81 | 0.05 |
| search ← alfworld | 1.34 | 0.75 | 7.56 | 0.01 |
| search ← webshop | 1.20 | 0.85 | 8.06 | 0.03 |
| webshop ← alfworld | **0.87** | **1.30** | 3.61 | 0.02 |
| webshop ← search | 1.68 | 0.66 | 1.86 | 0.03 |

agree は 0.60–1.68 でほぼ無差別、2ペアでは **conflict の方が高い**。唯一はっきり選択されているのは `on_silent_source_active`(1.86–8.06)。

**(P7) q ゲートが誤った量を測る。** `q = teacher_similarity(hat_off)`(`CT:735–743`)は off-task 2本の相互類似度で、on-task を読まない。実測 `gate/shuffled_to_live_gate_ratio ≈ 0.82` — 位置対応を破壊した偽教師でもゲートは実物の8割の率で開く。さらに `q_sim` の四分位ごとの実際の on-source 符号一致率は 0.413 / 0.475 / 0.413 / 0.441 と**フラット**で、ゲートは一致を予測していない。本来この役を担う `alpha_diagnostic` は step 87 まで全6ペアで 0 近傍。

**(P8) 周辺分布の偏りが未補正。** $P(\text{shift}>0)$ は教師/宛先で **0.240 〜 0.889** と大きく違う。中心化しない符号一致は主として「両教師とも下げがち」という周辺傾向を測る(§4.1)。

### 1.3 増幅の暴走

**(P9) 測度が student mass。** `Σ_v p_student(v)·e(v)`(0b4b630 で teacher mass から変更)。効果の 69–88% がアンラーニング位置に載る直接の原因。意図1なら $p_{on}$、意図2なら $p_{off}$ が測度であるべき。

**(P10) `|c|` が方向を捨てる。** `e = |c| + ...`(`CT:965`)。実測: 報酬 9.9 の**成功**エピソード内、reasoning の `'color'`($p_s=1.00$、$p_{on}=1.4\times10^{-2}$)に3教師が揃って下げ(`agree_neg`)→ **W=11.2**。GRPO が強化した行動を OPD 項が11倍で消しにいく。

**(P11) W に上限が無く、KL 最大の位置に乗る。** 実測 W 最大 18.8。`weight_kl_lift`(KL加重平均W ÷ 素平均W)が 1.21 → **1.31** と単調増加。$W$ と $D$ が同じ場所で最大化する正のフィードバック。

### 1.4 ゲートの緩み・診断

**(P12) M=2 で半数票が通る。** 0b4b630 で全会一致要件を外した結果 $c=(\text{capped}_{\text{agree}}+0)/2$。作用分(norm_offset を除く 0.501)の内訳は agree 48.7% / **`neutral_off_task_split` 29.1%** / conflict 12.6% / `neutral_on_task_silent` 4.2%。**off-task 同士が矛盾している位置が3割**を取っている。

**(P13) deadzone がラベル専用。** `report_epsilon=0.1` は state ラベルと pair-state にのみ使われ(`CT:2946–2954`、返る weight は破棄)、重みパスに入らない。ダンプ/メトリクスが語る agree/conflict/silent の物語と、実際の重みの挙動が一致しない。

**(P14) メトリクス prefix の不整合。** `dp_actor.py:4017, 4034` の `scalar_metrics()` が prefix 未指定で、`sign_weights.py:1008, 2407` の既定 `"sign_weight"` で描画される。同テーブルの turnover 側(`:4022, :4038`)は `"kl_weight"` を渡しており、run script の用語集(`run_multitask_cross_teacher_klw_qwen3.sh:450, 457`)も `kl_weight/*/token/*`。走行中の `n9zfny6m` は既に `sign_weight/*` で記録済みなので、修正時は旧 run 参照の扱いに注意。

## 3. deadzone スイープ

$\epsilon$ は shift(RMS単位)に掛かる。到達質量は教師確率質量の割合、偶然期待は 3教師一致の $1/4$。

**ARM**(1 RMS ≈ 2.076 nats):

| ε(RMS) | ε(nats) | 一致質量 | up | down | 偶然 | 超過 | 純度 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1.0 | 2.08 | 0.010 | 0.010 | 0.000 | 0.009 | 0.001 | 0.12 |
| 0.3 | 0.62 | 0.031 | 0.028 | 0.003 | 0.025 | 0.006 | 0.20 |
| **0.1**(旧アーム相当) | **0.21** | **0.051** | 0.044 | 0.007 | 0.043 | 0.009 | **0.16** |
| **0.03** | **0.062** | **0.106** | 0.059 | 0.047 | 0.069 | **0.037** | **0.35** |
| 0.01 | 0.021 | 0.117 | 0.062 | 0.055 | 0.080 | 0.037 | 0.31 |
| 0 | 0 | 0.215 | 0.084 | 0.131 | 0.155 | 0.060 | 0.28 |

**ARM2(xt1)**(1 RMS ≈ 2.193 nats): ε=0.1 → 質量 0.054 / 超過 0.013 / 純度 0.24。ε=0.03 → 0.075 / 0.014 / 0.19。ε=0 → 0.175 / 0.032 / 0.18。

**読み:**

1. **deadzone を小さくすれば到達質量は増える** — ε=0.1 の 5.1% から ε→0 の 21.5% まで約4倍。偶然超過も 0.9% → 6.0% と増える。
2. **ε=0.1 は大きすぎる。** 試した小さい値の中で純度が最悪(0.16、82%が偶然で説明できる)。純度の最適は **ε ≈ 0.03 RMS(≈0.06 nats)**。
3. **up/down の釣り合いが ε で激変する。** ε=0.1 では up:down = 6:1 で down 側の予算がほとんど無く、旧 target アームが頭から46%を徴収せざるを得なかった理由がこれ。**ε=0.03 で 0.059 対 0.047 とほぼ 1:1** になり、質量保存(Z=1)設計が自然に成立する。
4. **しかし頭は ε をいくら下げても届かない。** `|shift_on| < 0.01 RMS` に質量の **54.9%(ARM)/ 59.4%(CTL)** があり、その正体は $p_{on}$ 中央 **0.9999**、$p_{base}$ 中央 **1.0000**、**3教師のうち最弱の shift が数値的に厳密ゼロが 64.8%**。読むべき符号が存在しない。天井は $\epsilon$ の副作用ではなく、教師が頭を動かさなかったという事実。

control で $p_{base}$ と $p_{src}$ が有意に負 — **base 的・汎用的なトークンほどやや悪い軌跡に現れる**。現行機構が増幅しているのは base 相続の合意なので(§4.1)、これは §2.3 の webshop 悪化と機構的に整合する。**この負の関連は交絡でもある**: $\delta_{on}$ と $\delta_{src}$ は $-\log p_{base}$ の項を共有するので、$\log p_{base}$ が outcome と相関すると **両方の $\delta$ が見かけの関連を相続する**。§4.4 の partial 形だけがこれを分離する。

### 4.4 delta それ自体に価値はあるのか(cross-task の null との切り分け)

§4.1–4.3 と §4.5 の null はすべて **cross-task** の主張に対するもので、$\delta$ という量への null ではない。同一標本に $\delta_{on} = \log p_{on} - \log p_{base}$ と $\delta_{src} = \log p_{src} - \log p_{base}$ を並べ、差にもブートストラップCIを付けた。

| 検定 | ARM(sg1) | ARM2(xt1) |
|---|---|---|
| **トークン水準**(sampled, adv≠0) | n=2,529 | n=2,686 |
| Spearman($\delta_{on}$, adv) | +0.027 [−0.035, +0.088] | +0.047 [−0.002, +0.092] |
| Spearman($\delta_{src}$, adv) | +0.001 [−0.058, +0.064] | **+0.055 [+0.008, +0.106]** |
| 差(対応あり) | +0.026 [−0.038, +0.095] | −0.008 [−0.070, +0.056] |
| **$P(\delta_{on}>0\mid adv>0) - P(\cdot\mid adv<0)$** | **+0.069 [+0.003, +0.131]** | **+0.054 [+0.008, +0.100]** |
| $P(\delta_{src}>0\mid adv>0) - P(\cdot\mid adv<0)$ | −0.006 [−0.068, +0.061] | +0.034 [−0.021, +0.085] |
| **span 水準**(≥2 sampled tokens) | units=397 | units=182 |
| Spearman($\Delta_{on}$, adv) | +0.114 [−0.002, +0.225] | +0.069 [−0.083, +0.220] |
| Spearman($\Delta_{src}$, adv) | +0.005 [−0.130, +0.132] | −0.013 [−0.172, +0.144] |
| 差(対応あり) | +0.109 [−0.052, +0.265] | +0.081 [−0.070, +0.229] |
| **partial Sp($\Delta_{on}$, adv \| $L_{base}$)** | **+0.128 [+0.016, +0.235]** | +0.082 [−0.082, +0.241] |
| partial Sp($\Delta_{src}$, adv \| $L_{base}$) | +0.026 [−0.089, +0.147] | −0.014 [−0.167, +0.143] |

**読み:**

1. **$\delta_{on}$ は情報を持つ。** 2つの独立な run で、$P(\delta_{on}>0)$ の良否差が +0.069 / +0.054 とどちらも 0 を跨がず、ARM の `L_base` 統制後 span 相関が +0.128 で 0 を跨がない。効果量は小さい(0.05–0.13)が、符号は一貫して正で、複数の形で再現する。
2. **$\delta_{src}$ は `L_base` を統制したどの形でも null。** control のトークン水準 +0.055 が唯一 0 を跨がないが、これは §4.3 で述べた **共有 $-\log p_{base}$ 項による交絡**で説明できる(同じ標本で $p_{base}$ 自身が −0.060、`L_base` 統制後は −0.014 に消える)。
3. **ただし対応ありの差は 0 を跨ぐ**(+0.026 / +0.109 / +0.081 / −0.008)。よって「$\delta_{on}$ が $\delta_{src}$ より**有意に**良い」とは言えない。言えるのは「$\delta_{on}$ は base 統制下で繰り返し 0 を離れ、$\delta_{src}$ は一度も離れない」まで。
4. **含意。** teacher−base の対数確率差を使う手法(contrastive decoding、DExperts、proxy-tuning、logit/task arithmetic 等)は、いずれも**対象タスクと同じ分布・同じ属性で調整されたモデルの $\delta$** を使う。本監査が棄却したのは、それより強い「別タスクで調整されたモデルの $\delta$ を、そのタスクの状態上で、そのタスクについての証拠として読む」という主張である。両者は矛盾しない。

### 4.6 共有フォーマット成分:水準と shift で符号が逆(唯一の正の cross-teacher 信号)

§4.3 の「$p_{base}$ / $p_{src}$ が outcome と負」は**水準**についての観測である。**shift** にすると符号が逆になる。この2つは別の量で、混同してはならない:

* $\log p_{base}$ が高い = そのトークンは汎用的で予測しやすい → outcome とやや**負**(−0.060)
* $s_{gen} = \text{mean}_m(\log p_m - \log p_{base}) > 0$($m$ = off-task 教師) = **RL 済みモデル群がそのトークンを base より押し上げた** → outcome とやや**正**

off-task 教師はタスク $d$ について何も知らないので、$d$ の状態上での彼らの shift は「タスク非依存に RL が向かう方向」の推定量になる。候補単位(off-task 2本が揃う sampled 候補、adv≠0)で:

| 量 | ARM(sg1) n=515 | ARM2(xt1) n=602 |
|---|---|---|
| Spearman($s_{gen}$, adv) | −0.044 [−0.130, +0.043] | **+0.102 [+0.016, +0.188]** |
| **partial Sp($s_{gen}$, adv \| $\log p_{base}$)** | +0.025 [−0.046, +0.097] | **+0.092 [+0.003, +0.177]** |
| partial Sp($\delta_{on}$, adv \| $\log p_{base}$) | +0.026 [−0.053, +0.100] | −0.030 [−0.117, +0.063] |
| partial Sp(mean $\log p_{src}$, adv \| $\log p_{base}$) | +0.020 [−0.054, +0.097] | **+0.075 [+0.001, +0.156]** |

**これは本監査で唯一の、正で・base 統制後も残る cross-teacher 信号である。** 単一 source 版(n=2,686)の `Spearman(delta_src, adv) = +0.055 [+0.008, +0.106]` と整合し、2本平均で +0.055 → +0.102 と上がるのは実信号に対する平均化のふるまいと一致する。

**ただし外挿検定は通っていない(control、`partial Sp | log p_base`):**

| 分割 | 値 | n |
|---|---|---:|
| 全体 | +0.092 [+0.003, +0.177] | 602 |
| steps ≤150 / >150 | +0.067 [−0.051, +0.181] / +0.099 [−0.035, +0.224] | 329 / 273 |
| **alfworld** | **+0.152 [+0.017, +0.271]** | 257 |
| webshop | +0.118 [−0.030, +0.273] | 226 |
| **search** | **−0.103 [−0.305, +0.131]** | 119 |
| 3教師すべての平均 shift 版 | **−0.004 [−0.097, +0.087]** | 602 |

* どちらの時期半分も単独では 0 を跨ぐ(点推定は4分割すべて正: +0.072 / +0.038 / +0.059 / +0.110)
* alfworld に集中し、**search では符号が負**
* **on-task 教師を混ぜた3教師平均にすると信号が消える** — 「族の共通方向」という解釈にとって不都合
* ARM では null(機構が既に飽和させた可能性と、単なるノイズを区別できない)
* 本監査は 100 超の検定を行っており、5% で期待される偽陽性は約5件

**なぜ off-task 平均で正が出るのか(機構).** 最も整合する説明は「**共有方向の、雑音の少ない測定量**」である。

* $\mathrm{corr}(s_{gen}, \delta_{on}) = +0.643$、$\mathrm{sd}(\delta_{on})/\mathrm{sd}(s_{gen}) = 11.76/5.04 = 2.33$。つまり $\delta_{on} \approx$ (共有方向) + (それより2倍大きいタスク固有成分)。
* そのタスク固有成分は、トークン水準では行 advantage を予測しない($\delta_{on}$ の partial は −0.030)。
* off-task 教師は宛先タスクを知らないので、その平均は**タスク固有成分を含まずに共有方向を測る**。
* 共有方向が弱く advantage を予測する(+0.09)。source 1本では +0.055、2本平均で +0.102 と上がるのは平均化による雑音低減と一致。
* $w=0.25$ で on-task を混ぜると信号が崩れる(+0.006)のは希釈ではなく**分散支配**: その重みで既に on-task 由来の sd が off 平均由来と同等(0.78倍)になり、$w=0.5$ で 2.33 倍になる。

**「文体劣化検出器」という解釈は反証された。** $s_{gen}$ と `row_len` は無相関(−0.064 [−0.155, +0.033])で、しかも信号は**短い応答の方が強い**(row_len ≤ 中央値で +0.125 [+0.013, +0.233]、超で +0.076 [−0.048, +0.195])。劣化検出器なら長い応答で強く出るはずで、逆である。共有方向が具体的に何なのか(ハーネス書式の順守・ツール構文・指示追従・行動への commit)は**このデータでは区別できない**。標本の 87% が `format` ロールなので書式説が自然だが、未検証。

**判定: 手掛かり(lead)であって知見(finding)ではない。** ただし失敗した機構とは構造が違う点は重要である — **一致ではなく平均**、**重みではなく方向**、**position mode ではなく target mode**。したがって deadzone・全会一致・q ゲート・符号検定のすべてが不要になり、P4 / P6 / P7 / P8 / P12 / P13 が一挙に消える。

**共有成分の「除去」は反証済み。** off-task の shift を汎用方向として差し引く案($\log p_{on} - \text{mean}_m \log p_m$、base が厳密に消える contrastive 形)を同一標本で検定したが、改善しない: 差(除去後 − 従来)は ARM(sg1) −0.042 [−0.147, +0.059]、ARM2(xt1) −0.035 [−0.069, +0.000]。**符号は「悪化」の側**であり、除去ではなく利用の方向でしか筋が通らない。

1. **action 粒度に上げても off-task 側は回復しない。** span 単位の partial Sp($L_{on}$,$L_{src}$\|$L_{base}$) は −0.23 〜 0.00、$L_{src}-L_{base}$ vs adv は −0.01 〜 +0.20 で符号が不安定、全て CI が 0 を跨ぐ。
2. **粒度で改善するのは on-task 教師自身だけ。** $L_{on}-L_{base}$ vs adv がトークン水準 0.027 → span 水準 **+0.114**(ARM min2、CI が 0 を跨がない)。**もし利用できるものがあるなら、それは教師間の一致ではなく「自タスク教師の action 水準の評価」**。
3. **一致が有意になった箇所はすべて符号が負。** ARM の env_action で −0.313(トークン)/ −0.264(span)。ただし ARM は機構が一致を増幅した側の run なので、これは「教師について分かったこと」ではなく「増幅の結果」の可能性がある(control では同符号だが CI が 0 を跨ぐ)。
4. **多重比較の注意。** 本節と §4 で約 78 の検定を行い、5% で期待される偽陽性は約4。実際に CI が 0 を跨がなかったのは5件。**個々の有意は偽陽性と区別できない。頑健なのは「どの粒度・どの測度でも正の関連が一つも無い」という全体像である。**
5. `MIN=5` は ARM 5 / CTL 3 units しか作れない。ダンプは step あたり 128 件のサンプルなので、**厳密な span 水準検定には専用の測定パスが必要**(GPU が必要で、走行中は不可)。

## 6. 設計意図に対する含意

記録されている設計意図は2つ。

> **意図1** 教師一致時は強く蒸留するべき
> **意図2** on-task 教師が自信の無い場合は、off-task 教師の信号を使うべき

| 意図 | 現行機構が表現できるか | 測定が支持するか |
|---|---|---|
| 意図1 | **できない**。P2(候補証拠が位置スカラーに畳まれる)、P3(ゼロサム)、P10(方向を捨てる)。実測でも一致と不一致の選択性がほぼ同じ(P6) | **支持しない**。$\phi=+0.066$、partial 0.00〜0.04、novelty 絞りで質量 0.03〜0.34%、advantage 予測 ≤ 0 |
| 意図2 | **原理的にできない**。P1(位置スカラー正のスカラーは収束先を動かせない)。加えて P5(「自信」を測る項が無い、`silent` の実体は $p_{on}=0.935$) | **支持しない**。§4.4 で CI が 0 を跨ぎ2アームで符号が逆 |

**この表は cross-task の主張に限った判定である。** $\delta = \log p_{teacher} - \log p_{base}$ という量自体は、自タスクについては §4.4 の通り情報を持つ(base 統制後 +0.128)。棄却されたのは「別タスクで調整された教師の $\delta$ を、そのタスクの状態上で、そのタスクについての証拠として読む」という一段強い主張のみで、teacher−base 差分を使う手法一般ではない。

意図1は候補単位の**目標整形**、意図2は**目標の混合**($\tilde p = \lambda(x) p_{on} + (1-\lambda) \sum_m \beta_m p_{off,m}$、$\lambda$ は on-task の確信度、$\beta_m$ はそのタスクでの信頼性)であり、どちらも target mode を要求する。配管は `sign_weights.py` に存在する。

## 7. 提案されていた再設計と、それに対する判定

検討された案(§3 の測定を受けて設計):

* 一致・不一致の**増減を釣り合わせる**(Z=1 を構成上成立させ、頭に課税しない)
* **倍率は固定しない**(予算から導出)
* **deadzone を撤廃**(`min_m|δ_m|` の自己減衰に任せる)

具体形(位置ごと、支持集合は教師 top-k、$p = p_{on}$):

```
a(v) = sign · min_m |δ_m(v)|      # 全教師の符号一致時のみ、他は 0。振幅は教師が決める
D = {a<0}:  w_v = e^{a(v)} < 1
B = Σ_{v∈D} (1 − e^{a(v)})·p(v)                       # 解放予算
U = {a>0}:  w_v = 1 + B·g(v)/Σ_{u∈U} g(u)p(u),  g = e^{a}−1
その他:      w_v = 1                                    # 頭は不動
U か D が空 → w ≡ 1 (no-op)
```

$\Sigma_v w_v p(v) = 1$ が構成上厳密に成立し、再正規化なし・税ゼロ・自由定数ゼロ。副産物として `PreviousStepTaskKLWeightedMean`($\mu$)・cold start・1step ラグ・sidecar が不要になり、`kl_scale` は事後測定ではなく恒等式になる。規模の見積もり: ε=0 相当の到達(質量 21.5%、down 13.1%)で median $a$ = 0.36 RMS ≈ 0.75 nats なら $w\approx0.70$、$B\approx0.039$、$w_+\approx1.5$、**TV ≈ 3.9%** — 旧 teachertopk アームの実測 1.42% の約3倍を、頭への課税ゼロで得る。

**判定: 機構としては正しい修正だが、現時点では走らせるべきでない。** P2/P3/P9/P10/P12 を同時に潰す良い設計であり、旧アームの「46%の税」も消える。しかし §4–§5 が示すのは、この骨格が乗る量($a(v)$ が読む符号一致)が $\phi=0.066$ しか持たず、粒度を上げても回復せず、advantage との関連は 0 か負だということ。**deadzone・倍率・釣り合いのどれを直しても、それらは全て $(p_{on}, p_{off}, p_{base})$ の関数であり、その三つ組が「何が良いか」について持つ情報が上限 0.05 だという事実は変わらない。**

参考: 旧 `signweight target` アーム(`docs/multitask_signweight_pure_opd.md:59` の重み表 = 1.25/0.75 と teachertopk の 1.5/0.5)は「符号が揃えば増幅・揃って負なら減衰・他は 1.0」という同じ三値ルールで、150step × 2水準を走らせている。**倍率を2倍にしても episode 指標は区別できなかった**(全体成功率 0.533 対 0.534、last-50 全タスク ±0.01)、かつ**全7状態の frac/mass_frac が ±0.006 以内で不変**。ただし**どちらも control と比較されていない**ので、「否定された」ではなく「未検証」である。

### 11.6 なぜ cross-teacher の前提が成り立たなかったのか — より深い説明

§11.2–11.4 は §4 の null に、教師集合の非関連性より深い説明を与える。

**晩期の on-task 教師の残る教えは、ほぼ書式である。** alfworld で最も強く押されているのは `<`, `</`, `>`, `I`(タグ構文と一人称)、最も強く抑えられているのは `**`, `<th`, `Okay`(markdown・HTML・雑談)。webshop の最大項は `'<th'` 単独で 23.2%。内容語は予算の 24%。

そして**書式は教師間で真に共有されている**成分である(§4.1 の shuffled 比 0.82)。したがって:

* 教師たちが一致できるのは書式についてであり、それは3本とも同じハーネスで RL されたので当然である。
* 教師たちが一致できないのはタスク知識についてだが、**そもそも晩期の蒸留信号にタスク知識がほとんど残っていない**。
* 機構は「一致 = タスク知識の裏付け」と読む設計だったが、実際に一致しているのは書式であり、その書式は on-task 教師が単独で既に教えている。

つまり cross-teacher 裏付けが上乗せできる余地は、設計上ほぼ存在しなかった。§6 の判定(「教師集合の問題か機構の問題か切り分けられない」)は、ここで一段狭まる: **少なくとも晩期においては、上乗せする対象そのものが無い。** 早期(step ≤ 50、談話標識と内容語がまだ予算の多くを占める区間)なら話が違う可能性は残るが、未検証である。

### 11.7 この節の限界

1. **top-64 打ち切り。** シェアはすべて top-64 内の相対値。全体に対する割合を出すには `top64_share` が必要で、**control はこれを `opd/*` prefix で出している**(`opd/<scope>/push/kl_mass_abs_top64_share`、90 キー)。当初「control はトークン系メトリクスを出していない」と書いたのは `sign_weight/*` / `kl_weight/*` に限った話で、誤りだった。§13.5 はこのアンカーを使っている。
2. **分類は手作業。** 「内容語」は残余カテゴリで、`'Ġselect'` のような機能語寄りの動詞も含む。境界は再現可能だが恣意的。
3. **`sign_events` / `sign_pair_events` が無い。** よって本物の control では候補水準・イベント水準の検定(§4・§5)が**まだできていない**。§4.6 の +0.092 を本物の control で検証するには、これらのダンプが必要。
4. ARM との比較(§11.5)は step 61–111 に限る。ARM はまだ 150 step に到達していない。

## 12. 機構は文章を改善したのか

**結論: 示せない。** そして示せない理由と、代わりに示せることを分けて記録する。

### 12.1 反実仮想テキストが存在しない

`trainer.val_instance_log_dir` の jsonl に入っているのは
`data_source / experiment / score / step / task / tool_calling / traj_uid / val_index` で、**生成文は保存されていない**。
イベントダンプの `context` は当該位置の前後 16 トークンの窓にすぎない。
したがって「同じプロンプトを機構あり/なしで生成させて比べる」ことは、現在の記録からは原理的にできない。

### 12.2 機構が文章に加えた押しは最大 0.27 logit

生徒が**実際に出したトークン**(`is_sampled=1`)に絞り、位置で重複排除(3,960 → 2,409 件)すると:

| 量 | 中央 | p90 | 最大 |
|---|---:|---:|---:|
| `\|extra_logit_push\|` | 0.011 | 0.064 | **0.267** |
| `applied_weight` | 2.443 | 5.121 | 15.64 |

比較対象として、control の素の OPD の `base_logit_push` は alfworld で **±12 logit** に達する(§11.2)。
つまり **機構が出力トークンに加えた押しは、素の OPD の押しの 2% 程度が上限、中央値では 0.1% 程度**である。
$W$ が大きい(中央 2.44)のに logit 変化が小さいのは、$W$ が乗る per-token 押しがその位置で既に小さいため。

### 12.3 作用の半分は「教師が base と同じことを言っている」位置に載る

| 条件 | 位置の割合 | `\|extra\|` 質量 |
|---|---:|---:|
| $\|\log p_{on} - \log p_{base}\| < 0.1$ | 0.429 | 0.245 |
| 同 < 0.5 | 0.572 | 0.365 |
| 同 < 2.0 | 0.729 | 0.534 |
| $p_{on} > 0.99$ かつ $p_{base} > 0.99$ | 0.190 | 0.143 |

情報を運びうる位置($\|\log p_{on}-\log p_{base}\| > 2$)は位置の 27.1%、質量の 46.6% にとどまる。

### 12.4 報酬で区別していない

`\|extra\|` 加重の作用の向き:

| 行 | 上げを増幅 | 下げを増幅 | 上げを減衰 | 下げを減衰 |
|---|---:|---:|---:|---:|
| reward > 0 (n=1,044) | 0.480 | 0.495 | 0.023 | 0.002 |
| reward ≤ 0 (n=1,365) | 0.471 | 0.513 | 0.015 | 0.001 |

**成功した行と失敗した行で、向きの内訳がほぼ同一。** 出力トークン上では減衰はほぼ起きず(合計 2%)、機構は上下ほぼ半々に**増幅するだけ**である。

### 12.5 「筋が通って見える」実例(ただし方向は教師のもの)

情報を運びうる位置($\|\log p_{on}-\log p_{base}\|>2$)での最大作用 3 件:

1. `'Ġclean'` alfworld step26、extra **−0.243**、$p_{on}$=1.4e-09 / $p_{base}$=1.0、reward +9.9
   文脈: 「the knife is already clean. The next logical step is to take the knife and **clean** it. Since the knife is already clean, ...」— **自己矛盾した冗長 reasoning**。
2. `'Ġsink'` alfworld step11、extra **−0.241**、$p_{on}$=1.8e-13 / $p_{base}$=0.95、reward +9.9
   文脈: 「move the lettuce to the **sink**basin **again** to ensure it's clean」— 反復行動。
3. `'Ġ'` search step6、extra **−0.248**、$p_{on}$=7.4e-12 / $p_{base}$=0.99
   文脈: 「</think> </think>」— **閉じタグの重複**、崩れた出力。

いずれも「劣化したテキストの抑制を強めた」と読める。**しかし3件すべてで方向は on-task 教師が決めている**($p_{on}$ が 1e-9〜1e-13 に対し $p_{base}$ ≈ 1.0)。素の OPD が既に強く押し下げており、機構が足したのは高々 0.25 logit である。**修正は教師のもので、機構の寄与はその 2% の増幅**にすぎない。

対称の反例も同数用意できる(§2.3 の webshop `'color'`: 成功エピソード内の正しい属性語に W=11.2 の抑制増幅)。したがって **§12.5 は機構が何をしたかの例示であって、役に立ったことの証拠ではない。**

### 12.6 これに答えるために必要なもの

## 13. 蒸留予算の使途の欠陥と、プロンプト側の対策

§11 は「素の OPD の予算の 3/4 は内容語ではない」を示した。その最大項の正体を追うと、**タグ1つのトークン化の選択**に webshop の全 teacher-KL の 21.7% が使われていることが分かる。§13.5 に検証結果と、当初の見立ての訂正を置く。

### 13.1 タグのトークン化に webshop 予算の 21.7% が向いている

`'<th'`(id 13708) + `'ink'`(id 766) は **`<think` をリテラル3トークンで綴ったもの**。一方 Qwen3 には `<think>`(151667) / `</think>`(151668) が**単一の added token として存在**し、`tokenizer.encode("<think>")` はこの1トークンを返す。両経路はデコードすると**同一の文字列**になり、`projection.py` の `find("<think>")` 判定も**両方通る**(検証済み)。

control(晩期、`kl_mass`/`base_logit_push` 表、直近8ファイル合算)での押し:

| scope | token | \|kl_mass\| | base_push 合計 | count | p_stu |
|---|---|---:|---:|---:|---:|
| webshop | `'<th'` (13708) | 270,612 | **−230.99** | 143,166 | 0.095 |
| webshop | `'ink'` (766) | 25,595 | −0.00 | 7,432 | 0.929 |
| webshop | `'</think>'` (151668) | 11 | **+3.34** | 2,742 | 0.346 |
| alfworld | `'<th'` (13708) | 30,760 | **−92.62** | 373,232 | 0.201 |
| alfworld | `'<'` (27) | 2,587 | **+128.66** | 352,796 | 0.183 |
| alfworld | `'>'` (29) | 4,093 | **+87.57** | 342,970 | 0.338 |
| alfworld | `'</'` (522) | 4,520 | **+58.50** | 576,104 | 0.255 |

読み: **教師はタグの正規トークン化を教えている。** 単一トークンが存在する `<think>`/`</think>` では3トークン綴り(`<th`)を押し下げ単一トークンを押し上げ、単一トークンが存在しない `<action>`/`</action>` では構成部品(`<`, `>`, `</`)を押し上げる。`'ink'` の base_push が ≈0 で p_stu が 0.929 なのは、`<th` を出した後は `ink` がほぼ強制されるため — 分岐点は `<th` だけである。

§11.2 の通り **`'<th'` 単独が webshop の top-64 `|kl_mass|` の 23.2%**、alfworld でも押し下げ最大級。

**棄却した仮説を記録する。** 当初「`<think>` は特殊トークンなので `batch_decode(skip_special_tokens=True)`(`rollout_loop.py:1586,1591`)で消え、`projection.py:53` の `find("<think>")` が −1 になって無効判定される」というバグを疑った。**誤り**: `added_tokens_decoder` で `<think>` / `</think>` は `special=False` であり、`skip_special_tokens=True` でも消えない。両経路で `valids=1` になる。パーサに欠陥はない。

### 13.2 対策の候補

1. **プロンプトからタグ指示を外し、Qwen3 のネイティブ thinking に任せる**(推奨)。現状プロンプトは地の文で「`<think> </think>` に囲め」と要求しており、**それがリテラル綴りを生きた選択肢にしている当の原因**である。単一トークンはデコードすると `<think>` になるので `projection.py` の判定は通る(検証済み)。曖昧さを源で消すので、損失側の手術が要らない。
   * 唯一の risk は「指示を外すとタグを出さなくなる」で、`valid_action_ratio` を見れば安く検出できる。
2. **タグトークンを teacher KL からマスクする。** ただし §13.5 の通り**再配分にはならない**ので、per-task 再正規化と対で行う必要がある。
3. **生成時に3トークン経路を禁止する**(logit bias / bad_words)。ただし §13.5 の通り、候補としての KL は残るので効果は限定的。

### 13.3 プロンプトのタスク間統一

3つのテンプレート(`agent_system/environments/prompts/{alfworld,search,webshop}.py`)は**既に構造が揃っている**: 役割宣言 → `task_description` → history → observation → admissible actions → 「`<think> </think>` に囲め」 → action タグ。

実質的な差は1つだけ:

* **search のみ `<search> </search>` / `<answer> </answer>`、他は `<action> </action>`。** そして search は本監査の全測定で外れ値である — $\phi$ が負のペアを含み(§4.1)、$s_{gen}$ が負(§4.6)、`kl_mass` 予算が他タスクの 5–7%(§11.2)、転移行列 0.35–0.49、ターン上限も 4(他は 15/50)。action 語彙を `<action>search(...)</action>` / `<action>answer(...)</action>` に揃えるのは切り分けとして意味がある。

些末な不統一: webshop の "e‑commerce" が U+2011(非分割ハイフン)、変数名が `{admissible_actions}`(alfworld) 対 `{available_actions}`(webshop)。

**ただし方向に注意。** プロンプトを揃えると共有フォーマット成分は**増える**。本監査はその成分が cross-teacher で唯一転移するが、advantage との関連は 0 か負だと測っている(§4.3、§4.6)。したがって「揃えれば cross-teacher 裏付けが効くようになる」という筋ではない。**揃えることが効くとしたら、それは別の目的 — 書式の曖昧さそのものを減らすこと**である(§13.2-1、§13.5)。なお「予算を内容に回す」という言い方は誤りで、マスクは再配分にならない(§13.5)。

### 13.4 OPSD(= `main_sdar`)は、cross-teacher を殺した2点を構造的に回避する

実体(`verl/trainer/ppo/sdar_utils.py`):

$$L_{SDAR} = \mathrm{agg}\big(g_t \cdot (\log \pi_{teacher} - \log \pi_{student})\big), \quad g_t = \sigma(\beta \delta_t), \quad \delta_t = \log \pi_{teacher} - \log \pi_{student}$$

gate は detach。そして docstring にある通り **teacher は「同じモデルに privileged input(skill)を与えたもの」** で、別タスクで訓練された別モデルではない。

1. **書式の交絡が消える。** 教師と生徒が同一モデルなので共有フォーマット成分は定義上同一で、差は privileged input の効果だけになる。§11.6 の「一致しているのは書式で、それは on-task 教師が既に教えている」という問題が構造的に発生しない。
2. **gate がアンラーニング位置を潰す。** $\delta_t$ が大きく負(生徒が確信し教師が否認 = 本監査で効果の 69–88% が集中していた位置)では $g_t \approx 0$($\beta=5$、$\delta=-1$ で 0.0067)。cross-teacher 機構が**増幅**していた位置を、SDAR は**ゼロにする**。符号が逆である。

留保: sampled トークンの log-prob のみを使い top-k 分布を使わないので安いが情報は少ない。$\beta$(既定 5.0)と `sdar_coef` はハイパラであり、本監査が問題にしてきた「手置きの定数」がここには残る。

### 13.5 マスク案の検証結果(と当初の見立ての訂正)

**(1) 規模は確認された。** control の wandb アンカー `opd/<scope>/push/kl_mass_abs_top64_share` で、トークン表の top-64 内シェアを全 KL シェアへ換算した:

| task | top-64 内 | × `top64_share` | **= 全 teacher-KL シェア** |
|---|---:|---:|---:|
| **webshop** | 0.2769 | 0.7819 | **0.217** |
| alfworld | 0.0398 | 0.6278 | 0.025 |
| search | 0.0000 | 0.6665 | 0.000 |
| `__pooled__` | 0.1880 | 0.6402 | **0.120** |

token id `{13708 '<th', 766 'ink'}` だけで **webshop の全 teacher-KL の 21.7%、pooled で 12.0%**。極端にタスク非対称である。

参考: `opd/role/format/kl_share = 0.8596` — KL の 86% が `format` ロールに載る(`env_action` 0.113 / `tag` 0.018 / `tool_call` 0.010 / `reasoning` 6e-05)。

**(2) 訂正: これは「文字列を変えない no-op」ではない。** 当初そう書いたが誤り。3トークン綴りと単一トークンはデコード文字列は同じだが、**トークン列は2トークン長い**。`'<th'` は support 出現 56,685 回に対し `p_student_mean = 0.095`、`sampled/count = 0.089` で、実際に約 5,000 回出力されている(`'ink'` の count 5,684 と整合)。KL 項は `p_student('<th') → 0` を駆動しており、これは**応答を短くする正当な教え**である。ただし節約は think タグ1回あたり2トークンで、webshop の応答長 1,500–1,800 に対し ~0.2%。**21.7% の予算を 0.2% の短縮に充てている**という配分の問題として読むべきで、no-op ではない。

**(3) 訂正: マスクは再配分にならない。** `task_loss_weights.attach_task_loss_weights` の `T_task` は**そのタスクの応答トークン総数**(step 全体)であり、KL 項の数ではない。損失は $(1/T)\sum_{task} \mathrm{token\_mean}(task)$ で、`token_mean` の分母 `T_task` は KL からトークン id をマスクしても変わらない。したがって:

* マスクは分子だけを減らし、**そのタスクの蒸留項をマスク分だけ丸ごと弱める**。
* 実効的には **per-task で非一様な `teacher_kl_loss_coef` の削減**: webshop ×0.783、alfworld ×0.975、search ×1.000。
* 他トークンの勾配は**一切変わらない**。「空いた予算が内容語に回る」ことはない。

**しかも削減が最も大きいのは webshop** — ARM で唯一悪化したタスクである。マスク単独は交絡した実験になる。

**(4) したがって実験は2つに分かれる。**

* **(A) マスクのみ** = 「webshop の蒸留を 21.7% 弱める」実験。それ自体は解釈可能だが、**そう名付けて走らせること**。
* **(B) マスク + per-task 再正規化**(マスク後のトークン数で割る、または $1/(1-\text{masked share})$ で戻す) = per-task の総圧を保つ**純粋な再配分**。「予算を内容に回すと良くなるか」を試すのはこちら。

**(5) 生成時抑制(候補3)の効果は限定的。** `'<th'` は support 出現 56,685 回のうち出力は約 5,000 回で、KL 質量は「候補として確率を持っている」残り 51,685 回にも載っている。生成を禁じても候補としての KL は消えない。KL を消すには `p_student` 自体を下げる必要があり、それは今まさに KL 項がやっていることである。

## 14. sg1 の 150 step 到達後:検証で control を上回った理由

### 14.1 結果

検証(`val_step150.jsonl`、traj 単位)は ARM(sg1)が全タスクで control を上回った。一方、**同じ区間の学習中ロールアウト(T=1.0)では control が全タスクで上回っている。**

| | alfworld | webshop acc | search |
|---|---:|---:|---:|
| **検証** ARM / CTL | **0.714 / 0.651** | **0.667 / 0.635** | **0.394 / 0.384** |
| 非対応 z | +1.08(ノイズ内) | +0.53(ノイズ内) | **+3.17**(n=51,713) |
| **学習ロールアウト T=1.0、steps 121–148** ARM / CTL | **0.656 / 0.722** | **0.598 / 0.647** | 0.408 / 0.413 |

alfworld は 126 エピソード中 90 対 82、**8 エピソードの差**。手元の 5 run の `val_step150` は alfworld 0.651–0.714、webshop 0.627–0.675、search 0.386–0.394 に散っており、ARM は3つとも上端、control は下端付近。対応あり検定(McNemar)には control の `val_step150.jsonl` が必要で、本ホストには無い。

### 14.2 符号反転を説明する事実

検証と学習でサンプリングが違う: **alfworld / webshop の検証は T=0.4、search は greedy**(`rollout.val_kwargs_by_task`)、学習ロールアウトは T=1.0。そして ARM の entropy は control の **2.4 倍**(121–148: 0.590 対 0.249、alfworld 0.691 対 0.282)。search の entropy は両者同じ(0.099 対 0.103)。

| steps | alfworld teacher_kl ARM/CTL | entropy ARM/CTL | T=1.0 success ARM−CTL |
|---:|---|---|---:|
| 51–60 | 0.383 / 0.399 | 0.177 / 0.146 | **+0.175** |
| 81–90 | 0.307 / 0.353 | 0.483 / 0.160 | −0.023 |
| 111–120 | 0.280 / 0.280 | 0.823 / 0.290 | −0.066 |
| 141–148 | **0.234 / 0.196** | **0.772 / 0.322** | **−0.114** |

entropy の差が開くほど T=1.0 の成功率差が負に振れる。同時に alfworld では **step 120 以降 control の方が教師に近い**(teacher_kl の逆転)。応答も ARM の方が長い(alfworld +19% tokens、+16% turns; webshop +16% turns)。

### 14.3 T=1.0 での逆転は結果を否定しない(2026-09-02 訂正)

当初この節は T=1.0 の逆転を反証として扱っていた。**それは誤りである。** 検証プロトコル(alfworld/webshop T=0.4、search greedy)は両アームで同一かつ事前に固定されており、そこで測った値がこのプロジェクトの「精度」の定義である。T=1.0 の学習ロールアウトは**最適化の副産物**であって成果物ではない — RL は探索のために高温でサンプルするのであり、その条件での成功率が低いことは「わざと雑音を足したら弱い」と言っているに等しい。

さらに、**entropy が上がって T=1.0 の成功率が下がるのは、探索の対価としてむしろ健全な形**である。方策が平坦化して探索が増え、学習したモードは良くなり、低温評価でそれが読める — entropy bonus と同じ論理で、これは肯定的な筋書きですらある。

逆転が示すのは結果の可否ではなく、**帰属についての弱い手掛かり**にとどまる: 「目標分布が良くなった」なら全温度で良いはずで、「平坦だがモードが良い」なら低温だけで良い。観測は後者寄りだが、機構が知識を運びつつ副作用で entropy を上げた場合も同じ形になるので、決定的ではない。

### 14.4 検証側で説明がつくか — つかない

**検証条件は完全には同一でない。** 温度は同一(`val_kwargs_by_task` は config 差分に現れない: alfworld/webshop T=0.4、search greedy)だが、**`env.multitask.val_per_task_batch_size` が ARM `.search=252` 対 control フラット 126**、かつ control は pump 既定化(commit `9c5d528`)より前の起動である。**ただしこれで説明はつかない — §14.4-(i) の撤回を見よ。** また **control の `val_step150.jsonl` は本ホストに無く**(`/opt/home/...`)、その検証がどの step で走ったかは未確認である。

**(i) search(greedy 検証、entropy 不変、実測基準 2.6σ):** ARM は教師に近い(teacher_kl 0.089 対 0.115、−23%)。監査 §2 の通り $W$ は per-token KL と正相関(`weight_kl_lift` 1.27–1.29 を維持)し、**KL が大きい位置を重く蒸留する focal 型の再重み付け**として働く。KL 予算が最小の search で「教師への収束が速い」が最も素直に検証成績に出た。cross-teacher の裏付けは不要な説明である。

**撤回(2026-09-02):** 直前の版は「検証バッチ幅と pump の差(数値誤差)も 1pp を説明しうる」と書いたが、**桁で誤りだったので撤回する。** 復号の分岐による精度差の SD は $\sqrt{2f\,p(1-p)/n}$($f$=分岐する軌跡の割合、$p$=0.39、$n$=51,713):

| $f$ | 差の SD | 観測 1.0pp は |
|---:|---:|---:|
| 1% | 0.030pp | 33 SD |
| 5% | 0.068pp | 15 SD |
| **100%**(=2つの評価が完全に別方策。数値差では到達不能な上限) | 0.303pp | **3.3 SD** |

**到達不能な上限ですら 3.3 SD**、現実的な $f$ では 15–33 SD 足りない。しかも復号の分岐は両アームに等しく効く**不偏**な擾乱で、系統的にどちらかを持ち上げない。**検証条件の差では説明できない。**

**(ii) 二項 z は誤った検定だった(2026-09-02 訂正)。** z=1.08 / 0.53 は 126 を母集団からの独立標本と見なすが、**全アームは同じ 126 問を解いている**。手元の純 OPD 4本(機構は監査で不活性と判定済み、≒replicate)の run 間ばらつきを実測すると:

| task | replicate SD | 二項 SE | 差の SD(実測) | ARM−CTL | 実測基準 σ | 二項基準 σ |
|---|---:|---:|---:|---:|---:|---:|
| alfworld | 0.0188 | 0.0422 | 0.0265 | +0.0633 | **2.39** | 1.06 |
| webshop | 0.0218 | 0.0422 | 0.0309 | +0.0317 | 1.03 | 0.53 |
| search | 0.0027 | 0.0021 | 0.0038 | +0.0096 | **2.55** | 3.16 |

**実測ばらつきは二項 SE より小さい**(同じ問題集合を解くため)。したがって二項 z は保守的すぎ、実測基準では **alfworld 2.4σ / search 2.6σ / webshop 1.0σ**。search の replicate は 0.3858–0.3906 の幅 0.005 に収まり、**ARM 0.3936 はその全てより上、control 0.3840 は全てより下**である。

留保2つ: (a) 4本は純 OPD で ARM は OPD+GRPO なので目的関数が違い厳密な replicate ではない。(b) 機構差も含むため純ノイズの過大評価であり、真の σ はより小さく効果はより有意になりうる。

機構の内部量は監査の結論から動いていない: `shuffled_to_live_gate_ratio` 0.82(文法で開く)、`reward_positive/net_effect` は 61 step 以降負のまま(成功エピソードから圧を引く)、`teacher_novelty` は 0.70 まで上がるが `acted` 限定ではない。**cross-teacher の裏付けがタスク知識を運んだ証拠は、150 step 時点でも増えていない。**

### 14.45 では何が残るのか — 存在ではなく帰属

検証側(温度・バッチ幅・pump・数値)では説明できない。**2つの方策の差は実在する。**

**そして学習側の差も、この config では系統差ではない(2026-09-02 再訂正)。** 直前の版は GPU 枚数と `BALANCE_MINIBATCH_COLUMNS` を「最適化軌跡を変える系統差、不偏でもない」と書いたが、**これも誤りだったので訂正する。**

* **`BALANCE_MINIBATCH_COLUMNS`**: commit `6eac8d7` 自身が勾配不変であることを論証しており、その前提 `normalize_loss_by_task=True` は**両 run で成立している**(確認済み)。損失は step 水準の重みによる行の重み付き**和**なので、行がどの rank にあるかは mini-batch 勾配を変えない。動くのは FP 加算順のみ。
* **GPU 枚数 2 対 3**: 同じ論法が通る。`ppo_mini_batch_size=60`、`micro=5` で、world_size=2 → 30行/rank・ga=6、world_size=3 → 20行/rank・ga=4。actor が掛け戻す `task_dp_world_size × ga` は **2×6 = 3×4 = 12 で一致**。よって mini-batch 勾配は同じ60行の重み付き和で**不変**。
* 不変でないのは**ロールアウト**(vLLM のバッチ分割が変わり生成トークンが変わる)だが、これは**不偏**な別ドローであってどちらかを系統的に持ち上げない。

**したがって ARM と control の run 水準の差は、すべてシード相当の不偏な擾乱である。** 比較は「ARM のドロー A」対「control のドロー B」であり、正しいノイズ尺度は run 間ばらつきそのもの — §14.4-(ii) で実測したものである。

**統合すると(タスク間相関を考慮した Stouffer): Z = 3.30、片側 p = 0.0005。** 独立仮定なら 3.44、完全相関を仮定しても 1.99。

**ただし n=4 の σ 推定は極めて不安定である。** df=3 の 95%CI 係数は [0.57, 3.73] で、効果量は alfworld **[0.64, 4.21]σ**、search **[0.68, 4.51]σ**、webshop [0.28, 1.81]σ。タスク間相関行列も n=4 推定で、alfworld–search が −0.395 と符号すら安定していない(5本での推定では +0.422 だった)。

**現状で言えることの正味:** 差は実在し、run 間ばらつき基準の点推定では統合 3.3σ。**帰属を否定する具体的な代替説明は、いまや「シードのばらつき」しか残っていない**が、その大きさが 4 本の非厳密な replicate からしか推定できていないため、区間は 0.6σ から 4.2σ に広がる。**決着に必要なのは同一 config の反復(シード違い)であって、control の再学習ではない。**

### 14.5 決着させる測定

1. **【最優先】control を ARM と同一条件で再検証し、対応あり検定にかける。** 同一ホスト・同一 `val_per_task_batch_size`・同一 pump 設定で step-150 checkpoint を `val_only`。これが2つの脅威を同時に潰す: search の検証条件差が消え、`val_step150.jsonl` が揃って `scripts/val_paired.py` の McNemar(traj_uid 初出順)が走る。**対応あり検定は力が大きく違う** — 非対応 z=1.08 は 126 の独立標本を仮定しているが、両アームは同じ 126 問を解いており一致率が高ければ不一致ペアだけが効く。alfworld の正味 +8 が、例えば不一致 20 ペア中 14–6 なら McNemar で有意に届く。**現データを捨てずに結論を強められる唯一の測定。**
2. **シードを増やす。** 1 で有意に届かなければ、8 エピソードの差はシード反復でしか決まらない。
3. **cross-teacher 抜きの ablation。** $W$ を per-token KL の単調関数(例: $1+\kappa\,\mathrm{KL}/\overline{\mathrm{KL}}$ を mean-1 正規化)にした arm。(i) が正しければ search の +1pp が再現し、cross-teacher 部分は不活性と確定する。entropy bonus のみの arm が (ii) の対照。
4. **webshop "Score" 列の出所。** `val_step150.jsonl` の score は二値(成功×10)で、表の 0.768 / 0.760 は別ソース(`episode/webshop_webshop_task_score` 相当)。学習中の同指標は 121–148 で ARM 0.752 対 CTL 0.822 と**逆向き**なので、検証側の値の定義を揃えて再確認すること。
