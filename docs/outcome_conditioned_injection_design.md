**撤回**し、検証可能な最小形に絞った第2版。走らせる前に §6 を固定すること。

対象: alfworld、**飽和群のみ**。停滞群側は §5.2 の理由で本書から外す。

## 0. 何を検証するか

飽和群（8 本すべて成功）では advantage がゼロになる。GRPO の設計上これは正しい挙動で、
群内のリターンが揃うときベースラインはリターンに一致し、正しい更新はゼロである。
したがって**注入は「失われた信号の回復」ではなく、ベースラインを変えて advantage を作る操作**である。

検証する仮説はひとつ。

> **生徒がいまも選び得る失敗を抑えることで、未見ゲームでの成功率が上がる。**

`live_frac` の上昇は成功条件ではない。それは操作が起きたことの確認にすぎない。

## 1. 注入が作る advantage の大きさ

7 成功 + 1 失敗を群内の母標準偏差で正規化すると、報酬の尺度に依らず

$$A_{\text{success}} = \frac{1}{\sqrt 7} = +0.378, \qquad A_{\text{failure}} = -\sqrt 7 = -2.646$$

**注入した 1 本に、成功 1 本の 7 倍の絶対値が付く。** 実際の勾配の大きさは重要度比・系列長・
集約方法にも依存する。

大きさが 7:1 の分割だけで決まり、base の強さにも生徒の状態にも依存しないことに注意する。
control step300 の実測（生徒 10.00 / base 1.72 と 10.00 / 0.27）でも同じ値になる。

### 1.1 これが効くための条件

* **生徒がその失敗をいまも選び得る**こと。生徒がほとんど出さない失敗なら抑える余地がない。
* **失敗軌跡の中の適切な行動まで一律に抑えないこと**。全トークンを負に更新すると、
  その中の正しい行動も押し下げる。

どちらも `live_frac` では測れない。§7 の診断で別に測る。

## 2. 機構（最小形）

全アームで **素の生徒 8 本**を生成する。先頭 7 本の結果だけで判定する。

| 先頭 7 本 | RL の群 |
|---|---|
| 全成功 | 生徒 7 本 + **同じゲームの base 失敗 1 本**（8 本目の生徒行を差し替え） |
| それ以外 | 生徒 8 本（無介入） |

**OPD は全アームで元の生徒 8 本に固定する。** OPD 側を動かさないことで、精度差を
RL の群構成の変更だけに帰属できる。

base 失敗は事前生成したキャッシュから引く（§4）。使える失敗が無いゲームは注入対象外にする。

### 2.1 初版から落としたもの

* **計画付き生徒の注入**。混在群にも介入が入って 4 アームが分離できず、
  8 本目の素の生徒行が失われて「注入なし」に戻せなかった。停滞群側は §5.2 参照。
* **7+1 生成**。全アームで素の 8 本を生成し、RL 用の群でのみ差し替える。

## 3. アーム

| arm | RL の群 | 注入失敗への勾配 |
|---|---|---|
| control | 生徒 8 本 | — |
| OCI-sat-B | 生徒 7 本 + base 失敗 1 本 | **なし**（群平均だけ動かす） |
| OCI-sat-A | 生徒 7 本 + base 失敗 1 本 | **あり** |

**B を外さない。** A が B を上回って初めて「注入した失敗を抑えることに価値がある」と言える。
A と B が同等なら、負例への更新は不要で、効いているのは成功軌跡への一様な再強化
（$+1/\sqrt7$）だけだという結果になる。

### 3.1 A アームの勾配整形

LUFFY は重要度比 $\rho$ に $f$ を掛けるのではなく、**$\rho$ を $f(\rho)$ に置き換え、
off-policy 側の PPO クリップを外す**。また LUFFY の実験は生成元確率の分母を 1 と置いている。
実際の生成元確率を使う本機構とは、同じ $\gamma$ でも意味が変わる。

生成元確率を固定して $\rho = \pi_\theta(a|s)/\pi_{\text{behavior}}(a|s)$、
$J_{\text{off}} = A\,\rho/(\rho+\gamma)$ とすると

$$\frac{\partial J_{\text{off}}}{\partial \log \pi_\theta(a|s)} = A\,\frac{\gamma\rho}{(\rho+\gamma)^2}$$

この係数は $\rho \to 0$ で**ゼロ**であり、$\rho = \gamma$ で最大になる。

| $\rho$ | $f(\rho)$ | 勾配係数 |
|---:|---:|---:|
| 0.001 | 0.010 | 0.010 |
| 0.01 | 0.091 | 0.083 |
| **0.1** | **0.500** | **0.250** |
| 1.0 | 0.909 | 0.083 |

**到達確率の極端に低い base 軌跡は、強い負例にならない。** shaping を使ってもそうである。
$\gamma$ はアームの knob であり、事前登録では 0.1 に固定する。

## 5. 先行研究に対する位置

### 5.1 飽和群への負例混入は既出

[Too Correct to Learn (Mixed-CUTS, ACL 2026)](https://aclanthology.org/2026.acl-short.19.pdf) は、
通常サンプリングと**温度を上げた探索的サンプリング**を混ぜ、簡単すぎる問題でも後者が失敗することで
報酬分散を回復させる。飽和群に低報酬の軌跡を混ぜる発想そのものは既に扱われている。

本機構が差別化を検証できるのは、より限定した次の点だけである。

> **群の結果に応じて、凍結 base の失敗キャッシュを選択的に注入する設計**

したがって **Mixed-CUTS 型（現在の生徒から探索的に失敗を生成する）が重要な比較対象**になる。
将来のアームとして OCI-sat-T（温度を上げた生徒の失敗を注入）を置く。

### 5.2 停滞群側を本書から外す理由

LUFFY（R1 の軌跡を全群に混ぜる）、[SORT](https://arxiv.org/abs/2605.11505)（参照解から計画を導き、
計画あり/なしのトークン確率差で重み付け。生成は変えない）、
[NGRPO](https://arxiv.org/abs/2509.18851)（仮想の最大報酬サンプルで advantage を作る。生成しない）、
[POPE](https://arxiv.org/abs/2601.18779) が別々のやり方で扱っている。
LUFFY の 285 件の引用を要旨で走査した結果、停滞群側に空白は見つからなかった。

## 6. 事前登録

### 6.1 仮説

**H1**: OCI-sat-A または B が control の alfworld 検証成功率を上回る。
**H2**: A が B を上回る（負例への更新に価値がある）。

### 6.2 配線の検査（結果ではない）

**異なる報酬を入れた群で、設定どおりの advantage が計算されたか**を確認する。
具体的には注入群で $A_{\text{success}} = +1/\sqrt7$、$A_{\text{failure}} = -\sqrt7$ が出ること。

`live_frac` の閾値は置かない。注入後の生存率は

$$p_{\text{live,after}} = p_{\text{mixed}} + p_{\text{success}}\,q_{\text{negative}}$$

で、$q_{\text{negative}}$（使える base 失敗がある割合）に依存する。初版の「95% 以上」は導けない。
既存の 30% も 8 本群での測定なので、7 本判定にそのまま代入できない。

### 6.3 反証条件

* **A と B が同等**なら、負例への更新は不要という結果。H2 を棄却する。
* **A も B も control と同等**なら、飽和群への注入は効かない。機構を棄却する。
* **A または B が control を下回る**なら、$+1/\sqrt7$ の一様再強化か $-\sqrt7$ の負例が
  害になっている。§7 の診断で切り分ける。

### 6.4 検出力（限界として明記）

alfworld の反復検証 SD は 1.39pp だが、これは**同一 checkpoint を 3 回検証した評価の揺れ**であり、
**学習 seed 間の分散を含まない**。したがって「2pp 以上なら主張できる」とは言えない。
3 アーム各 1 引きで H2（A と B の差）を判定する検出力は無い。
**H2 を検証するなら学習 seed を複数取ること。予算に入らないなら H2 を落とす。**

### 6.5 適用範囲（限界として明記）

`env.rollout.n` は `config.env.rollout.n` の単一整数で、タスク別指定はコードに無い。
したがって本機構は **alfworld 単独でしか走らない**。3 タスク同時への転移は未検証のまま残る。

そして **OCI-sat は単タスクでも成立する機構である。** 当初の「複数タスク間を対象とする」という
条件を満たさない。現段階では **ALFWorld の飽和群を使った精度改善候補**として位置づける。

## 7. 診断

| 指標 | 何を見る |
|---|---|
| `oci/injected_groups` | 注入した群の数と、使える base 失敗が無く見送った数 |
| `oci/log_rho_hist/{pos,neg}` | **正負の注入別**の $\log\rho$ 分布 |
| `oci/grad_coef_hist/{pos,neg}` | 実効勾配係数 $\gamma\rho/(\rho+\gamma)^2$ の分布 |
| `oci/base_fail_action_overlap` | 注入した失敗行動を、生徒がいまも選ぶ確率（§1.1 の第1条件） |
| `actor/entropy` | 記録はするが、低下だけでは実装不良と正常な学習を区別できない |
| 群クラス別トークン量 | §7.2 |

`shaped_ratio_mean` は診断に使わない。$\rho=\gamma$ で $f(\rho)=0.5$ かつ勾配係数が最大になるため、
1 から離れることは到達不能の判定にならない。

### 7.1 先行測定の訂正

訓練 parquet の alfworld は **15 行、prompt はすべて空文字**で、実際のゲームは環境が
`seed + i // group_n` で決める。`index` で突き合わせた 2026-09-12 の救出率は**すべて無効**。
以後は `extra.gamefile` で突き合わせる。`env_manager.py` に parse/set 両方あり鍵として使える。

同じ `index` を引き直すとラベルが 83% 変わるのはこの帰結であり、方策の不安定さではない。
本機構は判定をその step 内で行い持ち越さないので、この訂正の影響を受けない。

### 7.2 未測定：群クラス別のトークン量

勾配が数えるのはトークンであって群ではない。control step300 の実測では

| task | 非ゼロ advantage トークン | 群での live |
|---|---:|---:|
| alfworld | **75.5%** | 30% |
| webshop | 37.6% | 16% |
| search | 23.5% | 22% |

**alfworld はトークンでは 4 分の 3 が既に生きており、3 タスクで最も健全である。**
飽和群（早く終わる＝短い）と停滞群（50 turn 上限＝長い）でトークン量が大きく違うため、
死んでいる 24.5% の内訳が飽和側と停滞側のどちらに偏るかで本機構の取り分が決まる。

`groups_raw` が生きた群しか記録していないため未測定。**退化群も記録する修正を入れ、
プローブ 1 本（約 20 分）で確定させてから §8 の事前生成に入ること。**
