# 出力空間でタスク間を扱う押し戻し制御: 「減衰」を「同意する教師への置換」に一般化する

状態: **提案のみ。実装なし。** 前提は `ARM=pushback`（`f7333cb`）の self gate と、
[opd_pushback_cross_task_extension.md](opd_pushback_cross_task_extension.md) §9（root プロキシの検定）、
理論文書 §3.2（識別不能性）・§3.6（出力空間の off-task 教師 vs 報酬）・§5.1（原則: 教師統計は目標に、信頼は報酬から）、
Armandpour et al. 2026（arXiv:2605.10889、ロジット空間の alignment score と成否による差）。

問い: 現行機構と同じく**出力空間**でタスク間を扱うなら、どの機構にすべきか。

---

## 0. 結論

1. **出力空間が持てるタスク間の量は 2 つしかない。** (i) 他タスクの教師 $m$ をタスク $i$ の状態で評価した分布（cross-teacher アームの「planes」）、
   (ii) 最終隠れ状態のカーネル $h_s^\top h_t$。(ii) は干渉の head 成分だけを運び、その大きさは全体の 1%、符号一致は偶然の水準（§9）。
   (i) は「干渉」ではなく「その教師がタスク $i$ の状態で報酬と同じ向きを押すか」を測る。
2. **したがって出力空間の多タスク機構は、送り手（タスク $j$ の OPD 項）を減衰する干渉ゲートにはできない。受け手（タスク $i$ のトークン）で、
   報酬を根拠に目標を選ぶ機構になる。** 現行の self gate は「報酬と対立する on-task 教師の押しを減衰する」。その一般化は
   「報酬と対立する on-task 教師の押しを、**報酬と同意する off-task 教師の押しに置き換える**」で、置換相手が無ければ現行と一致する（§1）。
3. これは理論文書 §5.1 の原則に整合する: どの教師を信じるかは報酬勾配（教師と独立）で決め、教師統計は目標（何を蒸留するか）にだけ入る。
   一様混合（§3.3 で撤回）や一致で重み付けた混合（§3.6 で不支持）とは、報酬で token ごとにゲートする点が違う。
4. **事前予測は「この教師集合ではほぼ発火しない」。** §3.6 の測定で、off-task 教師が on-task 報酬と再現的に同意するペアは無く、
   唯一再現するのは alfworld ← webshop の**負**である。置換率（§4）が事前登録した指標で、発火すれば新しい証拠、しなければ機構は現行と同じ。
5. **論文の成否層別を先に入れる。** 正解軌跡では教師の整列が ≈ 0（雑音）、不正解軌跡では 0.06〜0.09 と整列する。ゲート（減衰も置換も）の
   ε を成否で分けるのは無料で、この系列で最も安い変更（§3）。
6. **作らないもの**: 送り手側の head-kernel ゲート（$c_{i,j,t}=\sum_s(u_{R,i,s}\cdot u_{D,j,t})(h_s\cdot h_t)$）。構成はできるが、
   全体の干渉との符号一致が偶然の水準で、lm_head 単独の直接検定（安い）を通すまで制御には使わない（§5）。

## 1. 機構: 報酬ゲート付きの教師置換

タスク $i$ のトークン $s$ で、ロジット空間の降下方向を

* $u_R$: GRPO 項（報酬）
* $u_i$: on-task 教師 $i$ への KL（β 込み）
* $u_m$: off-task 教師 $m\ne i$ への KL（同じ閉形式、planes の log-prob から）

とする。すべて既存の閉形式（`opd_pg_alignment_terms`）で、追加の backward は無い。

**現行（self gate）**: $u_R^\top u_i<0$ の token で on-task 項に $a_i$ を掛ける。失われるのは $(1-a_i)$ 分の蒸留圧。

**一般化**: 同じ token で、報酬と同意する off-task 教師があれば、失う分をそこへ回す。

$$
m^\star(s)=\arg\max_{m\ne i}\ u_R^\top u_m
\quad\text{s.t.}\quad \frac{u_R^\top u_m}{\|u_R\|\|u_m\|}>\rho_{\min}
$$

$$
\log\tilde\pi_s = (1-\lambda_i)\log\pi_i + \lambda_i\log\pi_{m^\star} - \log Z_s
\qquad(\text{候補が無ければ }\lambda_i=0)
$$

* 目標は幾何混合で、support（生徒 top-k）+ tail の上で正規化する。`cross_teacher_target.build_target` の形（$\log\tilde p=\log p_{\rm on}+(c-\log Z)$）にそのまま乗る。
* $\lambda_i$ は on-task から外した保持率をそのまま渡す: $\lambda_i = 1-a_i$。総蒸留圧は保たれ、向きだけが報酬に同意する側へ変わる。
* 置換は**対立 token かつ候補あり**の場合だけ。それ以外は現行と同一（減衰のみ、または無介入）。
* $a_i$ は現行の閉形式（$\varepsilon R_i/C_i^-$、EMA、1 step 遅れ）のまま。$\rho_{\min}$ は「同意」の余裕で、雑音による誤置換を抑える唯一の新しい knob。

**なぜ「減衰」より筋が通るか。** 現行のゲートは、教師が報酬に逆らう token で蒸留を減らすだけで、その token の目標は空になる
（報酬単独）。置換は、教師集合の中に報酬と同意する分布があるなら、それを目標にする。多タスクの教師集合を持つことの意味がここに出る。
単タスクでは候補が無いので機構は現行に退化する。

**識別不能性との関係。** §3.2 の定理は「教師どうしの一致から on-task 教師の信頼性は読めない」。ここでは教師どうしを比べていない。
比べているのは各教師と報酬勾配で、報酬勾配は論文の式 2.5 により理想勾配（成功確率を最大に増やす方向）の不偏推定である
（この repo は行内の長さ正規化を持たないので、論文の GRPO への留保は当たらない）。

## 2. 費用（訂正）

**初版の「追加 forward/backward = 0」は誤りだった。** `_all_teacher_planes` の docstring が明示するとおり、
`sign_cache_ids` を埋めるのは「the three extra forwards only the cross-teacher arms run」である。
`student_indexed_topk` が節約するのは最後の gather（全語彙射影の代わりに $2Hk$）だけで、教師ごとのトランク forward は避けられない。

| 項目 | 量 |
|---|---|
| 追加 forward | 行あたり **2 本**（off-task 教師 2 体。base plane はこの機構には不要） |
| 実測（sg1 run、3 plane） | `sign_weight_forward` **143 s/step**、MFU ≈ 30%（前回提案 §1.1） |
| 2 plane 換算 | **約 95 s/step**（482 s の step に対し +20%） |
| 窓内 prefetch した場合 | `sign_weight_forward` は 143 → 2.5 s になるが、**gen がほぼ同じだけ増える**。移動であって削減ではない |
| host RAM | teacher hidden cache 3.3 → 約 10 GB。15.6 GB で node OOM の記録あり（前回提案 §0.1） |

pushback アームは `cross_teacher_kl_weight.enable=false` で planes を持たないので、これは純増である。
対立のある行だけ走らせる条件付き実行はできない —— 対立判定には生徒の top-k が要り、それは update 時にしか無い一方、
教師 forward は rollout 窓で先に走らせないと隠せないため、update 時に移すと直列になって却って遅くなる。

## 3. 成否による層別（先に入れる、無料）

論文（Qwen3-1.7B）: 平均 cosine は正解軌跡 0.001、不正解軌跡 0.058（BoolQ、$p=2\times10^{-9}$）。
on-task 教師の押しは、生徒が既に成功している軌跡では雑音、失敗している軌跡では成功方向に整列している。

現行のゲートは成否に関わらず同じ ε で対立 token を減衰させる。不正解軌跡での対立は、教師が整列している以上、
報酬勾配側の標本雑音である可能性が高い。そこで

* 正解軌跡（群内で $A>0$）: 現行の ε
* 不正解軌跡（$A<0$）: 緩い ε（例 3 倍）、または減衰しない

を別 knob にする。§1 の置換も同じ層別に従う（不正解軌跡では on-task 教師を置換しない）。
軌跡の成否は行ごとに既にあるので費用は無い。指標: 成否別の $C^-/R$、`a_applied`、置換率。

## 4. 事前登録する予測と指標

| 指標 | 予測（§3.6 から） |
|---|---|
| 置換率（対立 token のうち候補ありの割合）、タスク別 | alfworld: ほぼ 0（webshop 教師は負、search 教師は null）。search / webshop: 0 付近 |

## 5. 作らないもの: 送り手側の head-kernel ゲート

タスク $j$ の token $t$ に、タスク $i$ の報酬勾配をカーネルで運んで
$c_{i,j,t}=\sum_{s\in i}(u_{R,i,s}\cdot u_{D,j,t})(h_s\cdot h_t)$ を作り、負なら $t$ の OPD を減衰する案。
構成はでき、費用も小さい。しかし

* これは干渉の **head 成分**で、パラメータ空間の測定では全体の 0.1〜3.5%、符号一致は交差対で 4/8・4/8・2/8（§9）。
  干渉の 60% は層 0〜8 にある。
* head 単独（tied 埋め込みを除いた $u h^\top$）の直接検定はまだ無い。lm_head の勾配は $u$ と $h$ から追加 backward 無しで作れるので、
  N=8 と同じ 8 バッチで全体との符号一致を測る検定は安い。**通れば送り手側ゲートを再検討する。通るまで制御には使わない。**

## 6. 限界

* §1 の置換は目標の変更（M2）で、固定点を動かす。命題 2 の枠では「対立位置の $\tau$ を報酬側へ」ではなく「対立位置の目標を別の教師へ」になる。
  到達点が変わりうるのは意図どおりだが、方向は報酬勾配の標本に依る。$\rho_{\min}$ と成否層別がその防護。
* 置換候補の判定 $u_R^\top u_m>0$ は token 単位の標本量で、self gate の対立判定と同じ雑音を持つ。期待値では soft な置換になる。
* 干渉そのもの（タスク $j$ の OPD がタスク $i$ の損失を動かす量）は出力空間では測れない。それが要るなら
  [opd_pushback_cross_protection_design.md](opd_pushback_cross_protection_design.md)（パラメータ空間、追加 backward あり）。
* この機構が多タスク固有なのは「置換候補が他タスクの教師」だからで、機構の形は単タスクの self gate の一般化である。

## 7. 追記: 置換候補率をオフラインで測った。偶然の水準だった

§4 が事前登録した置換候補率は、GPU を使わずに既存の dump から読めた（`scripts/opd_offtask_candidate_rate.py`）。
`sign_pair_events` は per-token・per-(dst, src) で `advantage`・`p_student`・`p_on`・`p_source`・`is_sampled` を持つ。
標本トークンで、降下規約（正 = そのロジットを上げる）のもとに

* 報酬が上げたい ⟺ advantage > 0
* 教師 $t$ が上げたい ⟺ $\log p_t(a) > \log p_s(a)$（$D$ を使わない保守側の判定。$D_t\ge0$ なので候補を作り出す方向には誤らない）

とし、on-task が報酬と食い違う token に限って、off-task 教師のどちらかが報酬と一致する割合を数えた。
帰無は token ごとに advantage の符号を並べ替えたもの（周辺率を保ったまま報酬と教師の対応だけを壊す）。

| run | 受け手 | 対立 token | 候補率 | 並べ替え帰無 | 超過 |
|---|---|---:|---:|---:|---:|
| klw sg1 | alfworld | 413 | 35.6% | 37.2% | **−1.6pt** |
| klw sg1 | search | 150 | 31.3% | 29.5% | +1.9pt |
| klw sg1 | webshop | 354 | 35.3% | 38.2% | −2.9pt |
| klw xt1 | alfworld | 396 | 45.7% | 51.7% | **−6.0pt** |
| klw xt1 | search | 159 | 45.3% | 47.7% | −2.4pt |
| klw xt1 | webshop | 396 | 46.0% | 50.8% | −4.9pt |

**超過は −6.0 〜 +1.9pt で、6 セル中 5 つが負である。** すなわち on-task 教師が報酬に逆らう token において、
off-task 教師が報酬と一致する頻度は偶然と変わらない。生の候補率が 30〜46% あるのは、教師どうしが書式で一致することと
$p_t(a)>p_s(a)$ 自体の基底率によるもので、報酬の情報ではない。

**帰結: §1 の置換機構は、この教師集合では作らない。** 発火しても選ぶ相手は報酬に関して無作為である。
95 s/step と 3 教師分の cache は払わない。§3.6 の出力空間の結論（off-task 教師は on-task 報酬を予測しない）が、
**機構が実際に作動する条件の下で**確認された形になる。

**この読みの限界**（いずれも結論を弱める方向ではない）:

* 判定は標本トークンでの符号で、厳密な $u_R^\top u_m$ ではない。厳密版は $-\sum_v p_s(v)g_m(v)$ の項を含み、支持集合が要る。
* dump は機構 ON の 2 run（klw sg1 / xt1）で、control や pushback の方策ではない。
* advantage は軌跡水準の broadcast なので、「報酬がこの token を上げたい」は信用割当の雑音を含む。並べ替え帰無は周辺率を揃えるが、この雑音は揃えない。
* 対立 token は 150〜413（run × 受け手）。

**残るのは §3 の成否層別で、こちらはこの結果に影響されない。** 論文の測定（正解軌跡で整列 ≈ 0、不正解軌跡で 0.06〜0.09）は
on-task 教師についての主張で、置換候補の有無とは独立である。無料なので先に入れる。
