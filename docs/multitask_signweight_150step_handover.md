この文書は**引継ぎ用**である。「何が走ったか」「ログが何を言っているか」「何がまだ無いか」
「次に誰が何をするか」を、他人が wandb を開かずに再構成できる粒度で書く。
**結論を先に言うと、この150stepログだけでは2アームの優劣は判定できない。**判定に必要な
検証(validation)がこの走行には含まれていないからである(§2.3)。ログが答えているのは
「機構が意図通り動いたか」「介入がどれくらいの大きさか」であって、「効いたか」ではない。

## 1. 一段落での要約

3タスク同時の純OPD(`pg_loss_coef=0`、損失は教師への reverse KL のみ)に、
**生徒の top-20 候補ごとに、base からの policy shift の符号を4モデル(自タスク教師・
off-task 教師2本・base)で読み、off-task 2本が全会一致でかつ自タスク教師と一致した候補に
重み1.25を付ける**機構を入れた2アームを、それぞれ150step走らせた。
`position` は重みを per-token KL に掛ける(固定点を動かさない = target の対照)、
`target` は重みを確率に掛けて再正規化する(固定点を動かす)。
150stepの全ログ(target 245指標 / position 225指標)を集計した結果:

1. **機構は動いた。**候補の 19.3% が agree_pos、4.6% が agree_neg。配管の整合性も
   独立に検算して合った(§9)。
2. **しかし触れている教師確率質量は 8.6% しかない。**教師のRLは分布の頭ではなく裾を動かして
   おり、質量の 64.7% は自タスク教師が base から動かしていないトークンに載っている(§3.2)。
3. **介入の絶対量は小さい。**target アームの目標書き換えは全変動距離で 0.72%、KL で 0.001 nats。
4. **ただし相対量は上がり続けている。**生徒は150stepで教師にほぼ収束し(teacher_kl が
   0.571 → 0.005 nats)、書き換えが残り距離に占める割合は 0.3% → 25.2%(Alfworld 35.4%)に
   なった。**アームが分かれるとしたら150step以降**という予測がここから出る(§10.3)。
5. **2アームは、学習中ロールアウトを含む全共通指標でほぼ一致している**(成功率 0.533 vs 0.534)。
   これは「差が無い」という結論ではない。**正式な検証がまだ走っていない**だけである。

## 2. 走行の同定

### 2.1 アーム

| | Target arm | Position arm |
|---|---|---|
| experiment_name | `opd_multitask_signweight_target_qwen3_1.7b` | `opd_multitask_signweight_position_qwen3_1.7b` |
| CSV の `pid` | 2524363 | 1130066 |
| 記録step数 | 1–150 | 1–150 |
| 収集指標数 | 245 | 225 |
| `sign_weight/mode_is_target` | **1.000**(全150step) | **0.000**(全150step) |

指標数の差 20 は機構の定義そのものから来ており、欠損ではない:
target のみ `{target_kl, target_kl_ratio, inv_z, target_entropy_delta, target_tv, teacher_kl}`
× {全体, alfworld, search, webshop} = 24指標、position のみ `w_mean_pre_norm` × 4スコープ = 4指標。
**共通の221指標は両アームに揃っている。**

### 2.2 設定

`examples/opd_trainer/expected_multitask_signweight_{target,position}_config.yaml` が
intent lock であり、`main_opd` が Hydra 合成後の実効設定を起動時に照合して不一致なら停止する。
**2つのロックの差分は実質2行**(`sign_weight.mode` の `target` / `position` を2箇所)+
experiment_name + コメント1行のみ。**機械検証済みで、アーム間に他の差は無い。**

主要な固定値:

| | 値 |
|---|---|
| モデル | `Qwen/Qwen3-1.7B` |
| 損失 | `topk_kl`, `kl_loss_coef=1.0`, `topk=20`, `normalize_loss_by_task=true` |
| 純蒸留の不変条件 | `pg_loss_coef=0`, `use_kl_loss=false`, `entropy_coeff=0` |
| 教師 | `$HOME/checkpoints/teachers/{alfworld,search,webshop}_step300` |
| 最適化 | `lr=1e-6`, `warmup_ratio=0.1`, `ppo_mini_batch_size=60` |
| データ | `train_batch_size=45`, `env.rollout.n=8` → 360行/step, `data.seed=1`, `env.seed=1` |
| 支持集合 | `student_indexed_topk=true`(生徒の top-20) |
| 機構 | `agree_weight=1.25`, `agree_neg_weight=0.75`(target のみ有効), `disagree_weight=1.0`, `deadzone=0.1` nats, `base_path=Qwen/Qwen3-1.7B` |
| 走行 | `total_training_steps=300`, `stop_after_steps=150`, `save_freq=25`, `n_gpus_per_node=2` |

`total_training_steps` は300のまま `stop_after_steps=150` で止めている。150にすると
LR warmup(総stepの10%)が変わり step 15–30 の軌道が対照とずれるため。

### 2.3 【重要】検証は走っていない

`run_signweight_sequence.sh` の学習フェーズは **`trainer.test_freq=-1`** を渡す。
検証は別フェーズ(`val_only=True`)として学習後に走らせる設計である。したがって:

* **この CSV の `episode/*` は学習中ロールアウトの値**であり、正式な150step検証結果ではない。
  温度も違う(学習は `temperature=1.0`、検証は alfworld/webshop T=0.4・search greedy)。
* **対照アーム(`run_multitask_qwen3.sh`、符号重み無しの純OPD)はこの CSV に入っていない。**
  A/B の相手がいないので、この文書の数字だけから「効いた/効かない」は言えない。

### 2.4 コードの所在

**この走行を生んだ実装は本文書と同じブランチ `claude/pure-opd-signweight-student-topk`
にある**(本文書追加時点の HEAD: `aff49d1`)。機構の設計・重み表・指標の定義は
`docs/multitask_signweight_pure_opd.md` にあり、本文書はその指標の実測値を引き受ける、

## 4. 目標をどれだけ動かしたか(Target arm 固有)

表記は **`平均 ± std / step150 / 後半50step平均`**。

| 指標 | 全体 | Alfworld | Search | WebShop |
|---|---:|---:|---:|---:|
| `target_kl` | 0.0011±0.0002 / 0.0010 / 0.0010 | 0.0013±0.0004 / 0.0010 / 0.0013 | 0.0010±0.0000 / 0.0010 / 0.0010 | 0.0010±0.0000 / 0.0010 / 0.0010 |
| `target_kl_ratio` | 0.1481±0.0815 / 0.2520 / 0.2277 | 0.1744±0.1060 / 0.3540 / 0.2860 | 0.0298±0.0108 / 0.0350 / 0.0314 | 0.1568±0.0779 / 0.2230 / 0.2305 |
| `inv_z` | 0.9912±0.0008 / 0.9910 / 0.9911 | 0.9903±0.0011 / 0.9910 / 0.9903 | 0.9858±0.0010 / 0.9850 / 0.9857 | 0.9948±0.0006 / 0.9940 / 0.9947 |
| `target_entropy_delta` | 0.0017±0.0006 / 0.0020 / 0.0018 | 0.0032±0.0006 / 0.0030 / 0.0032 | -0.0010±0.0002 / -0.0010 / -0.0010 | -0.0025±0.0006 / -0.0030 / -0.0026 |
| `target_tv` | 0.0072±0.0008 / 0.0070 / 0.0072 | 0.0076±0.0009 / 0.0080 / 0.0077 | 0.0039±0.0005 / 0.0040 / 0.0038 | 0.0061±0.0003 / 0.0070 / 0.0061 |
| `teacher_kl` | 0.0484±0.1129 / 0.0050 / 0.0059 | 0.0563±0.1351 / 0.0040 / 0.0050 | 0.0687±0.1681 / 0.0250 / 0.0259 | 0.0229±0.0462 / 0.0060 / 0.0054 |

読み方:

* **`target_tv` = 0.0072。**目標分布 $p_i$ と書き換え後 $\tilde p$ の全変動距離が 0.72%。
  介入は**絶対量としては小さい**。
* **`target_kl` = 0.0011 nats**(`actor/teacher_kl_loss` と同単位)。
* **`teacher_kl` が 0.571 → 0.005 nats に崩落している。**生徒は150stepで教師にほぼ収束した。
  `pg_loss_coef=0` かつ `kl_loss_coef=1.0` の純蒸留なので当然ではあるが、**残り伸びしろが
  ほとんど無い状態に入っている**という事実は次の実験設計に直結する。
* **`target_kl_ratio` が 0.003 → 0.252 に上がった。**分子(書き換え量)はほぼ一定で
  分母(生徒の残り距離)が100倍縮んだ結果である。step150 時点で
  **Alfworld は残り距離の 35.4%、WebShop は 22.3% を書き換えが占める。**
  Search だけ 3.5% と低いのは、search 教師との残り距離 `teacher_kl` が 0.025 と
  他タスク(0.004–0.006)の4〜6倍あり、分母が縮んでいないため。
* **`inv_z` = 0.9912 < 1**、すなわち $Z > 1$。`docs/multitask_signweight_pure_opd.md` §5 が
  予告した**系統的シャープ化(tail の縮み)は実測された。**大きさは 0.9%。
* **`target_entropy_delta` は符号が一定でない**: 全体 +0.0017、Alfworld +0.0032(エントロピー
  増加)、Search −0.0010、WebShop −0.0025(減少)。$Z>1$ で tail は必ず縮むのに全体の
  エントロピーが上がるのは、頭(高確率かつ `neutral_on_task_silent`、重み1.0)ではなく
  中位の `agree_pos` が持ち上がるため、top-20 の中では平坦化するからである。
* **温度交絡は懸念された規模では起きていない。**$|\Delta H| \le 0.003$ nats。
  §5 が「符号シャッフル対照を符号情報の検定として読むための前提」としていた
  「`target_entropy_delta` がゼロ近傍」は、**大きさとしては満たされている。**
  ただし符号がタスク間で反転しているので、シャッフル対照を組む際は**タスク別に**
  この量を見ること(全体平均は Alfworld の + と WebShop の − が打ち消し合っている)。

再走行するなら、この4指標(+`inv_z`)だけでも小数第5位まで出すこと。

## 9. 配管の整合性チェック(独立検算)

診断指標が「損失が実際に使っている物」の上で計算されているかを、指標同士の代数関係から検算した。

### 9.1 Position arm(厳密に一致)

位置重みは教師質量による加重平均なので、恒等式

$$\overline{w} = 1 + 0.25\big(\text{mass\_frac}_{\text{agree\_pos}} + \text{mass\_frac}_{\text{agree\_neg}}\big)\times \text{teacher\_coverage}$$

が成り立つはず。代入すると $1 + 0.25 \times (0.0653 + 0.0206) \times 0.993 = 1.02133$。
**実測 `w_mean_pre_norm` = 1.02145。誤差 0.01%。**
位置平均と質量加重が線形に噛み合うので厳密一致が期待でき、実際に一致した。
**`mass_frac_*`・`teacher_coverage`・`w_mean_pre_norm` が同じ物を見ていることの機械的証明。**

### 9.2 Target arm(Jensen 差を含めて整合)

$Z - 1 = 0.25(\sum_{\text{agree\_pos}} p - \sum_{\text{agree\_neg}} p)$ から予測すると:

| | 予測 $\overline{Z}-1$ | 実測 $1/\overline{1/Z} - 1$ | 比 |
|---|---:|---:|---:|
| 全体 | 0.01109 | 0.00884 | 1.25 |
| Alfworld | 0.01209 | 0.00976 | 1.24 |
| Search | 0.01762 | 0.01442 | 1.22 |
| WebShop | 0.00689 | 0.00524 | 1.31 |

**タスク別の順序(Search > Alfworld > 全体 > WebShop)は完全に一致**しており、
比が 1.2–1.3 で揃っているのは `inv_z` が $1/Z$ の**位置平均**であるのに対し予測が
$Z$ の位置平均から来ているため(Jensen の不等式)。

$\mathbb{E}[1/Z] - 1/\mathbb{E}[Z] \approx \mathrm{Var}(Z)$ から逆算すると
$\mathrm{Var}(Z) \approx 0.0022$、すなわち $\mathrm{std}(Z) \approx 0.047$。
**位置ごとの書き換え量は平均(0.011)の約4〜5倍のばらつきを持つ**ということであり、
「全体で TV 0.72%」は個々の位置が一様に 0.7% 動いているという意味ではない。
(この逆算は3桁丸めの上での2次近似なので、桁の主張として読むこと。)

### 9.3 診断と損失が同じ量を見ているか

`sign_weight/teacher_kl`(診断側で集計した生徒→教師の KL)と
`actor/teacher_kl_loss`(実際に損失として backward された値)は別経路で計算されている。
`sign_weight/teacher_kl` は target arm にしか無いので、検算できるのは target のみ。
後半50step平均(step 101–150)で比較すると:

| 対象 | `sign_weight/teacher_kl` | `actor/teacher_kl_loss` | 差 |
|---|---:|---:|---:|
| 全体 | 0.00590 | 0.00614 | 4.0% |
| Alfworld | 0.00498 | 0.00496 | 0.4% |
| Search | 0.02592 | 0.02444 | 5.7% |
| WebShop | 0.00538 | 0.00538 | 0.0% |

**タスク別では 0–6%、Alfworld と WebShop はほぼ完全一致。**集計の重み付けが違う
(診断は有効位置の単純平均、損失は per-task 正規化を通っている)ので厳密一致は
期待できないが、この一致は**診断が損失と同じ分布・同じマスクの上で計算されている**
ことを支持する。全体値の 4.0% は、タスク別が揃っているのに全体だけずれていることから、
タスク間の合成方法の違い(`normalize_loss_by_task`)で説明できる。

## 10. 読み取り — 何が言えて、何が言えないか

### 10.1 言えること

1. **機構は設計通りに発火し、診断は損失と同じ物を見ている**(§9)。
2. **重みが掛かる教師質量は 8.6%。**これは実装の不備ではなく、**教師のRLが分布の頭を
   動かさなかった**という教師側の性質から来る構造的な上限である(§3.2)。
3. **転移可能性行列が測れた**(§6)。Alfworld ↔ WebShop は 0.68–0.76 で共有構造があり、
   Search はどちらとも 0.35–0.49 で共有していない。
   **これは検証の成功率を一切使わずに得られた、タスク間関係の独立な測定である。**
4. **§5 が予告したシャープ化交絡は実在するが小さい**(`inv_z` 0.991、$|\Delta H| \le 0.003$ nats)。
   符号シャッフル対照を符号情報の検定として読む前提は満たされている。
5. **`position` と `target` の状態分布・一致率・資源はすべて一致**しており、
   **2アームは「同じ状態判定に対して重みの掛け先だけが違う」という設計通りの関係にある。**

### 10.2 言えないこと

1. **どちらのアームが良いか。**検証が走っていない(§2.3)。
2. **機構が効いたか。**対照アーム(符号重み無し純OPD)がこの CSV に無い。
3. **`episode/*` の差。**学習中ロールアウトであり、温度も検証プロトコルと違う。
   そもそも2アームの差は step間標準偏差の数十分の一で、**判別限界以下**である。
4. **step単位の細かい軌道**(§4.1 の量子化)。

### 10.3 次に効くとしたらどこか(予測)

**生徒は150stepで教師にほぼ収束した**(`teacher_kl` 0.571 → 0.005 nats)。
純蒸留なので、ここから先は「教師との残り 0.005 nats をどう詰めるか」の局面に入る。
一方で**書き換え量 `target_kl` は 0.001 nats でほぼ一定**なので、
`target_kl_ratio` は 0.003 → 0.252 へと上がり続けている。

したがって **150→300 の区間こそが、target の固定点移動が目的関数を支配する区間である。**
150step で2アームが一致しているのは想定と矛盾しない。
逆に、**300step で差が出なければ、この機構は 8.6% の質量に対する ±25% の重みでは
足りないという結論**になる(その場合の選択肢は §11 の作業5)。

### 10.4 「target > position」の判定に必要なもの

`docs/multitask_signweight_pure_opd.md` §10 の設計通り:

* position ≈ target がともに対照より改善 → 利得は再配分(サンプル効率)であって知識注入ではない
* target > position → 固定点移動が効いている

**この判定には3アーム(対照・position・target)の検証値が要る。**今あるのは2アームの
学習中ロールアウトだけである。

### 10.5 設計上の含意(原稿に書くべきこと)

* **重みは凍結モデルだけの関数ではない。**支持集合が生徒の top-20 なので、生徒が漂えば
  候補集合が変わる。実測でも `frac_agree_pos` が 0.238 → 0.193、
  `search__on__alfworld` が 0.477 → 0.377 と動いている。
  **固定の注釈ではなくフィードバックループである**ことが数字で確認された。
* **`frac` と `mass_frac` は必ず対で報告すること。**Search の `conflict_on_neg` は
  候補数 36.5% / 質量 0.2% で、片方だけ見ると正反対の印象になる。
