# 出力空間の交差ゲート（MOPD 初版）: 純粋 OPD+GRPO の上に、他タスクの役割別 RL 参照による soft 減衰だけを加える

状態: **提案のみ。実装なし。** 本文書は同名の旧版（self gate の上に交差判定を足す案）を置き換える。
置き換えの理由は [opd_pushback_control_review.md](opd_pushback_control_review.md) §9: self gate は片側統計量で発火し、
削る先が報酬の持たない情報で、戻る道を持たなかった。その判断を選択条件として引き継がないために、
**self gate の係数 $a_j$ と「自己対立している token に限る」条件の両方を外す。**

先行: [opd_pushback_output_space_multitask.md](opd_pushback_output_space_multitask.md)（置換案。§7 のオフライン測定で棄却）、
[opd_pushback_cross_protection_design.md](opd_pushback_cross_protection_design.md)（パラメータ空間版）、
理論文書 §4.8.3（役割）、Armandpour et al. 2026（arXiv:2605.10889）。

**問い。** 他タスクの RL 参照を使って OPD の適用箇所と強さを制御することが、純粋 OPD+GRPO より 3 タスクの成績を改善するか。

**これはタスク・役割ごとに正規化した出力空間の競合の制御である。** モデル全体のパラメータ干渉
（$\langle r_i,d_j\rangle$）を再現するという保証は付けない（§7）。新アームは**探索実験**として位置づける。

---

## 1. アームの構成

| 部分 | 扱い |
|---|---|
| GRPO 損失・OPD 係数 β | 純粋 OPD+GRPO と同じ |
| self gate の $a_j$ | **削除** |
| 自己対立を必須にする条件 | **削除** |
| 正の advantage だけを対象にする条件 | 入れない |
| 他タスクの役割別 RL 参照 | 使用（§2） |
| 役割別の交差減衰 $\lambda_{j,c}=1-b_{j,c}$ | step ごとに更新（§4） |
| タスク間の OPD 予算の再配分 | 行わない |
| 初期条件 | 比較する純粋 OPD+GRPO と同じ checkpoint・config・seed から開始。現行 pushback の途中 checkpoint は使わない |
| 追加 forward / backward / 事前校正 | 無し |

**「再配分しない」と「どのタスクも犠牲にしない」は同義ではない。** 自己対立条件を外したので、
「webshop 自身には有益だが alfworld の参照とは対立する OPD」も減衰対象になる。これを防いだとは主張せず、
§9 の指標で失ったものを把握する。自タスクとの整列は**ゲートの条件ではなく、介入で失ったものを測る指標**として使う。

適用する重みは

$$
w_{j,t}=1-\lambda_{j,c(t)}\,h_{j,t},\qquad 0\le\lambda_{j,c}\le\lambda_{\max},\quad h_{j,t}\in[0,1]
$$

で、$h$ は §3 の soft ゲート、$\lambda$ は §4 の制御で決まる。他タスクとの対立が観測されない位置（$h=0$）は基準の OPD をそのまま使う。

## 2. 参照

### 2.1 定義

タスク $i$、役割 $c$ の RL 参照と強度:

$$
v_{i,c}=\operatorname{EMA}\big(\mathbb E_{i,c}[r_{i,t}]\big),\qquad
R_{i,c}=\operatorname{EMA}\big(\mathbb E_{i,c}[\|r_{i,t}\|^2]\big)
$$

* $r_{i,t}=c_t\,(e_{a_t}-p_t)$。係数 $c_t$ は
  [`policy_loss_gradient_coef`](../verl/trainer/ppo/core_algos.py:543) の **clip 後**の値であり、advantage ではない
  （$-A$ が正しいのは最初の mini-batch だけ。現行 run は 6 mini-batch）。
* $d_{j,t}$ は送り手 $j$ の OPD 信号。**β は含め、$\lambda$ は含めない**（制御器が自分の出力を読み戻さない）。
* $\mathbb E_{i,c}$ は padding と重複行を除いた、役割 $c$ の token 上の正規化平均。
* 語彙座標は**実 token ID**。$v_{i,c}$ は $(\text{役割}\times V)$ の疎ベクトルで、判定は $t$ の支持集合への gather。
* **rank をまたいだベクトルを合算してから**参照・ノルム・内積を作る。スカラーを後から all-reduce すると rank 間項が落ちる。
* 参照は前 step の値を step 内で固定。初 step は参照だけ作り $\lambda=0$。

### 2.2 プロンプト集合を分けた二つの参照

参照の再現性を確認するため、各 $(i,c)$ で二つの参照 $v^{(1)},v^{(2)}$（対応する $R^{(1)},R^{(2)}$、$\kappa^{(k)}=\|v^{(k)}\|^2/R^{(k)}$）を持つ。
割り当ては

$$
\mathrm{side}=\operatorname{hash}(\text{分割 seed},\ \text{task},\ \text{安定した prompt ID})\bmod 2
$$

で、**毎 step の再抽選はしない**。毎 step 振り直すと同じプロンプト由来の信号が時間を跨いで両側の EMA に入るため、
固定分割で「異なるプロンプト集合から参照方向が再現するか」を見る。

| 項目 | 仕様 |
|---|---|
| 分割単位 | プロンプト。GRPO 群・軌跡・token を途中で分割しない。同じプロンプトが後の step に再登場しても側を変えない |
| rank との関係 | rank 番号をハッシュに入れず、全 rank で同じ割り当て |
| タスク・役割との関係 | タスク内で分割し、役割別統計はその後に集計 |
| 群数の偏り | 行を捨てたり、均等化のために側を移したりしない |
| 片側が不足 | その受け手・役割の交差参照を**無効**にする（§2.3） |
| 欠測 step | ゼロを EMA に入れず、保持して経過 step を記録 |
| 観測できたが信号がゼロ | **ゼロとして更新する**（欠測と区別する。保持すると RL 信号が消えた後も古い参照が残り続ける） |
| 再開 | 分割 seed、参照 EMA（両側）、観測数・鮮度を保存・復元 |
| 更新重み | $v^{(k)}$ と $R^{(k)}$ は**同じ群集合・同じ EMA 重み**で更新する（§3 の上界の条件） |

これは**厳密な独立標本ではない**。両側とも同じ学習中モデルの影響を受ける。文書上は「プロンプト集合を分けた参照の再現性」と呼ぶ。

制約側（§4）が使う単一の参照は、本文書では両側の平均 $v_{i,c}=\tfrac12(v^{(1)}+v^{(2)})$、$R_{i,c}=\tfrac12(R^{(1)}+R^{(2)})$ と**決める**
（第三の累積器を持たない。この決めは変更可能で、変える場合は明記する）。

### 2.3 参照の有効性

$(i,c)$ の交差参照が**有効**なのは、**直近 8 training step の窓**で、両側それぞれが役割 $c$ について最小プロンプト数・
最小 PG 信号プロンプト数・最小制御対象 token 数を満たし、最終観測からの経過が許容内で、統計が有限かつ $R^{(k)}>0$ のとき。
数値は §8。単一 step で判定すると、固定二分と search の少ない群数によって有効性が頻繁に切り替わるため、短い履歴を使う。

数え方も固定する。

* 同じプロンプトが窓内に再登場しても、プロンプト数には **1 件**として数える。
* PG 信号の有無は advantage ではなく、**実際の clip 後の $r$** で判定する。
* token 数には、制御母集団内の clip でゼロになった token も**含める**。
* padding と、そのための複製行は数えない。
* 条件を満たさない受け手は $\mathcal V_{j,c}$ から除外し、残った有効受け手で平均し直す（§3）。

**κ は記録するが有効性の閾値には使わない**（§3 の通り κ はゲートに乗法で入る）。有効性は step 開始時に確定し、step 内で固定する。
**閾値を自動で下げて参加させない。** search が無効になる期間があっても、無効だった理由と期間を記録するだけにする。

## 3. soft ゲート

送り手 $j$、役割 $c$ に対する有効な受け手の集合を

$$
\mathcal V_{j,c}=\{\,i:\ i\ne j,\ (i,c)\text{ の交差参照が有効}\,\}
$$

とし、各受け手について両側で正規化してから小さい方を取る:

$$
q_{ij,t}=\min_{k\in\{1,2\}}\ \frac{\big[-(v^{(k)}_{i,c})^\top d_{j,t}\big]_+}{\sqrt{R^{(k)}_{i,c}}\,\|d_{j,t}\|+\delta}
$$

両側とも負のときだけ、弱い方の対立強度を採る。$v^{(k)}$ と $R^{(k)}$ を同じ重みで更新する限り、Jensen より
$\|v^{(k)}\|^2=\|\mathbb E r\|^2\le\mathbb E\|r\|^2=R^{(k)}$ なので

$$
q_{ij,t}\ \le\ \min_k\sqrt{\kappa^{(k)}_{i,c}}\ \le\ 1
$$

が成り立ち、$[0,1]$ への収まりに δ 以外の保護は要らない。**二分参照の $q$ を、単一参照の $\sqrt\kappa\cos$ と等置しない。**

受け手の重みは有効受け手の一様平均:

$$
\omega_{ijc}=\begin{cases}1/|\mathcal V_{j,c}| & i\in\mathcal V_{j,c}\\ 0 & \text{それ以外}\end{cases},
\qquad
h_{j,t}=\sum_{i\ne j}\omega_{ijc}\,q_{ij,t}
$$

* RL 強度・タスクの token 数・κ による追加の重み付けはしない。**強度は既に $q$ と制約に入るので、$\omega$ でタスクの優先順位を追加しない。**
* 有効性と重みは step 開始時に確定し、step 内で固定。受け手が一つ欠けたら残りで平均し直す。有効受け手が無ければ $h=0$。
* 平均するため、一つの受け手への対立が薄まりうる。各受け手への保護は §4 の制約で個別に扱う。
* これは統計的有意性の保証ではない。信頼性と強度をゲートに反映する、明示的な設計上の選択である。
* **交差制御する役割は `format` と `env_action` のみ**（§8.5）。それ以外の役割は $h_{j,t}=0$、$\lambda_{j,c}=0$ で基準の OPD をそのまま使う。

**上界の帰結。** 減衰は token あたり最大 $\lambda_{\max}\sqrt{\kappa}$。κ が小さい参照ではゲートは自動的に弱まる（§5）。
同時に、**介入の実際の上限を決めるのは $\lambda_{\max}$ ではなく $\sqrt\kappa$ である**可能性が高い。
精度が baseline と変わらなかったとき、「機構が無効」と「ほぼ何も削っていない」を分けるのは §9 の保持量と κ の記録だけになる。

## 4. 制御: 負の部分を減らすのではなく、符号付きの合計寄与を改善する

受け手 $i$ に対する基準の交差量と、減衰で取り除く交差量:

$$
B_{ijc}=\mathbb E_{j,c}\big[v_{i,c}^\top d_{j,t}\big],\qquad
D_{ijc}=\mathbb E_{j,c}\big[h_{j,t}\,v_{i,c}^\top d_{j,t}\big]
$$

固定参照・固定ゲートの下で、適用後の量は $B_{ijc}-\lambda_{j,c}D_{ijc}$。$D$ は符号混合でありうる —— 受け手 $k$ のせいで $h>0$ になった位置で
$v_{i}^\top d>0$ なら、減衰は受け手 $i$ への正の寄与を失わせる。**ある受け手を助けるための減衰が別の受け手を損なうことが、制約に入る。**

受け手ごとの条件（スラック $\xi\ge0$ は条件未達）:

$$
\sum_{j\ne i}\big(\bar B_{ijc}-\lambda_{j,c}\bar D_{ijc}\big)\ \ge\ -\varepsilon_{\rm cross}\,\bar R_{i,c}-\xi_{i,c}
$$

### 4.1 スラックの消去と目的関数

固定した $\lambda$ に対する最適スラックは解析的に

$$
\xi_{i,c}=s_{i,c}(\lambda)=\Big[-\varepsilon_{\rm cross}R_{i,c}-\sum_{j\ne i}B_{ijc}+\sum_{j\ne i}\lambda_{j,c}D_{ijc}\Big]_+
$$

なので、役割 $c$ ごとに解く問題は

$$
\min_{0\le\lambda_{j,c}\le\lambda_{\max}}\ \Big\{\sum_j K_{j,c}\,\lambda_{j,c}^2+\rho\sum_{i\ \mathrm{valid}}\Big(\frac{s_{i,c}(\lambda)}{R_{i,c}+\delta}\Big)^2\Big\},
\qquad
K_{j,c}=\frac{\mathbb E_j\big[\mathbf 1[c(t)=c]\,h_{j,t}^2\|d_{j,t}\|^2\big]}{\mathbb E_j\big[\|d_{j,t}\|^2\big]+\delta}
$$

* $K_{j,c}$ は**取り除く出力ベクトルの二乗ノルム**を送り手の OPD エネルギーで正規化したもので、役割割合を含む。
  $\|b-\mathbf 1\|^2$ では強い OPD を大量に削る場合とごく弱い OPD を少量削る場合を区別できないため、これに替える。
* 第 2 項は教師信号を残すことと交差条件の未達を減らすことの明示的な比較。$\rho$ は実験条件（§8）。
* **各役割で最大 3 変数の box 制約付き凸問題**。スラック消去後は単一の二次式ではなく**区分的二次の凸目的**。
  一つの送り手の減衰量が複数の受け手制約に入るので、一般に複数の制約が結合する —— 単一乗数の探索で解ける問題ではない。
  CPU の float64 で、backtracking 付き射影勾配法などで十分小さく解ける。

### 4.2 減衰の上限

初回は暫定的に $\lambda_{\max}=0.2$（$b_{\min}=0.8$）。最適値の主張ではなく、**未検証の代理指標による介入を限定する実験条件**。
条件を満たせなくても上限を突破させない —— 出力空間の代理指標を満たすために教師信号を無制限に削ることを優先しない。
係数の 20% 減衰でも二乗ノルムはその位置で最大 36% 減るため、小さな介入と決めつけず、実際の保持量を記録する（§9）。

### 4.3 実装条件

* 統計は全 rank 集約後の同じ値を使う。一つの rank で解き、係数を broadcast する。
* 非有限値・未収束時は、その役割を $\lambda=0$ にして理由を記録する。
* 解が不定になる未観測・無介入の変数は $\lambda=0$ を選ぶ。
* 係数と参照は step 内で固定。当該 step の統計から次 step の係数を更新する。
* 適用係数、介入コスト $K\lambda^2$、受け手別スラック $s_{i,c}$、予測値と適用後の実測値を保存する。
  **これは過去の統計に基づく次 step の制御であり、次 step の実測量が条件内に収まる保証はない。**

## 5. 定義から言えることと、言えないこと

**言える。** 推定された基準交差量が、すべての保護条件を既に満たす場合（$s_{i,c}(0)=0$ がすべての有効な $i$ で成り立つ場合）、
無介入の $\lambda=0$ が最適解になる。$K\ge0$ なので目的の第 1 項は $\lambda=0$ で最小、第 2 項もゼロ。

**言えない。** 「雑音参照なら必ず不活性」は証明できない。有限標本の雑音参照では $B$ が偶然負になり、ゲートによる選択で $D$ も偏りうる。
言えるのは、κ が小さければ $q$ の上界が小さく（§3）、介入の大きさが縛られる、というところまで。

**解放について。** EMA が更新されて無介入で条件を満たすようになれば $\lambda\to0$ に戻る。これは即時・単調な回復の保証ではない。
self gate（[opd_pushback_control_review.md](opd_pushback_control_review.md) §9.4）との違いは、規則が読む量が符号付きであり、
対立が消えれば量もゼロへ行く構造になっていること。

## 6. 役割の実体（コードの帰結、予測ではない）

[`sign_weights.py:2556`](../verl/trainer/ppo/sign_weights.py:2556) の役割は **6 個**。参照本体は 3 タスク × 6 役割 × 2 側 × 151,936 × fp32 ≈ 21.9 MB、
交差判定に使う 3 役割に限れば 10.9 MB。生成 token に実際に付くのは 4 個で、2 個は構造的に空になる。

| 役割 | 保持するタスク | 備考 |
|---|---|---|
| `format` | 3 タスク全部 | イベントの 74〜96%、OPD push 質量の **97%**。**実体は推論文**（下記） |
| `env_action` | alfworld, webshop | search は持たない。OPD push 質量の 0.7% |
| `tool_call` | search のみ | `<search>` の呼び出しと `<answer>` の最終回答が**混在**。交差相手を持たない |
| `tag` | 3 タスク全部 | タグ自身のトークン。純粋構文。**交差判定から除外** |
| `reasoning` | なし | 下記のタグ不一致により一度も開かない（`opd/role/reasoning/*` が 43 step 中 1 step・kl_share 0） |
| `env_obs` | なし | 1 行 = 1 turn なので観測は次 turn の prompt 側に入り `responses` に無い |

**`reasoning` が空になる理由はタグ照合の不一致。** `<think>` の id は Qwen3 の特殊トークン `[151667]` だが、モデルはリテラル文字
（id 13708 `<th` 始まり）で書くため [`token_roles`](../verl/trainer/ppo/sign_weights.py:2592) が span を開かない。
結果として推論文はすべて `format` に落ちる。**3 タスク共有の唯一の内容役割は、書式ではなく推論スタイルの参照である。**

初版では `env_action` と `tool_call` を統合しない。統合には「異なる役割どうしの比較が意味を持つ」という新しい仮定が要る。
したがって **search が参加するのは `format` だけ**で、環境行動の役割では送受いずれにもならない。この拡張だけで 3 タスクの内容レベルの干渉を網羅する設計ではない。

## 7. 正規化: この量が何であって何でないか

### 7.1 条件付き平均は損失の交差項に比例しない

[`task_loss_weights.py:129`](../verl/trainer/ppo/task_loss_weights.py:129) の行重みは $w_j=M/(K\,T_j)$（$M$=mini-batch 数、$K$=タスク数）でタスク内は定数。
役割 $c$ に限ると $\sum_{t\in(j,c)}w_j\,x_t=\tfrac MK\,P_j(c)\,\mathbb E_{j,c}[x]$ で、**役割占有率 $P_j(c)$ が残る**
（env_action は alfworld 2.6% / webshop 12.6%）。§4 の $K_{j,c}$ はこれを含み、制約は役割ごとの条件付き平均で置く。

さらに、**出力空間の異なる位置どうしの内積にはパラメータへの Jacobian が入っていない。** 正規化を合わせても損失交差項には等しくならない。
これは測定済み（[opd_pushback_cross_task_extension.md](opd_pushback_cross_task_extension.md) §9: 出力層 proxy と全モデル交差項の符号一致は
交差ペアで 4/8・4/8・2/8、root が担う大きさは 0.1〜3.5%、質量の 60% は layer 0–8）。

> タスク・役割ごとに正規化した出力空間の競合を制御する。役割の出現頻度とは別に保護条件を置く。

### 7.2 $\varepsilon_{\rm cross}$ が縛るもの

役割ごとの条件が成り立てば、受け手の $P_i(c)$ で混合したタスク水準の相対条件も成り立つ。
**損失単位では合成しない**（左辺は送り手の $P_j(c)$、右辺は受け手の $P_i(c)$ を要する）。$\varepsilon_{\rm cross}$ は正規化された量に対する許容であって、損失に対する予算ではない。
初版は $\varepsilon_{\rm cross}=0$（§8.1）なので、条件は「正味の交差寄与を負にしない、スラックの分だけ未達を許す」という形になり、
許容量の水準を事前に決める問題そのものが消える。代わりに、どれだけ未達を許すかは $\rho$ と介入コストの比較で決まる。

### 7.3 残る非対称

$v$ は平均（相殺でも支持の分散でも小さくなる）、$R$ は平均エネルギー（どちらでも小さくならない）。直交支持の極限で $\kappa\to1/n_{\rm eff}$ なので、
**RL 信号が多数の相異なる語彙に広がる受け手ほど $q$ の上界が小さく、保護が弱くなる。** 報酬方向の非整合ではなく支持の多様性だけで起こる。
既定として許容するが、$n_{\rm eff}$ と相異 ID 数を κ と併記する。

## 8. 事前固定条件（MOPD 初版）

**尺度に基づく設定であり、性能最適化済みではない。** 事前 run で作動点を探すのではなく、意味を説明できる固定条件で開始する。
最適値の主張ではなく、最初の探索実験の設定である。

### 8.1 制御

| 条件 | 初版 | 意味 |
|---|---:|---|
| $\varepsilon_{\rm cross}$ | **0** | 正味の負の交差寄与を、制御上の改善対象にする |
| $\rho$ | **$10^{4}$** | β=0.01 によるスラック二乗の尺度縮小を補う（§8.2） |
| $\lambda_{\max}$ | **0.2** | 各 token の減衰を $0.2\,h$ 以下に限定する |
| 基準 β | **0.01 で維持** | OPD 自体の強さは変えない |

$\varepsilon_{\rm cross}=0$ とするのは、今回は正負を合算した交差量（§4）を使うためである。
事前の測定なしに「どれだけの負なら許容するか」という閾値を追加せず、**負の寄与の改善と、教師信号を失う費用を $\rho$ で比較する**構成にする。
**ε=0 でも負の交差量を必ず解消するわけではない** —— 介入コスト $K\lambda^2$、減衰上限 $\lambda_{\max}$、スラック $\xi$ があるため、
基準の OPD を残して条件未達を許容できる。

### 8.2 ρ の根拠: β の尺度差を一度だけ補正する

$d=\beta\tilde d$ と置き、数値保護項の影響を無視できる範囲では

$$
B,\ D\ \propto\ \beta,\qquad h\ \text{は }\beta\text{ に不変},\qquad K\ \text{も }\beta\text{ に不変}
$$

（$q$ は分子・分母とも β に比例するので不変、$K$ は分子・分母とも $\beta^2$ に比例するので不変）。$\varepsilon_{\rm cross}=0$ ではスラックも β に比例し、
$R$ は β を含まないので

$$
\Big(\frac{s}{R}\Big)^2\ \propto\ \beta^2
$$

となる。**$\rho=1$ では、介入コストには残らない $\beta^2$ が条件未達の罰則にだけ残る。** β=0.01 ならその係数は $10^{-4}$。そこで

$$
\rho=\frac{1}{\beta_0^{2}}=10^{4},\qquad \beta_0=0.01
$$

とする。罰則を $\big(s/(\beta_0 R)\big)^2$ として評価することと同じである。

* これは両項を必ず同程度にする設定ではなく、**既知の β の尺度差を一度補正する**設定である。
  参照の相殺や、RL と OPD の実際の強度差までは補正しない。
* この導出は $\varepsilon_{\rm cross}=0$ に依存する。$\varepsilon>0$ では $s$ に β を含まない $-\varepsilon R$ の項が入るので、$\beta^2$ の比例は崩れる。
* **将来 β を変更する場合も $\rho$ を自動変更せず、別の実験条件として扱う。**

### 8.3 参照の有効性（片側ごと。数え方は §2.3）

| 条件 | 初版 |
|---|---:|
| 群数・token 数を数える期間 | **直近 8 training step** |
| 最小プロンプト数 | **各側・各役割で異なるプロンプト 4 件** |
| そのうち PG 信号を持つプロンプト | **各側で 2 件以上** |
| 最小制御対象 token 数 | **各側・各役割で 64 token** |
| 最終観測からの許容経過 | **2 step 以内** |
| κ による有効性閾値 | **設けない** |
| 追加条件 | 両側の統計が有限で、$R^{(k)}>0$ |

**これらの数値は信頼区間や有意性を保証するものではない。** 一つのプロンプトや、古い参照だけで他タスクを制御しないための初期条件である。

### 8.4 EMA

| 項目 | 初版 |
|---|---|
| $v^{(1)},v^{(2)},R^{(1)},R^{(2)}$ | EMA 減衰 **0.8** |
| $B,\ D$ | EMA 減衰 **0.8** |
| $K$ の構成統計 | EMA 減衰 **0.8** |
| 初期化 | 最初の有効な観測値 |
| 欠測 | 更新せず保持 |
| 観測できたが信号がゼロ | **ゼロとして更新** |

減衰 0.8 の半減期は約 3.1 観測。参照と交差統計の両方を平滑化するため、初版では 0.9 より反応を速くする。それでも二段の平滑化と 1 step 遅延は残る。

$K$ は step ごとの比をそのまま EMA するのではなく、**分子・分母を別々に更新してから比を取る**:

$$
K_{j,c}=\frac{\operatorname{EMA}\big(\mathbb E_j[\mathbf 1[c(t)=c]\,h^2\|d\|^2]\big)}{\operatorname{EMA}\big(\mathbb E_j[\|d\|^2]\big)+\delta}
$$

「欠測」と「観測されたゼロ」の区別が重要である。後者まで保持すると、RL 信号が消えた後も古い参照が残り続ける。

### 8.5 数値保護・分割・対象役割

| 条件 | 初版 |
|---|---|
| δ | **$10^{-30}$**。物理的な信号不足の閾値としては使わない |
| 分割 seed | **1** |
| ハッシュ | **SHA-256 など、プロセス間で安定したもの。Python 組み込みの `hash()` は使わない** |
| ハッシュ入力 | 分割方式の version、seed、task、安定した prompt ID |
| 交差制御する役割 | **現行分類の `format` と `env_action`** |
| `tag` / `tool_call` など | **交差制御しない** |
| 初 step | 参照収集のみ、$\lambda=0$ |
| 更新頻度 | 毎 step 更新、次 step に適用 |

δ でゼロ除算をごまかすのではなく、$R=0$、$\|d\|=0$、OPD エネルギーがゼロのケースは**先に分岐する**。δ は残る数値計算の保護だけに使う。
固定 seed だけではプロセスを跨いだ同じ分割を保証できないので、`hash()` は使わない。

run 中に役割分類も変更すると、機構と母集団を同時に変えることになる。
**初版は §6 に記載した現行分類で固定し、`format` を純粋な書式とも純粋な推論とも解釈しない。**

### 8.6 run 中の確認と、設定を動かさない規約

5・10・20・40 step で、次の三段階を**分けて**確認する。

| 段階 | 主に見る値 |
|---|---|
| 参照が使えているか | 有効率、群数、鮮度、両側参照の cosine |
| 制御器が減衰を要求しているか | $\lambda$、基準スラック $s(0)$、適用後スラック |
| 実際に OPD が変わったか | $h$、$\lambda h$、保持量、除去コスト |

$\lambda=0.2$ に張り付いていても $h$ が小さければ実際の介入は小さい。逆に $\lambda$ が小さくても、強い OPD に集中していれば無視できない。

**動かなかったから $\varepsilon$・$\rho$・上限を途中で変える運用はしない。** 変更が必要なら、元の条件の結果を残したうえで別アームにする。
3 タスクの改善判定には**共通条件の評価**を使い、学習時の `episode/*_success_rate` とは区別する。

## 9. 記録する指標

**介入で失ったもの**（シーソーが起きた理由を、self gate を再導入せずに確認する）

| 指標 | 何を答えるか |
|---|---|
| `cross/lambda/{task}/{role}`、`cross/K/{task}/{role}` | 適用した減衰と介入コスト |

## 10. 事前予測（探索的）

**介入量は $\sqrt\kappa$ で縛られるため小さいと予想される。** 実 κ（$-p$ 項込み）は未測定で、e_a 近似の 0.001〜0.05 を目安にすると
係数の減衰は最大でも数%。精度差が出なかった場合、その理由が「削っていない」なのかは §9 の保持量で判定する。

**webshop の係数が最も下がる、という予測は探索的に登録するが、成功条件にはしない。**
step 300 のパラメータ空間 $C_{ij}=\langle r_i,d_j\rangle$（N=8、非正規化）では webshop の OPD 列だけが全行で負（t = −2.83 / −2.53 / −1.75）だった。
しかし checkpoint・空間・集約粒度（タスク全体 vs 役割別・token 選択後）・基準対立量 vs 最適減衰量・非正規化 vs cosine、
のすべてが違うので、webshop が最も下がらなかったことだけで代理指標の失敗とは扱わない。「過去の観測と整合するか」の補助的な読みに留める。

**比較対象。** 純粋 OPD+GRPO は `sdar_multitask_opd_grpo_qwen3_1.7b`（wandb `ktrcnege`、298 step、
`cross_teacher_kl_weight` / `pushback_control` / `task_diag` すべて null）として存在する。ただし 8 月の run であり、
同一 config・初期条件だけで時期や実行環境の差を除いた因果比較が成立するわけではない（webshop の応答長に era shift がある）。

（共有 ID 数は集合の重なりで、内積を決めるのは共有座標に載る勾配の重み）。

### 11.1 撤回: dump から計算した κ は参照の有効性判定に使えない

イベント dump から $r_t=A_t(1-p_t)e_{a_t}$ として計算した $\kappa=0.0013\sim0.0472$ を「参照方向がほぼ雑音」と読んだのは誤り。

* この近似では各 token が 1 座標のスパイクなので、ID が相異なれば $\kappa=1/n$ が恒等的に成り立つ。実測 $\kappa\cdot n$ は 0.85〜1.45。
* $-p_t$ 項を落としている。$c_t$ は報酬由来なので $-c_tp_t$ も PG 方向の一部。
* clip 後の係数ではなく advantage を使っている。dump は ratio も `old_log_prob` も持たないので $c_t$ はオフラインで復元できない。
* イベント dump は軌跡 uid も群 id も持たないので、プロンプト集合を分けた参照の一致はオフラインでは測れない。§9 の指標はすべて in-run。

## 12. 限界

* $v_{i}^\top d_{j,t}$ は head ブロックの量の $h_s\cdot h_t$ を役割一致の重みに置き換えた形。別のカーネルへの置換であって、モデル全体の干渉を再現する根拠は無い（§7.1）。
* 同じ語彙・同じ役割で集約した RL 方向を他タスクの参照として使えるという仮定は未検証。役割を揃えても状態の意味は一致しない。
* search は `format` にしか参加しない。`tool_call` は交差相手を持たず、内部で既に不均質。
* 判定は 1 step 遅れの参照に基づく局所量で、次 step の損失変化を保証しない。
* 二分参照は独立標本ではない。両側とも同じ学習中モデルの影響を受ける。
* 参照が不安定だった場合の結論は「この役割分割・集約・標本数では安定した参照が得られなかった」まで。
  「他タスクに使える RL 方向が存在しない」とは言えない。
* 採否は 3 タスクの評価精度で決める。ここで記録する量はどれも代理である。
