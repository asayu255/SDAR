# 出力空間の交差ゲート: 役割別 RL 参照による、自タスク対立の部分集合への追加減衰

状態: **提案のみ。実装なし。** 現行機構（`ARM=pushback`、`f7333cb`）の self gate をそのまま残し、その上に交差判定を足す。
追加 forward / backward / rollout / 事前校正は無い。

先行: [opd_pushback_output_space_multitask.md](opd_pushback_output_space_multitask.md)（置換案。§7 のオフライン測定で棄却）、
[opd_pushback_cross_protection_design.md](opd_pushback_cross_protection_design.md)（パラメータ空間版）、
理論文書 §4.8.3（役割）、Armandpour et al. 2026（arXiv:2605.10889）。

**これはタスク・役割ごとに正規化した出力空間の競合の制御である。** モデル全体のパラメータ干渉
（$\langle r_i, d_j\rangle$）を再現するという保証は付けない。§2 の通り、正規化を揃えてもパラメータ空間の
損失交差項には等しくならない。その保証が要るならパラメータ空間版（追加 backward あり）。

## 0. 機構

$$
w_{j,t}=w^{\rm self}_{j,t}\cdot\begin{cases}b_{j,c(t)} & t\in H_j\\ 1 & \text{otherwise}\end{cases},
\qquad 0\le b_{j,c}\le 1
$$

* $w^{\rm self}$ は現行のまま（$u^{RL}_{j,t}\cdot u^{OPD}_{j,t}<0$ の token に $a_j$）。$b\equiv1$ で現行と一致。
* $H_j$ は**自タスクでも対立し、かつ他タスクの参照とも対立する** token。自タスクと明確に整列する token を、
  他タスクの参照だけを理由に減衰させない。「alfworld を助けるために webshop 自身が必要とする OPD を削る」を構造で防ぐ。
* **係数は役割別 $b_{j,c}$。** format の競合を理由に下がった係数が env_action の対象 token に及ぶのを防ぐ。
  役割ごとに独立な小問題へ分解され、追加費用はゼロ。
* $b_{j,c}$ は教師全体ではなく $H_j$ にだけ掛かる。タスク間の予算移動はしない。増幅もしない。

扱えない対立が残る: 自タスクを助け、他タスクを妨げる token は初版では解消しない。これは意図した保守性である。

## 1. 参照ベクトルと交差判定

役割 $c$ ごとに、タスク $i$ の RL 参照と強度を持つ。

$$
v_{i,c}=\operatorname{EMA}\big[\mathbb E_{i,c}[u^{RL}]\big],
\qquad
R_{i,c}=\operatorname{EMA}\big[\mathbb E_{i,c}[\|u^{RL}\|^2]\big]
$$

$$
x^{\rm self}_{j,t}=(u^{RL}_{j,t})^\top u^{OPD}_{j,t},
\qquad
x^{\rm cross}_{i,j,t}=v_{i,c(t)}^\top u^{OPD}_{j,t}
$$

$$
A^-_{ijc}=\operatorname{EMA}\Big[\mathbb E_{j,c}\big[w^{\rm self}_{j,t}\,[-x^{\rm cross}_{i,j,t}]_+\big]\Big]
$$

* $\mathbb E$ は padding を除いた正規化済みの重み付き平均。$u^{OPD}$ は $\beta$ 込み、$b_{j,c}$ 抜き
  （制御器が自分の出力を読み戻さない）。$u^{RL}$ の係数は
  [`policy_loss_gradient_coef`](../verl/trainer/ppo/core_algos.py:543) の **clip 後**の $c_t$ であり、advantage ではない。
* 語彙座標は**実 token ID** で揃える。top-k 配列の第 1 要素どうしを比較しない。$v_{i,c}$ は $(\text{役割}\times V)$ の
  疎ベクトルで、判定は $t$ の支持集合 20 個への gather。
* **rank をまたいだベクトルを合算してから**参照・ノルム・内積を作る。スカラーを後から all-reduce すると rank 間項が落ちる。
* cosine ではなく**負の内積の大きさ**を使う。弱い方向と強い方向を同等に扱わない。
* 参照は前 step の値を step 内で固定。初 step は交差ゲート無効で参照だけ作る。

### 1.1 役割の実体（コードの帰結、予測ではない）

[`sign_weights.py:2556`](../verl/trainer/ppo/sign_weights.py:2556) の役割は **6 個**
（format / reasoning / env_action / tool_call / env_obs / tag）。参照本体は 3 タスク × 6 役割 × 151,936 × fp32 = **10.9 MB**、
交差判定に使う 3 役割に限れば 5.5 MB。生成 token に実際に付くのは 4 個で、2 個は構造的に空になる。

| 役割 | 保持するタスク | 備考 |
|---|---|---|
| `format` | 3 タスク全部 | イベントの 74〜96%。**実体は推論文**（下記） |
| `env_action` | alfworld, webshop | search は持たない |
| `tool_call` | search のみ | `<search>` の呼び出しと `<answer>` の最終回答が**混在** |
| `tag` | 3 タスク全部 | タグ自身のトークン。純粋構文。**交差判定から除外** |
| `reasoning` | なし | 下記のタグ不一致により一度も開かない |
| `env_obs` | なし | 1 行 = 1 turn なので観測は次 turn の prompt 側に入り `responses` に無い |

**`reasoning` が空になる理由はタグ照合の不一致である。** `<think>` の id は Qwen3 の特殊トークン `[151667]` だが、
モデルはリテラル文字（id 13708 `<th` 始まり）で書くため [`token_roles`](../verl/trainer/ppo/sign_weights.py:2592) が
span を開かない（xt1 60 step の応答で 151667 は出現 0 回）。結果として推論文はすべて `format` に落ちている。
`format` の最頻標本トークンは alfworld で `' to' ' the' ' need' ' next' ' I' ' which' ' examine'`。
**3 タスク共有の唯一の内容役割は、書式ではなく推論スタイルの参照である。** これは実験条件として記録する。

### 1.2 参照の有効性判定

**$\kappa=\|\mathbb E[r]\|^2/\mathbb E[\|r\|^2]$ の固定閾値で参照を無効化しない。** $\kappa$ が小さいのは、
異なる位置が異なる語彙を押すことでも、正負の相殺でも起きる。**平均方向の推定誤差を測ってはいない。**
（§7 の通り、e_a 項のみの近似では $\kappa n\equiv 1$ が恒等的に成り立つ。）

判定は次の 4 つを分けて見る。微小信号に対する数値的保護と、推定の安定性の判定を混ぜない。

| 指標 | 確認すること |
|---|---|
| $\kappa_{i,c}$ | 個々の信号に対して平均方向がどの程度残るか（記録するが単独では判定しない） |
| 有効プロンプト群数・群ごとの寄与の偏り | 少数の群だけで参照が決まっていないか |
| 異なる群集合から作った参照の一致 | 平均方向が再現するか。**GRPO プロンプト群単位**で分割する |
| 参照更新の前後で交差判定が変わる割合 | 実際のゲート判断が安定しているか |

有効な参照を持たない $(i,c)$ には制約を課さず、既定 $b_{j,c}=1$。**課さなかった $(i,c)$ の割合を記録する**
（これが「機構が何もしなかった」と「何もしなくてよかった」を分ける唯一の列）。
追加 forward / backward は不要だが、集計と保持する統計の費用は増える。

## 2. 正規化: この量が何であって何でないか

**単位ベクトル化して $\sum_t\|u_{OPD}\|$ を分母にする案は採らない。** それは OPD ノルム加重の「逆向き cosine の平均」で、
$\beta$ もタスク $i$ の RL 強度も消え、分母が受け手 $i$ ではなく送り手 $j$ の量になるため、逐タスク制約に差し替えられない。
方向の診断としては有用なので指標には残す（§4）。

**分母は $\|\mathbb E[u^{RL}]\|^2$ ではなく $\mathbb E[\|u^{RL}\|^2]$。** self gate の $R_j=\sum_t\|u_{R,t}\|^2$ が
同じくトークンごとのエネルギー和であることと整合する。

### 2.1 条件付き平均は損失の交差項に比例しない

[`task_loss_weights.py:129`](../verl/trainer/ppo/task_loss_weights.py:129) の行重みは
$w_j=M/(K\,T_j)$（$M$=mini-batch 数、$K$=タスク数）でタスク内は定数。役割 $c$ かつ制御対象 token に限ると

$$
\sum_{t\in(j,c,\mathrm{ctl})} w_j\,r_t
=\frac{M}{K}\;P_j(c,\mathrm{ctl})\;\mathbb E_j\!\left[r_t\mid c,\mathrm{ctl}\right]
$$

**条件付き平均だけでは、役割・制御対象 token の出現割合 $P_j(c,\mathrm{ctl})$ が抜ける。**
役割を落とした和では $\sum_c P_j(c)=1$ で消えるが、役割ごとには消えない。
（実測の役割占有率: env_action は alfworld 2.6% / webshop 12.6% で **4.8 倍**違う。丸め誤差ではない。）

さらに、**出力空間の異なる位置どうしの内積にはパラメータへの Jacobian が入っていない。**
正規化を合わせても、実際のパラメータ空間の損失交差項に等しくなるわけではない。
これは導出上の欠落ではなく測定済みの事実である
（[opd_pushback_cross_task_extension.md](opd_pushback_cross_task_extension.md) §9: 出力層 proxy と全モデル交差項の符号一致は
交差ペアで 4/8・4/8・2/8 ＝偶然水準、root が担う大きさは 0.1〜3.5%、質量の 60% は layer 0–8）。

したがって本設計の位置付けは次の一文に限る。

> タスク・役割ごとに正規化した出力空間の競合を制御する。役割の出現頻度とは別に保護条件を置く。

役割別平均を使う設計自体は残す。ただし「実際の損失への比例」を根拠にしてはならない。

### 2.2 $\varepsilon_{\rm cross}$ が縛るもの

各役割で条件付き平均の形で $A^-_{ijc}\le\varepsilon R_{i,c}$ が成り立てば、

$$
\sum_c P_i(c)\,A^-_{ijc}\ \le\ \varepsilon\sum_c P_i(c)\,R_{i,c}
$$

なので、**$\varepsilon_{\rm cross}$ は役割水準でもタスク水準でも成立する相対予算**である。
一方これは**損失単位では合成しない**: 左辺は送り手の $P_j(c)$、右辺は受け手の $P_i(c)$ を要し、両者は一致しない。
$\varepsilon_{\rm cross}$ は正規化された量に対する予算であって、損失に対する予算ではない。

### 2.3 残る非対称に名前を付ける

分子は $u^{RL}$ の**平均**（相殺でも支持の分散でも小さくなる）、分母は**平均エネルギー**（どちらでも小さくならない）。
直交支持の極限では比が $1/n_{\rm eff}$ に落ちるので、**RL 信号が多数の相異なる語彙に広がる受け手ほど
$A^-/R$ が小さくなり、保護が弱くなる。** これは報酬方向の非整合ではなく支持の多様性だけで起こる。
既定として許容するが、性質として記録し、$n_{\rm eff}$ と相異 ID 数を $\kappa$ と併記する。

## 3. 係数の決定

現行 self gate の $a_j$ を維持し、**役割 $c$ ごとに**、有効な参照を持つ受け手 $i$ について

$$
\min_{0\le b_{j,c}\le1}\ \tfrac12\sum_j\left(b_{j,c}-1\right)^2
\qquad\text{s.t.}\qquad
\sum_{j\ne i} a_j\,b_{j,c}\,\overline{A^-}_{ijc}\ \le\ \varepsilon_{\rm cross}\,\overline{R}_{ic}
$$

* 正負を相殺しない。他タスクへの OPD 予算の移動はしない。自己対立かつ交差対立の部分だけ追加減衰する。
* 係数と参照は step 内で固定。当該 step の統計から次 step の係数を更新する。追加 forward / backward は行わない。
* **これは過去の統計に基づく次 step の制御である。** 参照もデータも変わるため、次 step の実測量が制約内に収まる保証はない。
  予測値と適用後の実測値を両方記録する。

**解法にソルバは要らない。** env_action を持つのは alfworld と webshop だけなので、この役割の制約は受け手ごとに**1 変数**で閉形式。
format / tag は送り手 2 個の 2 変数で、box ∩ 半空間への射影＝乗数の 1 次元二分法。

**$b_{\min}$ は次のどちらかを明示する。** 「床を追加すればよい」では不十分で、$b_{\min}>0$ は元の制約を実行不能にしうる。

* $b_{\min}=0$: 対象 token の OPD を全遮断し得るが、元の制約の実行可能性を保つ。
* $b_{\min}>0$: 保護条件の未達を許し、その量を明示的に記録する。

正の床が精度面で優れているという証拠はまだ無い。床は実験上の選択である。

**初版はゲートを二値のまま維持する。** 微小な負の内積で一律に減衰する問題はあるが、soft 化するなら
制約側の統計も変えなければならない。ゲートを $h_{j,t}\in[0,1]$（自己対立していない位置では必ずゼロ）とすると
$w_{j,t}=w^{\rm self}_{j,t}\left[1-(1-b_{j,c(t)})h_{j,t}\right]$ となり、対応する負の量は
$A^-_{ijc}=\mathbb E_{jc}\big[h_{j,t}[-x^{\rm cross}]_+\big]$ である。**ゲートだけ soft にして二値用の統計を流用してはならない。**
また内積の閾値を「$R$ の分位」で決めるだけでは参照と OPD の尺度差を処理できない。平滑化を入れるならその尺度を別途定義する。

**$\varepsilon_{\rm cross}$ は実験条件として設定する。** self gate の $\varepsilon$（=0.003）とは集約方法が違うので数値を流用しない。
決めるための別の事前 run は課さない。通常学習中に作動率・制約未達・保持量を確認する。
値を分位からオンラインで決める場合は「一定の押し戻しを許容する制御」から「相対的に強い対立を選ぶ制御」へ意味が変わるため、
**別設計として扱う。**

$H_j$ の外にも負の交差寄与は残る。その残存量（`cross_residual`）を別に記録し、
「制御対象の押し戻しが条件内」と「全交差押し戻しが条件内」を混同しない。

## 4. 記録する指標

**作動と量**

| 指標 | 何を答えるか |
|---|---|
| `cross/ab_applied/{task}/{role}` | **実際に適用された積 $a_j b_{j,c}$**。$b$ 単独では self gate の動きと分離できない |
| `cross/b/{task}/{role}`、`cross/a/{task}` | 上の内訳 |
| `cross/skipped_frac`、`cross/infeasible` | 有効な参照が無く制約を課さなかった $(i,c)$ の割合と、制約が両立しなかった step |
| `cross/gate_frac/{task}/{role}` | $H_j$ が control 母集団に占める割合 |
| `cross/kl_removed/{task}/{role}`、`cross/dd_removed/{task}/{role}` | **実効的な減衰量**: 交差ゲートで落ちた KL 量と $\|u^{OPD}\|^2$ |
| `cross/A_neg/{i}/{j}/{role}`、`cross/R/{i}/{role}`、`cross/ratio/{i}/{role}` | 制約の両辺 |
| `cross/predicted_vs_realized/{i}/{role}` | 次 step で実測した左辺と、係数決定時の予測値 |
| `cross/residual/{i}` | $H_j$ 外に残った負の交差寄与 |

**参照の安定性**（§1.2 の 4 指標）

| 指標 | 何を答えるか |
|---|---|
| `cross/kappa/{i}/{role}`、`cross/n_eff/{i}/{role}`、`cross/n_distinct/{i}/{role}` | 平均方向の残り方と、その分母になっている支持の広さ |
| `cross/group_count/{i}/{role}`、`cross/group_gini/{i}/{role}` | 有効プロンプト群数と寄与の偏り |
| `cross/ref_split_cos/{i}/{role}` | GRPO プロンプト群を 2 分割して作った参照どうしの一致 |
| `cross/decision_flip_frac/{i}/{role}` | 参照更新の前後で交差判定が変わった token の割合 |
| `cross/small_dot_frac/{i}/{role}` | 二値判定が微小内積で決まっている割合（平滑化の要否の材料） |

**共通支持の実体**（「書式に偏る」を検定する）

| 指標 | 何を答えるか |
|---|---|
| `cross/support_overlap/{i}/{j}/{role}` | $v_{i,c}$ の支持と $t$ の支持の重なり |
| `cross/energy_on_shared/{i}/{j}/{role}` | 共通支持に載る RL / OPD 勾配エネルギー。**ID 個数ではなく重み** |
| `cross/x_cross_absmean`、`cross/x_cross_neg_frac` | 実際の交差内積と負部分の大きさ |

**self と cross の関係**

self と cross は $u^{OPD}$ を共有するので依存する。交差部分への限定は独立な二重の裏付けではなく、
自タスクへの局所的悪化を避けつつ他タスクの参照で選択を絞る操作である。相関だけでは
「単に厳しくした self gate」と確定できないので、**閾値付近の選択そのもの**を記録する。

| 指標 | 何を答えるか |
|---|---|
| `cross/corr_self_cross` | $x^{\rm self}$ と $x^{\rm cross}$ の相関（要約） |
| `cross/sel_vs_selfonly_jaccard` | **同じ減衰量になる self のみのゲート**が選ぶ token 集合との Jaccard |
| `cross/disagree_role_share`、`cross/disagree_grad_rms` | 一致しない token の役割分布と勾配強度 |

すべて既存の all-reduce に相乗りする。追加 forward / backward は無い。

## 5. 未決の 2 点（実装前に決める）

1. **$A^-$ に $w^{\rm self}$ が入ることで、2 つの制御器が結合する。** $a_j$ が下がると $A^-_{ijc}$ も下がり交差制約が緩む。
   「self が既に削った分は cross が扱わない」という意味なら妥当だが、$A^-_{ijc}$ は教師の生の対立量ではなく
   **self ゲート後の残量**である。$b_{j,c}$ を外す理由づけ（自分の出力の読み戻し）は $w^{\rm self}$ には当てはまらないので、
   これは選択として明記する。ゲート前の値も併記して両者を区別する。
2. **$b_{\min}$ を 0 とするか正とするか**（§3 の二択）。実行可能性を保つか、保護条件の未達を許して記録するか。

## 6. 事前予測

**保守的な交差部分への限定により介入量は小さくなると予想される。実効的な減衰量と役割分布を記録し、精度への影響を評価する。**

$H_j$ の token で係数は $\Delta w_t=a_j(1-b_{j,c})$ 変わる。ただし平均 token 重みの減少率と、KL 損失量・勾配強度・
精度への影響は別物である。少数の環境操作 token に集中すれば割合が小さくても挙動は変わりうるし、
書式 token に広く作用しても成功率は動かないかもしれない。**どちらとも事前には言えない。**

**最初に効くとすれば webshop → alfworld の env_action である。** 制約に入る $a_j$ は送り手の self gate 係数で、
現 run では webshop だけ 1.00（alfworld 0.75、search 0.74）。webshop は同時に env_action の占有率が最大
（12.6% 対 alfworld 2.6%）。**初回 readout で検証できる予測である。**

補助的な仮説（検定対象であって前提ではない）: 交差ゲートは `format` に偏る。
根拠は §4.8 の「位置の 84〜92% が format」と、参照支持の重なりが format で最も大きいこと。
ただし §1.1 の通り `format` の実体は推論文なので、これは「書式に偏る」ではなく「推論スタイルに偏る」という仮説である。
**「内容役割では実質作動しない」は予測であって結論ではない** —— 共通支持に載る勾配エネルギーを測るまでは決まらない。

| format | alf–search | −0.063 / −0.156 | 38/297 |
| format | search–web | −0.115 / −0.017 | 38/365 |
| env_action | alf–web | −0.055 / −0.004 | 2/69 |

**この測定が支持するのは 1 つだけ: 構成した参照は 1 方向へ潰れていない。** 以下は支持しない。

* **有用性ではない。** 参照が違っても、タスク間干渉について何も運ばないことはありうる。
* **self の焼き直しかどうかでもない。** self は token 自身の $u^{RL}$、cross は集約参照なので、
  $v_i=v_j$ でも $v_i^\top u^{OPD}_{j,t}\ne (u^{RL}_{j,t})^\top u^{OPD}_{j,t}$。似ていても焼き直しにはならない。
* **発火範囲でもない。** 共有 ID 数は集合の重なりで、内積を決めるのは共有座標に載る勾配の重みである。
  2 個でもそこに集中していれば効く。

### 7.1 撤回: dump から計算した $\kappa$ は参照の有効性判定に使えない

イベント dump から $r_t=A_t(1-p_t)e_{a_t}$ として計算した $\kappa=0.0013\sim0.0472$ を
「参照方向がほぼ雑音」と読んだのは**誤りである。撤回する。**

* この近似では各 token が 1 座標のスパイクなので、ID が相異なれば $\kappa=1/n$ が**恒等的に**成り立つ。
  実測 $\kappa\cdot n$ は 0.85〜1.45 で全行が直交支持の基準値 1。$\kappa$ は支持集合の大きさを読んでいた。
* $-p_t$ 項を落としている。$c_t$ は報酬由来なので $-c_t p_t$ も PG 方向の一部であり、
  「生徒分布の項だから報酬情報ではない」とは言えない。
* **clip 後の係数ではなく advantage を使っている。**
  [`policy_loss_gradient_coef`](../verl/trainer/ppo/core_algos.py:543) の docstring が明示する通り、$-A$ が正しいのは
  ratio 1 かつ clip 外、すなわち**最初の mini-batch だけ**。現 run は 360 行 / `ppo_mini_batch_size=60` = 6 mini-batch で、
  clip 枝に入った位置は真の $c_t$ がゼロなのに $-A$ は満額を数える。dump は ratio も `old_log_prob` も持たないので
  **$c_t$ はオフラインで復元できない。**
* 制御母集団（ゼロ信号を含む）とも、通常学習の token 分布（層化標本ではない）とも一致しない。

同じ理由で、step パリティで割った split-half（cos 0.00〜0.24）も判定に使えない。
分割単位は **GRPO プロンプト群**であるべきで、step 分割には参照ドリフトが混入する。
そのうえイベント dump は軌跡 uid も群 id も持たないので、**群集合を変えた参照の一致はオフラインでは測れない。**
§1.2 の 4 指標はすべて in-run readout である。

## 8. 限界

* $x^{\rm cross}$ は head ブロックの量 $\sum_{s,t}(u_s\cdot u_t)(h_s\cdot h_t)$ の $h_s\cdot h_t$ を役割一致の重みに
  置き換えた形である。**別のカーネルへの置換であって、予測精度が単調に悪化する関係ではない。**
  ただしモデル全体の干渉を再現する根拠は無い（§2.1 の測定）。
* 同じ語彙・同じ役割で集約した RL 方向を他タスクの参照として使えるという仮定は未検証。役割を揃えても状態の意味は一致しない。
* **この拡張だけで 3 タスクの内容レベルの干渉を網羅する設計ではない。** `env_action` は alfworld–webshop の対だけ、
  `tool_call` は search 単独で交差相手を持たない。**search が参加するのは 3 タスク共有の `format` と `tag` だけ**で、
  環境行動の役割では送受いずれにもならない。初版で `env_action` と `tool_call` を統合しない
  ——統合には「異なる役割どうしの比較が意味を持つ」という新しい仮定が要るため、採るなら別条件として記録する。
  なお `tool_call` は検索呼び出しと `<answer>` の最終回答が混在しており、役割内部で既に不均質である。
* 判定は 1 step 遅れの参照に基づく局所量で、次 step の実際の損失変化を保証しない。
* self / cross の判定は $u^{OPD}$ を共有するので依存する（§4）。
* **参照が不安定だった場合の結論は「この役割分割・集約・標本数では安定した参照が得られなかった」までである。**
  「他タスクに使える RL 方向が存在しない」とは言えない。
* 採否は 3 タスクの評価精度で決める。ここで記録する量はどれも代理である。
