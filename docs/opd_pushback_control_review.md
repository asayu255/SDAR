## 0. 結論

1. **機構は理論文書の枠組みに正しく収まる。** これは位置スカラー重み（M1）を、教師と独立な信号（報酬の降下方向）で決める形である。
   命題 2 により、ゲートされた位置の固定点は報酬単独の側へ動く。教師統計を信頼に使わないので §5.1 の原則 2 に反しない。
   この系列で初めて、(a) 報酬の証拠を使い、(b) 位置ごとで、(c) cross-teacher 統計を持たない機構になった。
2. **実装は設計どおりで、試験 133 件が通る。** ゲートは 3 つの集約経路すべてに入り分母には入らない。制御入力は β で測り、$a$ を含まない。
   $a_i$ は step 内で固定、1 step 遅れ。resume で設定が違えば拒否する。
3. **しかし β=0.01 では、閉形式が動く作動点に届かない。** 走行中アームの readout から Cauchy–Schwarz で上界を取ると
   $C^-/R \le \sqrt{D/R}$ は 88 step の中央値で alfworld 0.024、search 0.022、webshop 0.014、最大でも 0.087。
   **ε=0.1 に一度も届かない**ので、$a_i=1$ のまま、`ARM=pushback` は control と同じ run になる（§2）。
   設計書の表が 0.02 → $a=1.0$ と書いている、まさにその行にいる。
4. **これは実装の欠陥ではなく regime の問題である。** ロジット空間で教師の押し戻しは報酬の降下の 1〜2% しかない。
   パラメータ空間で OPD の一次寄与が RL の 0.25〜0.99% だった（静的版の検討）のと同じ事実の別の面で、
   $\beta=0.01$ では教師が押し戻せないから、押し戻しを制御する余地が無い（§2.2）。
5. **ε を作動点に対して決めない限り、この実験は成立しない。** ε は「許容する押し戻し」の絶対値として置かれたが、
   押し戻しの水準は β に線形なので、β を知らずに ε の意味は決まらない（§3）。
6. **作動すれば、規則は単調に締まる方向に働く**（§4）。対立 token で報酬に道を譲ると、そこで教師の KL が増え、
   β で測る $C^-$ は増え、$R$ は減る。$a_{\min}=0$ なので終点は全遮断。設計書の「全遮断ではなく強度に応じた減衰」は
   $C^-/R\in[\varepsilon,\infty)$ の途中でしか成り立たない。
7. **ゲートの判定は軌跡水準の advantage の符号を token に broadcast したものに乗っている**（§5）。期待値では
   条件付き advantage との対立になるが、標本ごとには「その token が成功軌跡にいたか失敗軌跡にいたか」で決まる。
   期待値で見れば、設計書が退けた soft gate が標本抽出によって実現する。

## 2. 作動点: $C^-/R$ の上界

### 2.1 見積もりの方法

走行中アームは `ctl_*` 列を持たない（f7333cb 以前のコード）。持っている列から同じ母集団・同じ重みで上界を作る。

* $D=\sum_t \text{basis}^2\,\|u_{D,t}\|^2 \le \beta^2\cdot(\texttt{push\_l2\_logit\_base})^2$（全 response token の和なので control 母集団の和以上）
* $R=\sum_t \text{basis}^2\,\|u_{R,t}\|^2 \approx \overline{\text{basis}}^2\cdot n_{\rm align}\cdot(\texttt{pg\_push\_rms\_logit})^2$、
  $\overline{\text{basis}}=\texttt{kl\_sum\_base}/\texttt{kl\_sum}$（basis と $\|u_R\|^2$ の相関を無視した近似）
* Cauchy–Schwarz: $C^-=\sum_{\rm neg}|u_R^\top u_D|\le\sqrt{R\,D}$、よって $C^-/R\le\sqrt{D/R}$

$\beta$ は $u_D$ に入り $u_R$ に入らないので、$\sqrt{D/R}\propto\beta$。

### 2.2 値（88 step）

| | alfworld | search | webshop |
|---|---:|---:|---:|
| $\sqrt{D/R}$ 中央値 | **0.024** | **0.022** | **0.014** |
| 最小 / 最大 | 0.014 / 0.087 | 0.010 / 0.056 | 0.010 / 0.060 |
| 対立 token の割合（`pg_dot_neg_frac`） | 0.51 | 0.49 | 0.49 |
| ε | 0.1 | 0.1 | 0.1 |

$\sqrt{D/R}\approx 0.02$ は「ロジット空間で $\|u_D\|/\|u_R\|\approx 1/50$」を意味する。パラメータ空間の $\|r\|/\|d\|$ が 6〜11 だった
のと桁は違うが（空間が違い、Jacobian と行重みが挟まる）、向きは同じで、**教師は報酬の降下を 2% しか打ち消せない**。
閉形式は $C^-/R>\varepsilon$ で初めて $a<1$ になるので、ε=0.1 では 88 step のどこでも作動しない。上界は
$|\cos_t|=1$ を全対立 token に仮定した場合であり、実際の $C^-/R$ はさらに小さい。

### 2.3 「符号が反転した」について

設計書 §0 が根拠に挙げた webshop の対角の符号反転は、`pg_cos_mean/webshop` が step 1〜31 で +0.06〜+0.12、
41〜88 で −0.05〜+0.006 と動いたことを指す。反転は確認できるが、大きさは $|\cos|<0.12$ で、per-token cosine の平均は
step ごとの揺れが大きい（alfworld は同じ期間に −0.22 から +0.09 を往復）。「静的 $b$ の前提が崩れた」の根拠としては弱く、
`adv_zero_frac` の変化（webshop 0.62 → 0.17〜0.27）の方が確実である。

## 3. ε の意味は β 抜きに決まらない

$C^-/R$ は β に線形なので、ε=0.1 は

* β=0.01 では「現在の押し戻しの 5〜10 倍まで許容」= 何もしない、
* β=1.0（純 OPD 系スクリプトの値）では $\sqrt{D/R}\approx 1.4$〜$2.4$ となり、$a\approx\varepsilon/(C^-/R)\approx 0.05$〜$0.1$ = 対立 token をほぼ全遮断、

と、同じ ε が両極端になる。設計書は ε を「許容する介入強度」の絶対値と位置づけているが、押し戻しの尺度が β で決まる以上、
**ε は作動点に相対的にしか定義できない**。実験にするには次のどちらかが要る。

1. **β=0.01 のまま、ε を観測比の分位で置く**（例: 先行 20 step の $C^-/R$ の中央値の 1/2）。ゲートが半分の step で動く。
   ただし「10% の押し戻しを許容する」という意味は失われ、「現状の半分にする」という相対的な強度になる。
2. **β を上げて教師が押し戻せる regime に置く**（例: β=0.1〜1.0）。そこでは制御に意味があるが、control も β を揃え直す必要があり、
   この系列の他アーム（すべて β=0.01）と比較できなくなる。

どちらを選ぶかは設計判断だが、**現在の lock（ε=0.1、β=0.01）で起動すれば 49 時間かけて control を再現する**。
起動前に 2〜3 step だけ回して `ctl_pushback_neg_frac` を読めば確定する（30 分）。上の上界はそれを待たずに言える範囲である。

## 4. 作動した後の動学: 締まる方向にしか動かない

ゲートが $a<1$ になった対立 token では、報酬が教師に勝って動く。その token では

* 教師の KL が増え、$\|u_D\|$（β で測る、ゲート抜き）が増える → $C^-$ 増、
* $p(a_t)\to1$ に近づくと $\|u_R\|^2\propto(1-p_a)^2+\sum_{v\ne a}p_v^2\to0$ → $R$ 減。

したがって $C^-/R$ は単調に増え、$a_i$ は単調に減る。止めるものは $a_{\min}$ だけで、既定は 0。
EMA（0.9）は速度を落とすが向きは変えない。PPO の clip は step 内では $u_R=0$ にして token を対立集合から外すが、
次の step で ratio が 1 に戻れば復帰する。

これは欠陥ではなく、「対立で譲る」規則の帰結である（自動的な per-token の $\beta(t)$ 減衰）。ただし設計書の
「全遮断ではなく強度に応じた減衰」は $C^-/R\in[\varepsilon,\infty)$ の途中経過にしか当てはまらない。
走らせるなら (i) $a_{\min}>0$ を置く、(ii) `a_applied` と `ema_ratio` の時系列を事前予測として書く（単調減少・単調増加）、
(iii) 予測が外れたときの読み方を決めておく。

## 5. 判定信号の中身: broadcast された advantage

対立判定 $u_R^\top u_D<0$ の $u_R$ は $-\partial L_{\rm pg}/\partial\log p\cdot(e_{a_t}-p)$ で、係数は軌跡水準の advantage
（群内正規化、全 token に broadcast）と ratio から決まる。同じ状態 $(s,a)$ でも、成功軌跡にいた標本と失敗軌跡にいた標本で
符号が逆になる。

* **期待値**では $\mathbb E[u_R\mid s,a]\propto\tilde Q(s,a)$（命題 2 の証明）なので、判定は「教師が条件付き advantage と対立するか」になる。
* **標本ごと**には $(s,a)$ に対する実効重みは $1-(1-a)\Pr[\text{対立}\mid s,a]$、すなわち設計書が退けた soft gate が
  標本抽出によって実現している。閉形式は 1 バッチでは厳密だが、その期待値は soft gate である。
* 失敗軌跡（$A<0$）で教師が sampled token を生徒より好む位置は「対立」になり、教師の引きが切られる。
  失敗の原因がその token に無い場合、教師の「ここは合っている」という信号を捨てることになる。
  信用割当の雑音がそのままゲートに入る。

これは β=0.01 の regime では問題にならない（作動しないので）。作動する regime に移すなら、
`min_live_groups=4` だけでは足りず、判定を群平均（同じ prompt の 8 本の多数決）にする方が期待値に近い。

## 6. 走行中の静的アームとの関係

* 静的アームは step 88。設計書は「静的版の記録として完走させる」とする。それでよい。
* 静的 $b$ の実体は「webshop の $\beta$ 半減・search ×1.19」（trust_vs_spillover §3）で、これは ε の縛りを受けない
  **強制的な信頼変更**である。押し戻し制御は同じ regime でそれを一切しない（作動しない）ので、
  2 つのアームは「介入 50% 対 介入 0%」の比較になり、機構の比較にならない。
* 押し戻し制御が本当に検定するのは「教師が押し戻せる regime で、対立位置だけ譲ると到達点が変わるか」であり、
  それには β を上げた control が要る。

`ctl_conflict` の定義が `dot < 0` の純粋な符号判定であることも同じ問題の一部で、alfworld の `pg_dot_neg_frac` は
w1 0.559（n=349k、z=+70）から **w4 0.505（n=298k、z=+5）** ——実在した偏りは 40 step でほぼ消えている。
webshop は 0.477〜0.490（z が**負**）で、この教師だけは符号付きでも整合側に寄っている。

advantage が付く。教師がそこを上げれば $u_R\!\cdot\!u_D<0$ になる。**$dot<0$ は「教師が報酬に逆らっている」と

9.1 のサブタスクの並び（2 段階課題だけが最下位）と整合する。Armandpour et al. 2026 の「不正解 rollout ほど OPD の整合が高い」とも同じ向き。

代わりに出たのは **解放経路が無い**こと。対立の実体（neg_frac、ctl cos、conflict_frac）は 40 step でほぼ消えたのに、

### 9.5 対策（実装しない。記録のみ）

* **A. 両側にする。** $C^-/R$ ではなく $(-X)_+/R$ を閾値する。現データでは 3 タスクとも無発火。
  バルクの整合に隠れた集中的な押し戻しを見逃す、という損失がある。
* **B. ヌル差分（推奨）。** $(C^--C^-_{\rm null})/R$ で発火。**対称ヌルなら $C^-_{\rm null}=(C^-+C^+)/2$ となり脱バイアス統計量は $-X/2$、
  すなわち A と一致する。** それを超えるには置換ヌル（タスク内で $u_R$ と $u_D$ の対応をシャッフルして $C^-$ を再計算）が要る。
  token ごとの内積は既に計算済みなので追加 forward はゼロ。
* **C. 大きさで選ぶ。** `dot < 0` に $\lvert dot\rvert>\kappa\,\mathrm{sd}(dot)$ を加える。累積器を 1 本（$\sum dot^2$）増やすだけ。
* **D. 解放条件を要件にする。** 置き換えた統計量が、平均がゼロへ行くときゼロへ行くことを構成上確認する。A・B は満たし、現行は満たさない。
* **E. 暫定（コード変更なし）。** ε を分散フロアの上へ（測定値は alfworld 0.0044 / search 0.0033 / webshop 0.0016 なので ε=0.005 で全無発火）。
  事実上 control に戻るだけで統計量は直らず、尺度が動く場面（search の $R$ は 40 step で 18 倍縮んだ）で再び誤る。

因果の帰属は妥当な水準（config 差が pushback のみ、同一 seed、24/12、era 内最下位、削られている項が正味で整合）だが p≈0.07 なので、
確定には **seed を替えた push 1 本**が要る。

### 9.6 拡張への含意と、方針の変更

交差ゲートの $A^-_{ijc}=\mathbb E[w^{\rm self}[-x^{\rm cross}]_+]$ は **同じ「合算前 clip」構造**であり、
しかも $x^{\rm cross}$ は集約参照 $v_i$ との内積で分散対平均比は self よりさらに悪い（$\kappa\approx1/n$ の測定）。
そのまま作れば self gate より強く雑音をゲートする。**拡張を作るなら B（置換ヌル）の上に建てることが前提条件**であり、調整項目ではない。

**方針。** 本文の機構（self gate）をこれ以上改良する方向は取らない。
9.2〜9.4 が示すのは、自タスク基準の押し戻し制御が (i) 片側統計量で発火し、(ii) 削る先が報酬の持たない情報で、(iii) 戻る道を持たない、
という三点であり、これは単タスク学習でも同じ形で成立する問題である。研究方針（多タスク学習の機構であること）に照らして、
**純粋 OPD+GRPO の上に、交差ゲート設計からタスク間機構の部分だけを実装する**方向へ移る。
self gate の $a_j$ は前提から外れるので、
[opd_output_space_cross_gate_design.md](opd_output_space_cross_gate_design.md) の §0（$w^{\rm self}$ との積）、
§1（$A^-$ の $w^{\rm self}$ 重み）、§3（制約の $a_j$）、§5-1（2 つの制御器の結合）は、この移行に合わせて書き直しが要る。

### 10.4 判定方法と、MOPD アームへの含意

* **300 step の判定は対比較ではなく共通条件の検証精度で行う。** 10.1 が示すのは、学習中の step 単位の差は step 60 付近で
  対としての意味を失うということで、これは arm の性質ではなく 2 本の run を並べることの性質である。
* **MOPD（交差ゲート）アームの読み方はこれで確定する。** self gate は更新方向を 0.4〜0.9% 動かして 62 step で検出可能な差を出さなかった。
  交差ゲートは設計 §10 の見積もりで OPD エネルギーの 0.1〜0.7%（self gate の 21% の 30〜200 分の 1）しか削らないので、更新方向では
  0.005〜0.02% 程度になる。**300 step の学習時成功率でこれを検出できる見込みは無い。**
  [opd_output_space_cross_gate_design.md](opd_output_space_cross_gate_design.md) §8.6 が採否を共通条件の評価に置き、
  §9 が `episode/*_success_rate` を推移把握用に降格したのは正しかった。**最初の readout は精度ではなく、
  参照が成立するか（κ・`ref_cos_sides`・`valid`）と、作用対象があるか（`B` が有意に負か）である。**
* §9.5 の対策の優先順位は変わらない。10.2 は「戻らない」を「遅れて戻る」に緩めるだけで、**片側統計量で発火する**という 9.2 の欠陥
  —— $-X/R$ が 3 タスクとも負（正味で整合）なのに $C^-/R$ が ε を超える —— には触れていない。
