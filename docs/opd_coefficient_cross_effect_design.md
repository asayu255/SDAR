## 1. 係数の決め方（固定する）

$$
\tilde C^{(n)}_{ij} = \frac{\langle r_i^{(n)}, d_j^{(n)}\rangle}{\|r_i^{(n)}\|\,\|d_j^{(n)}\|},\qquad
\tilde C = \frac1N\sum_n \tilde C^{(n)},\qquad
c_j = \sum_{i}\tilde C_{ij},\qquad
w_j = \frac{\overline{\|d_j\|}}{\sum_k \overline{\|d_k\|}},\qquad
\delta_j = c_j-\textstyle\sum_k w_k c_k,\qquad
b_j = \mathrm{clip}\big(1+\kappa\,\delta_j,\ b_{\min},\ b_{\max}\big)
$$

* **和は全タスクの行を取る。** タスクごとに違う扱いは無い（§1.3）。対角 $\tilde C_{ii}$ は含める（除いても順位は変わらない: §1.1）。
* $\overline{\|d_j\|}$ は $C$ と同じプローブの $N$ バッチについて、バッチごとの $\|d_j^{(n)}\|$ の平均。
  rms やバッチ内シェアの平均に替えても $b$ の差は 0.003 以下。
* $b_{\min}=0.5$、$b_{\max}=1.5$。$\kappa$ は**最も外れた列が box に当たる値**
  （$\kappa=\min\big((1-b_{\min})/(-\min_j\delta_j),\ (b_{\max}-1)/\max_j\delta_j\big)$）。自由パラメータは box だけ。
* **予算は勾配ノルムで取る。** $\sum_j w_j\delta_j = 0$ なので clip が効かない限り $\sum_j \|d_j\|\,b_j = \sum_j\|d_j\|$ が自動的に成り立つ。
  **係数の平均は 1 にならない**（§1.2）。
* 実効係数は $\beta\,b_j$。$\|r\|/\|d\|$ が 4〜16 なので、$b_{\max}=1.5$ でも RL 支配は変わらない
  （理論文書 §4.5 の regime を出ない）。$b_{\min}=0.5$ は「正則化を半分は必ず残す」の意味。
* **go/no-go**: $N$ バッチの bootstrap で $c_j$ の**順位**が 90% 以上再現しなければ $\kappa=0$（= control）とし、走らせない。

### 1.2 「総量」は 2 つあり、同時には揃えられない

OPD の量として意味を持つ不変量は 2 つある。

* **線形和** $\sum_j b_j\|d_j\|$: 任意の損失 $L_k$ への一次効果 $r_k^\top\sum_j b_jd_j$ は $b_j\|d_j\|$ に線形なので、これがその上限を決める。
* **合成ノルム** $\|\sum_j b_jd_j\|$: 実際に更新に足される OPD ステップの長さ。$d_j$ どうしはほぼ直交（cosine ±0.1）なので
  $\approx\sqrt{\sum_j b_j^2\|d_j\|^2}$ で、係数の**二乗**に効く。

初版の $\sum b_j=3$ はどちらも保っていなかった（+10% / +24%）。ノルムが最大の search（$\|d\|$ 0.886、他は 0.41〜0.46）に
配分を寄せるので、係数の和を保つと勾配は増える。§1 の予算は線形和を厳密に保ち、合成ノルムは +11% 残る。
一様な倍率は 2 つの不変量を**同じ比で**動かすので、再配分（違う比で動かす）を 1 本の一様アームで両方揃えることはできない。
残る +11% の扱いは §4。

### 1.3 なぜ $S$ を持たないか（改訂 2）

検討の QP では search の RL 行（3 成分とも負、$p$ = 0.34 / 0.87 / 0.04）が解を $b=0$ に潰した。
それは硬い制約の性質で、全成分負の行が 1 本あれば実行可能集合が $\{0\}$ になる。
そこで改訂 1 は「信頼できる行の集合 $S$」を定義して search を外したが、これは

* タスクごとに違う扱いをする**機構の非対称**であり、
* $S$ の選定が手作業なので、別のタスク集合・別の checkpoint で同じ手順を再現できない。

比例則ではこの集合が要らない。$c_j$ は行の**和**なので、雑音の多い行は $c_j$ に雑音を足すだけで、
何も潰さない。実際に search 行を入れると $b$ は (1.05, 1.21, 0.50) → (1.08, 1.19, 0.50) で、差 0.03 は
bootstrap の 5–95% 帯の内側である。順位の再現率は 97% → 96% で変わらない。

行の信頼度を式に入れたい場合も、**全タスクに同じ定義で**掛かる重み $\alpha_i$（$c_j=\sum_i\alpha_i\tilde C_{ij}$）でなければならない。
レビューが提案した advantage 被覆率（$A\ne0$ のトークン割合）を含め、候補と step 300 のデータで出る値
（bootstrap 2000 回、順位 search > alfworld > webshop の再現率）:

| $\alpha_i$ の定義 | $\alpha$（alf, search, web） | $b$ | 順位再現 | $P(b_{\text{search}}>1)$ |
|---|---|---|---:|---:|
| **なし（本線、等しい票）** | (1, 1, 1) | **(1.08, 1.19, 0.50)** | 96.4% | 0.999 |
| $S$={alf, web}（改訂 1、人が選ぶ） | (1.5, 0, 1.5) | (1.05, 1.21, 0.50) | 97.1% | 0.998 |
| advantage 被覆率（0.755 / 0.235 / 0.376） | (1.66, 0.52, 0.83) | (1.05, 1.20, 0.50) | 97.2% | 1.000 |
| 被覆率の二乗 | (2.23, 0.22, 0.55) | (1.04, 1.21, 0.50) | 97.4% | 1.000 |
| 生存 GRPO 群のシェア（5.5 / 3.4 / 5.1 群） | (1.18, 0.72, 1.10) | (1.07, 1.20, 0.50) | 96.9% | 0.999 |
| between-batch 精度 $1/\overline{\mathrm{SE}^2}$ | (0.76, 1.86, 0.38) | (1.13, 1.17, 0.50) | **65.1%** | 0.951 |

精度重みを除くどれも順位を変えず、$b$ は 0.035 の中で動き、順位再現は 96〜97% で区別がつかない。
**データはこの選択を決められないので、原理で決める。等しい票を事前登録する。** 理由は 4 つ。

1. **cosine 空間では信頼度の低い行は既に減衰している。** 雑音の混じった $\hat r_i$ の cosine は
   $\cos(\hat r_i,d_j)\approx\cos(r_i,d_j)\sqrt{\mathrm{rel}_i}$ と 0 へ縮む（Spearman の減衰、理論文書 §4.7 が補正に使った関係）。
   実測で search 行の $|\tilde C|$ の平均は 0.043、alfworld / webshop は 0.074 / 0.077 で、search 行は**既に半分の票**しか持っていない。
   被覆率 0.52 はそれにもう一度掛かる二重の割引である。精度重みが逆に search を最大にして順位再現を 65% に落としたのは
   同じ現象の裏側で、減衰して小さくなった値が「安定」に見えるからである。
2. **被覆率は 2 つの違うものを混ぜる。** 8 本の rollout がたまたま揃った標本の人工物は $N$ バッチの平均が均す。
   一方、現在の方策の下でそのプロンプトの結果が本当に決定的なら、真の政策勾配もそこでは 0 で、生存群の勾配が
   タスクを代表している。被覆率はこの 2 つを区別せず、どちらにも同じ割引を掛ける。
3. **被覆率は `rollout.n` と成功率の regime に依る。** ほぼ解けたタスクも、ほぼ解けないタスクも被覆率が下がる。
   学習段階で被覆率が動けば、整列とは無関係な理由で $b$ が動く。run 間の変動源が 1 つ増えることになり、再現性の向きと逆である。
4. **$S$ を再現することは検証ではない。** $S$ は QP の診断から来た経験則で、それに一致する重みを選ぶのは循環である。
   被覆率版の利点として挙げられた「機構が入力の関数として閉じる」は、等しい票でも同じく成り立ち、材料が 1 つ少ない。

被覆率が本当に測っているべきもの（生存群の勾配がタスクの状態分布に対して**偏っている**か）は、
現在のプローブでは測れない（退化群の勾配は 0 なので、生存群と全群の整列を比べられない）。
偏りの測定が無い間は、減衰による自動的な割引だけを使う。

**等しい票の規則に要る唯一の付則**（タスクを区別しない）: あるバッチでタスク $i$ の RL 勾配が厳密に 0 なら、
そのバッチの行 $i$ の cosine は定義されないので、その行の平均から**そのバッチを除く**（`nanmean`）。
行 $i$ で定義されたバッチが $N/2$ 未満なら go しない。$N=8$ の step 300 データでは 24 セルすべてが非ゼロで、この付則は発動していない。

案 B（早期 checkpoint）で等しい票と被覆率が**順位で食い違った**場合は、低被覆の行が結果を動かしているという信号なので、
重みで消さずにその行のバッチ別の符号を見る。それが「$S$ を人が選び直す」ことの、測定に基づく代わりである。

## 2. 理論的な位置づけ（短く）

* 命題 2（理論文書 §2.2）: $b_j$ はタスク $j$ の全位置で $\tau$ を $b_j$ 倍する。固定点は
  $\pi^\star\propto\pi_d\exp(\tilde Q/(\beta b_j))$ の側へ動く。webshop は教師寄りが弱まり、search は強まる。
* 一次の効果は小さい（検討 §4.2: OPD の一次寄与は RL 自身の 1% 未満）。**この run が検定するのは一次の量ではなく、
  「$C$ の順位で教師の重みを配り直すと、早期の学習と @150 の到達点が変わるか」である。**
* 測定に支持されている情報は「webshop 教師の押す向きが他の報酬勾配と食い違う」（検討 §5: 3 つの独立測定が同じ向き）。
  再配分則はこの 1 つの情報を $b_{\text{web}}<1$ として使い、残りは予算の帰結である。
* RL–RL の衝突は解消しない（cosine 0.002〜0.016 で、解消すべきものが無い）。
* 同一タスク対 $\tilde C_{ii}$ には共分散が混入する（検討 §4.3）。対角を除いても順位が同じことを確認済みなので、
  この run の $b$ には効かない。

## 3. 測定点: どの checkpoint で $C$ を取るか（判断待ち）

150 step の run を **base から 0→150** で走らせる前提（OPD が効く区間を含めるため。step 150→300 では

| 案 | 測定点 | 費用 | 何が言えるか |
|---|---|---|---|
| **A** | step 300 の既存データ（§1.1 の $b$ = (1.08, 1.19, 0.50)）をそのまま使う | **追加測定なし** | 「step 300 の順位が早期にも効くか」。適用点と測定点がずれるので、null が出ても「早期の順位が違った」と「順位が効かない」を区別できない |
| **B** | 早期 checkpoint で $N=8$ のプローブを取り直す（$C$ と $\|d_j\|$ の両方） | プローブ 1 回（1 バッチ = rollout 1 本 + backward 6 回、$N=8$） | 適用点と測定点が一致する。**null が「順位が効かない」を意味する** |

B の checkpoint（レビューで実在を確認済み）:

* **B1: 8/5 control の step 50**（`~/checkpoints/verl_agent_opd_grpo_multitask/global_step_50`、world size 3、`optim` あり）を HF にマージして
  `PROBE_HF_PATH` で読む。control 側の測定だが Adam 状態は落ちる（$P=I$ のみ。規則が使うのも $P=I$ なので不足はない）。
* **B2: 8/13 アームの step 50**（`~/checkpoints/verl_agent_opd_grpo_tmp_multitask/global_step_50`、world size 2、`optim` あり）。
  そのまま読め、Adam 幾何の $C$ も取れる（$P=I$ との符号一致の確認になる）。ただし signweight target アームであって control ではない。

推奨は **B1 を本線、B2 を Adam 幾何の確認**。B1 と step 300 で順位が同じなら A と B は同じ $b$ になり、
違えば「順位は学習段階で変わる」が分かった時点で B の $b$ を使う。
プローブのコードは `claude/cross-teacher-target-6b2123` にあり、学習側のブランチには cherry-pick で持ち込む（レビューの申し出どおり）。

早期 checkpoint では生存群が少ない可能性がある（base 近傍は成功率が低く、全失敗群が退化する）。
go の条件は 2 つで、どちらもタスクを区別しない: (i) 3 タスクとも生存群の 8 バッチ平均が 3/15 以上
（step 300 では 5.5 / 3.4 / 5.1）、(ii) 順位の bootstrap 再現率 90% 以上（§1）。

| control | (1, 1, 1) | 1.751 | 1.050 | 同じコード・同じ seed 手順で 0→150 |
| **再配分** | §1 の $b$、例 (1.08, 1.19, 0.50) | **1.751** | 1.164 | 処置。線形和は control と一致 |
| 一様（任意） | $(u, u, u)$、$u=\|\sum bd\|_{\text{再配分}}/\|\sum d\|$ = **1.11** | 1.94 | **1.164** | 合成ノルムを再配分と一致させる。GPU が 1 本増える |

初版の「同じ平均係数の一律アームは control と一致するので不要」は**誤りだった**（§1.2）。改訂後は

* **2 本なら** control と再配分。線形和は一致、合成ノルムは +11% が残る。この残差は限界として書く（§6）。
* **3 本なら** 一様 1.11 を足す。再配分は control と線形和を、一様と合成ノルムを共有するので、
  **再配分が両方と違えば配分の効果**、一様とだけ同じなら合成ノルム（OPD ステップ長）の効果、と読み分けられる。

「同じ平均係数の一律減衰」（初版の第 3 アーム）は、平均が 1 でなくなった今は意味を持たないので外す。
既存の klw control @150（0.651 / 0.635 / 0.384、$n=1$、8/29 のコード）は参考値にとどめ、
GPU が足りず control を既存値で代用する場合は @150 の差が 5pp 未満なら判定しない。

**検証**: step 150 の checkpoint を同一プロトコルで 3 回（`RUN_TAG` を変える。同じ step を再検証すると
per-instance dump が上書きされる: 理論文書 §6.3）。タスク別に報告し、pooled は出さない。
反復雑音は alfworld SD 1.39pp、webshop acc 0.46pp（$n=3$ の推定なので上限側 6.3σ̂ でも変わらない主張だけ述べる）。

**事前予測**（早期の順位が step 300 と同じ場合）:

| タスク | $b$ | 予測 | 外れたら |
|---|---|---|---|
| webshop | 0.5 | **2 つの仮説が逆を予測する。** H1（干渉）: acc ≥ control。H2（早期は教師が必要）: acc < control @150 | どちらが出ても情報になる。H2 なら「step 300 で食い違う教師も早期には要る」 |
| search | 1.19 | OPD が主信号（生存群 1〜5/15）。≥ control、差は小さい | < control なら教師寄りが強すぎる（$\tau$ の増加が search の固定点を悪化） |
| alfworld | 1.08 | ≈ control（±2pp 以内） | 差が出れば search / webshop 経由の共有パラメータの効果。§4.7 の幾何と照合 |

**3 タスクとも null** なら、$\beta=0.01$ でのタスク別係数には梃子が無い、で機構族を閉じる
（理論文書 §4.5「係数の選択が一次、位置別の重みは二次」と整合）。

## 6. 限界（走らせる前から分かっていること）

* $C$ は一次・局所・$P=I$ の量で、run が検定するのは「その順位で配り直すと到達点が変わるか」であって、一次近似の正しさではない。
* 順位は checkpoint 1 点・プロンプト列 1 本（理論文書 §4.14.6）から出ている。案 B でも同じ制約。
* **予算の不変量は 2 つあり、2 本のアームでは片方しか揃わない**（§1.2）。合成ノルムの +11% は
  「OPD ステップ長が 1 割長い」効果と分離できない。3 本目（一様 1.11）が無い限り、正の結果の帰属は「配分または長さ」まで。
* $\|d_j\|$ の比は checkpoint と学習段階で変わりうる（理論文書 §4.15.4: 純 OPD step 150 では search ×5.8、ここでは ×2.2）。
  案 A では予算の一致も step 300 の値に依る。Adam の前処理後のノルム比は測っていない。
* box $[0.5, 1.5]$ は選択であり、測定から出ていない。$b_{\text{web}}$ は常に box の下端に張り付くので、
  この run が実際に検定する自由度は「webshop を半分にし、その分を search に回す」の 1 つ。
* 対称な規則でも、タスク間の**データ側**の非対称は残る（search の生存群が少ない、教師の KL 係数が 0.001 と 0.01 で違う、
  復号設定が greedy と sampled で違う）。規則はこれらを均さない。均すのは規則の役目ではなく、測定の read-out に書く。
* $n=1$ の学習 run では、alfworld で 5pp 未満の差は決められない。
* 適応版（学習中に $C$ を測って $b$ を更新する）は採らない。backward が 6 倍になる測定 step が要り、
  FSDP の勾配取得は 2 度の取り違え（mini-batch 1 つ分、gathered buffer）を起こした経路である。静的な $b$ で先に答えを出す。
